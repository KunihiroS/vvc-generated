変換パイプライン

Claude → agy

スキルは、Claudeの直前の応答を一度ファイル経由でagyに渡し、得られた出力を“逐語的に近い形で”そのまま返します。重要なのは「agy出力を印字して、さらにClaudeが整え直さない」ことです。

入力
Claudeの回答テキスト
出力方針
agyの出力をそのまま表示（改変しない）
“Translation”寄りの文体変換 / style correction translation

読み手別のモード

colleague / manager / director

同一内容でも、読み手に応じて出力長とトーンを調整できるモード（colleague/manager/director）を提供します。短縮しすぎるモードでは情報落ちの可能性があるため、用途分離が重要です。

colleague
普段の共有向け
manager
要点化・短縮
director
さらに上位向け
Bilingual: “要点化” = summarization

運用の手順

/debuzz

使い方は /debuzz [mode] [text] で、内部ではテンポラリファイルに書いた本文をプロンプトに埋め込みます。これによりCLI仕様の制約（stdin/外部ファイル参照）を回避します。

CLI制約
stdinを読まない / 外部ファイル読めない
実装回避
テンポラリへ書く → プロンプトに埋め込む
“動く”ためのノウハウ / implementation detail

導入時の検証観点

品質保証は別途

品質
事実性の担保（verification）

運用

Risk: 文体改善 vs 情報構造の薄まり

結論
