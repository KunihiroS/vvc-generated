Native inference on Apple Silicon

MiniMax-H3 概要

Apple Silicon（主にM系チップ）で「画像→動画/音声/マルチモーダル」推論を高速化する、ネイティブ実装（h3-metal）の要点を、steps・reuse・layers・量子化/融合まで繋げて整理します。

Speed vs consistency

速さは 一致 を揺らす

速度最適化（reuse/layers/token-reduction/int8・融合）は、MLX等の別実装とピクセル完全一致を保証しません。代わりに「設定・被写体・動き」を整合させ、検証しながら最適点を探す設計になっています。

一致しない理由
乱数/実行エンジン/量子化/演算融合の差
だから必要
A/B検証（--use-slower-*、make parity/test）
Key idea：高速路と近い同一性の検証路

From prompt to frames

生成は 反復

H3は内部でTransformer（DiT等）・VAE、さらにテキスト/画像/音声のconditioningを扱い、一定ステップ数のデノイジングを繰り返してフレーム列を生成します。

Transformer（例：DiT）＋VAE＋conditioning
生成の骨格
N回デノイジング → フレーム列

Five speed levers

制御レバー 5 つ

速度/品質/検証可能性を分ける主軸は、steps・reuse・layers・token-reduction・int8量子化/演算融合です。

i) --steps
デノイジング回数（ちょうどN回）
ii) reuse
全デノイザの再評価を減らす
iii) layers
アクティブTransformerブロック数を減らす
iv) token-reduction
トークン圧縮（構図が逸れる可能性）
v) int8 + fused
Metal最適化（数値検証は切替でA/B）
運用指針
検証用フラグで近い同一性と高速路を両立

EVIDENCE
07 / 16
What is --steps?

steps＝ 反復

--steps N は、実際のデノイジングパスがちょうどN回になることを意味します。時間要求（--seconds）は24fps相当に丸められます。

定義
デノイジングパスがちょうどN回
補足
末尾処理の“終端ゼロ”が関係
時間指定
--seconds → 24fps換算 → フレーム形状へ丸め
実務の見方
まずstepsを固定して挙動を検査
次：reuse/layersで“同じ目的を軽く”する
PROCESS
08 / 16
Reuse & fewer layers

計算を 間引く

reuseは再評価を減らし、layersはTransformerブロック数を減らすことで速度を上げます。評価手順として「まずsteps固定→次にlayers」などが組めます。

reuse
全ボディの再利用（再評価削減）
layers
アクティブTransformerブロック数を削減
推奨手順
i steps固定
次の検査
ii layers調整
最終的に
iii 速度/品質を合意点へ
目的：速度と品質の切り分け
DISTINCTION
09 / 16
token-reduction is optional

token-reductionは オプトイン

デフォルトOFFで、token-reductionはトークン圧縮によって構図がclose-referenceから逸れる可能性があります。速い試作向けで、参照整合性最優先なら慎重に判断します。

デフォルト
OFF（opt-in）
起こりうること
構図が逸れて“別の方向”へ
向く用途
ラフに方向性を見る（速度優先）
注意
参照整合性（close-reference）重視なら要A/B
次：native 256 previewの位置付け
COMPARISON
10 / 16
Native 256 preview

native 256は 確認用

native 256 previewは、細部や複雑な構図では不利になり得るため最終品質の代替になりにくいです。主用途は“構図確認の高速プレビュー”です。

理由
空間トークングリッドが小さい
補足
RoPE座標は256向けに自動調整
位置付け
構図確認のための高速プレビュー
結論
最終レンダ品質の保証ではない
Next：--showと--profile
EVIDENCE
11 / 16
Observe: --show / --profile

可視化で 検証

--show はデノイジング遷移ごとに代表フレームを表示し、完了後に最終フレームも出します。--profile は各フェーズの壁時計時間・ピークメモリ・dispatch回数などを可視化できます。

--show（観測）
代表フレーム逐次表示＋最終フレーム
副作用
追加デコード時間と一時メモリが必要
--profile（計測）
壁時計時間・ピークメモリ・dispatch回数など
狙い
速さ最適化を“測って”進める
次：int8量子化と演算融合
ARCHITECTURE
12 / 16
Metal int8 & fused kernels

Metal最適化で 短縮

M5向けのint8量子化と演算融合は大幅な高速化になり得ます。一方で数値検証が揺れる可能性があるため、--use-slower-* 系で比較できるよう配慮されています。

int8量子化
BF16 → int8（高速化）
演算融合
例：fused gated AdaLN、最終headキャスト統合
狙い
Metal 4/TensorOps＋短い実行経路
検証のために
--use-slower-* でA/B比較
次：運用の結論（初心者の入口）
CLOSING
13 / 16
Practical workflow

まとめ：測って攻める

このプロジェクトは「速さ・品質・数値整合性のトレードオフ」を体系化し、--show と--profile、さらにパリティテスト導線で検証可能にしています。

強み
steps/reuse/layersの役割が明確、最適化の“芯”まで具体
限界
入力と環境依存で最適域が変わる（網羅的データは不足しがち）
初心者推奨
まずbalanced等のプリセット→--show / --profileで確認
意思決定
速度重視か同一性重視かを要件で切り分けてA/B
日本語（補助）：検証 / 高速化 / トレードオフ 終
