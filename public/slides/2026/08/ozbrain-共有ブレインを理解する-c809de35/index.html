Shared Brain for Agents / 共有ブレイン

OzBrain 共有ブレイン

複数のAIエージェント（Claude / ChatGPT / Cursorなど）が、同じ“作業中の情報”を参照・更新できるクラウド基盤です。

problem
03 / 16
Copy & drift / 分散してズレる

なぜ必要？

従来は、エージェントごとに知識や作業情報をコピー＆ペーストしたり、別ツールに散らばせたりして“最新性”が崩れます。

従来の流れ
Claudeには貼る／ChatGPTには貼る／Cursorには別ファイル…
起きること
分散・陳腐化（ドリフト）で前提が揃わず、手戻りが増える
metaphor
04 / 16
Single source of truth / 唯一の真実

ブレインはひとつ

OzBrainは「プラットフォームのメモリ」ではなく、作業成果（計画・決定・調査・顧客情報など）を“単一の情報源”に保持します。

保持するもの
Latest plan / 決定 / Research / 次のToDo
各エージェント
必要な記事だけ参照（読み取りルーティング）
architecture
05 / 16
Routing & size rules / 記事に分けて制御

巨大化を抑える

ブレインは無制限に詰め込むのではなく、読み取り時は必要記事へルーティングし、書き込み時はサイズ規律で制御します。

読み取り
必要な記事へ（ルーティング）
書き込み
サイズ規律（肥大化を回避）
破綻時
記事が大きい場合は分割・リファクタリング
evidence
06 / 16
Conflict visible / 競合を表面化

矛盾は止めて確認

既存内容と書き込みが矛盾した場合、競合（コンフリクト）を顕在化させ、エージェントが“止まって確認”する設計が述べられています。

狙い
一見整合している誤情報の拡散を減らす
ポイント
競合が起きた“瞬間”を可視化すること自体が価値
enumeration
07 / 16
監査・追跡 / Audit trail

誰がいつ何を？

共同作業のために、誰がいつどの記事を読んだ／書いたかを記録する監査ログ（CSVエクスポート）が強調されています。

ログ
Read / Write の時系列を追跡
持ち出し
監査ログをCSVでエクスポート
comparison
08 / 16
Tools vs OzBrain / ツール内メモリとの違い

既存メモリと何が違う？

既存の“メモリ”はツール内キャッシュや好みになりがちで、分散すると“同じ最新情報”になりません。

既存メモリ
ツール内で完結しやすい（最新が揃わない）
OzBrain
複数ツールが参照・更新する単一情報源
evidence
09 / 16
Security first / 暗号化と分離

安心して共有する条件

暗号化保存、監査ログ、テナント分離、Row-level security（RLS）強制、Revok（取り消し）でアクセス遮断までが説明されています。

暗号化
盗まれても読めない形で保存
RLS
Row-level securityで強制
取り消し
Revokで即座に切れる
process
10 / 16
Export & delete / 連携しやすさ

ロックインを抑える

Markdownとしてエクスポート（例：brain-export.zip）、キャンセル後のハード削除の説明があり、移行可能性を意識しています。

エクスポート
Markdown / brain-export.zip
削除
退会時に削除できる（ハード削除を示唆）
distinction
11 / 16
But verify / 実務で検証

導入前の確認点

競合時の最終決定フロー、ルーティング根拠、サイズ規律の失敗モード、権限設計や鍵管理・ログ保持期間の詳細は入力だけでは確定しません。

競合
“止まって表示”までで、正解を自動決定するかは不明
セキュリティ
鍵管理・侵害時手続き・ログ保持期間の厳密性は要追加確認
closing
12 / 16
Takeaway / 結論

作業状態を共有する

OzBrainは「複数エージェントが同じ作業状態を共有する」ことで、整合性・共同作業・監査可能性・サイズ制御を狙うプロダクトです。

価値（要約）
ドリフト削減／競合可視化／追跡可能性
次の一歩
実際のUX（競合・ルーティング・権限）を小さく検証して判断

Next: verify the details / 追加確認

参照して確かめる

以下はこの要約から読み切れない“検証ポイント”です（公式資料・UI・契約/セキュリティ資料で確認してください）。

Conflict handling
競合時に誰が何を選び、最終的にどのルールで確定するか（自動/手動、承認フロー）
Routing basis
ルーティング（必要記事の選択）の根拠、失敗時の挙動、取り落としの扱い
Security specifics
鍵管理・ログ保持期間・権限（閲覧/書き込み/管理者）の粒度、退会時削除の保証範囲
Data portability
添付/画像/メタ情報のエクスポート完全性、復元手順（運用で使えるか）
