COVER
02 / 16
ターミナル体験を“統合”する
Warp AgentCLI
単なるチャットではなく、シェル操作・対話型アプリ・ディレクトリ移動・リモート作業まで、ターミナルの文脈を保ったまま支援するCLIです。
PROBLEM
03 / 16
ギャップ問題
端末が本丸Terminal
多くのエージェントCLIは“プロンプト回答”中心ですが、開発は実際に端末を動かし続ける作業で進みます。
典型の詰まり
回答はできても、
実操作（移動・対話・全画面）に繋がりにくい
導入の壁
“使う端末に縛られる”と、日常ワークフローに合わず定着しにくい
CORE IDEA
04 / 16
同等体験を任意へ
スタンドアロン化
Warp Terminal内のマルチモデル・コーディングエージェントを、Ghostty/iTerm2/VS Code/標準ターミナルなど“任意のターミナル”で使えるCLIとして提供します。
狙い
環境依存による生産性損失を減らす
強み
Warpの端末基盤の利点を持ち出す
結果
“端末統合”が導入価値の中心
METAPHOR
05 / 16
tmuxの発想
擬似端末を管理pty
エージェントがターミナルとやり取りする“擬似端末接続（pty）”を、裏側で多重化（multiplexing）してセッション文脈を保ちます。
pty（擬似端末）
入力・出力の流れを“端末らしく”扱える土台
tmux的な狙い
セッションの間接化で、文脈を落としにくくする
EVIDENCE
06 / 16
“作業が続く”
セッション持続
pty多重化とセッション管理により、セッション中のディレクトリ変更ができ、リモート先でも運用を組み立てやすくなります。
ローカル
ディレクトリ移動しても作業文脈を維持
リモート
リモートに“バイナリを入れず”にエージェント運用
PROCESS
07 / 16
対話型アプリを扱う
全画面もOKInteractive
sqliteやvim、gdb、htopのような全画面・インタラクティブ端末アプリを、エージェントが操作できることが挙げられています。
DB
sqlite（例: クエリ生成・整理）
編集/環境
vim（例: 終了や操作支援）
デバッグ
gdb（例: ブレークポイント設定）
UX
08 / 16
“進めるUI”
コマンド支援が中心
自然言語かシェルコマンドかを自動判別し、`!`でシェル実行やタブ補完メニューで“使いながら進める”操作性を狙います。
自動判別
自然言語 / シェルコマンドを分類して処理
タブ補完
提案だけでなく、入力を前に進める導線
SYSTEM
09 / 16
複数を回す
オーケストレーション
マルチエージェントのオーケストレーションや、クラウドエージェントへのハンドオフ（引き継ぎ）で、作業をプロセスとして運用します。
i
複数エージェントでタスクを分担し、全体を段取り化
ii
ローカル作業 → クラウドへのハンドオフで継続管理
iii
単発回答ではなく“開発プロセス”の運用を志向
COST
10 / 16
選び方で損益が変わる
モデル・ルーティング
タスク複雑度に応じた自動ルーティングとカスタムモデルルータ設定で、コスト最適化と性能の両立を狙います。
自動
品質・速度・コストを踏まえた割り当て（と説明）
カスタム
ルール設定で「どのモデルが何を担当するか」を設計
DISTINCTION
11 / 16
単なるチャットじゃない
統合の焦点
本記事の中心メッセージは、「ターミナル作業環境そのものを統合的に扱うエージェントCLI」です。
入力
シェル操作を自然に扱う
状態
セッション文脈を持続
出力
全画面/対話型アプリも扱う
英語語彙メモ: session（セッション） / multiplexing（多重化） / routing（ルーティング）
CAUTION
12 / 16
期待値の調整
評価と運用の確認Check
価値は高そうでも、成功率・失敗時の回復・セキュリティ境界・比較の定量根拠などが本文からは十分読み取れません。
品質
ベンチマーク / 評価方法 / 成功率の根拠を要確認
運用
失敗時に人間がどれだけ制御できるか、リカバリ設計を確認
セキュリティ/データ取り扱い（ログ、保存期間、監査、暗号化など）も公式情報で補完が必要です。
CLOSING
13 / 16
意思決定の要点
導入は“適合確認”でFit
意思決定は、あなたのワークフローで再現性が出るか、失敗時のコントロール範囲、コスト/品質のトレードオフ、情報の取り扱い要件を基準に行うのが安全です。
i
自分の端末操作（移動・対話・全画面）で効くかを小さく検証
ii
失敗・例外時の挙動と、人間の介入手段を確認
iii
ルーティングによるコスト見積もり条件と、セキュリティ/運用要件を照合
参考: Warp Agent CLIが目指すのは「ターミナル統合エージェント」であり、そこが導入効果の鍵になります。
