KNOWL
02 / 16
永続メモリの設計思想
supersessionで誤誘導を抑える
knowl は、AI開発エージェント向けに「リポジトリ単位の永続知識」を提供し、更新された事実だけが検索で優先されるように設計されています。
PROBLEM
03 / 16
雑多メモの罠
古い情報が競合する
エージェントは各セッションで基本的に「空から始まる」ため、永続メモリを雑に追記すると、古い主張が検索で同時に上位に出て誤判断につながります。
典型
append-only だと 過去 と 更新 が同居
結果
「現在の工学的真実」を取り違える
CORE
04 / 16
訂正として扱う
supersessionが中心
knowl は「同一主題の書き込み」を訂正（更新）として扱い、置き換え済み（superseded）の記録を通常の retrieval から退避させます。
入力
新しい事実（同一主題）
運用
旧記録は superseded として検索対象外
RESULT
05 / 16
ON/OFF差が大きい
精度ベンチマーク
retrieval-levelの主張として、supersession を ON にすると top-1 精度が 98%、OFF では 47% まで下がると報告されています。
retrieval-level
ON top-1 = 98%
retrieval-level
OFF top-1 = 47%
end-to-end
総合評価として 90 を報告（他方式より優位、という構図）
KNOWLEDGE
06 / 16
7種類に型化
fact/decision/…
knowl は知識を 7つの型に整理し、単なる自由文ノートではなく「何をすべきか」や「何を守るか」に検索が寄るようにします。
i
fact（事実）
ii
decision（判断）
iii
goal（目標）
iv
constraint（制約）
v
architecture（設計）
vi
state（状態）
vii
skill（技術/手順）
QUALITY
07 / 16
似てるだけじゃ足りない
意味の違いを分ける
文の類似度だけでなく、現在の意思決定・目的・制約といった「用途の違い」を検索ランキングに反映させ、解釈のブレを抑えます。
検索の軸
「いま必要な型」が上位へ
期待
参照粒度・目的が明確になる
FRESHNESS
08 / 16
evidenceで陳腐化を扱う
「古くなる前提」
code が移動・変更されると証拠（evidence）が陳腐化し得るため、「常に正しい」を前提にしない設計姿勢が明示されています。
紐づけ
evidence をファイル/シンボルへ
現実
変更で drift（鮮度のズレ） が起こりうる
LIFECYCLE
09 / 16
状態で制御する
active / superseded
knowledge はステータス（active/deprecated/rejected/archived/superseded）や鮮度、信頼度、根拠（evidence）を保持し、整合性を取りにいく方向性が強調されています。
active
いま有効
deprecated
非推奨
rejected
却下
archived
保管
superseded
置換済み（検索退避）
目的
誤情報の再利用を抑える
DEPLOY
10 / 16
ローカルDB中心
アカウント不要
.knowl/ 配下にローカルDBを置き、アカウントやAPIキー不要を掲げます（共有は任意、必要に応じてプロモート等の手順）。
保管
.knowl/ にDB
接続
CLI / MCP 経由で同一ローカルストアへ
POLICY
11 / 16
「何でも保存」しない
会話ログは境界つき
基本方針は「会話そのものは保存しない」。必要ならファイル上のトランスクリプト検索をオプトインにする、という線引きが書かれています。
デフォルト
プロンプトや stdout、環境変数などの生ログは記録しない方針
例外
トランスクリプト検索はオプトイン（必要な場合だけ）
CRITIQUE
12 / 16
強いからこそ
運用品質に依存
supersession は強力ですが、誤った置換（本当は別価値・条件付きの前提の違い）をすると、後続の検索が不利になり得ます。
再現性
ベンチ数字は評価条件やタスク依存（そのまま再現とは限らない）
前提
「同一主題として正しく更新」ができて初めて効く
緩和
確信がない場合に両方残す、viewerでの確認/監査が重要（と本文の文脈）
CLOSING
13 / 16
結論
「現在の真実」を守る
knowl は、置き換え（supersession）でステール情報を退避させつつ、7型・evidence・ステータスで整合性を運用する永続メモリとして有望だとまとめられます。
勝因
supersession による競合抑制
要点
7型で参照目的を明確化
注意
編集品質・監査で最終品質が決まる
