KOTRO
02 / 17
ローカル統合ガバナンス

Control Plane

Kotro（kotro-proxy-engine）は、コーディングエージェントの経路を「監査・制御・コスト管理」するローカル基盤です。
同じダイヤル KOTRO_MODE で、MCP（ツール）とLLM（プロバイダ通信）を一貫制御します。

Problem
03 / 17
攻撃面が二つある

Two Planes

エージェントが扱う「ツール（MCP）」と「LLMへのリクエスト経路」は別物で、危険も別系統で起きます。
プロンプトインジェクション、ツールスキーマすり替え、秘密情報漏えい、無限ループ課金などが現実に起こり得ます。

Metaphor
04 / 17
証拠で止める

Flight Recorder

Kotroは「止めたか」だけでなく「何が検知・ブロック・変換されたか」を後から再現できる設計思想を持ちます。
Escape Lab（再現評価）で“検知結果の説明可能性”を重視しています。

Architecture
05 / 17
同じダイヤルで統合

KOTRO_MODE

KOTRO_MODE は disabled / audit / enforce の段階運用です。さらに キルスイッチ がモードより優先され、最優先停止として働きます。

disabled

ガードレール機能は無効。

audit

検知中心で記録（ブロックは抑制寄り）。

enforce

より積極的にブロック・強制制御。

Kill switch

緊急停止。モードより優先。

Planes
06 / 17
MCPとLLMは別制御

MCP / LLM

Kotroは mcp-wrap とLLM側プロキシを分け、異なる脅威に対応します。
ツール操作の“正当性”はMCP側、LLM経路の“安全性・コスト”はLLM側です。

MCP側（mcp-wrap）

ツールスキーマのdrift隔離、引数検証、危険操作にオペレータ承認。

LLM側（プロキシ）

注入検知・秘密情報レダクション・キャッシュ・サーキットブレーカー・予算制御。

MCP
07 / 17
Toolsの“すり替え”封じ

mcp-wrap

ツール呼び出しは、プロンプトが安全でも危険になり得ます。
そのため、ツールスキーマのピン留め（drift quarantine）や引数検証で“rug-pull”を抑止します。

Pin

ツールスキーマを固定しdriftを隔離。

Validate

引数を検証して不正を弾く。

Approve

破壊的/高リスク操作は TaskEnvelope 等で承認。

LLM
08 / 17
注入と漏えいを潰す

Prompt Guard

LLM経路では、プロンプトインジェクション検知や秘密情報のレダクションを行います。
さらに無駄な再課金や無限ループの課金増を抑えるため、キャッシュ・サーキットブレーカー・トークン予算が用意されています。

Injection

KOTRO_INJECTION_BLOCK などで注入をブロック。

Redaction

秘密情報をレダクションして漏えいを抑止。

Cache

X-Kotro-Cache（例：HIT）で同一状態の再課金を削減。

Budget

トークン予算（例：429）やサーキットブレーカーで暴走を止める。

Reality
09 / 17
“ローカル”でも外へ出る

Proxy Pattern

KotroはIDE/エージェントからのHTTPを受け、内部で検知・レダクション・キャッシュ等を実施して上流へ転送します。
完全オフラインではなく、「ローカルで監査してから外へ出す」構図です。

目標はサンドボックス隔離ではなく、経路ポリシー制御＋証拠の両立です。

Clients
10 / 17
IDE接続の制約

Cursor Bridge

クライアントごとに接続方法が異なり、制約がそのまま運用条件になります。
特にCursor Chatはローカルへ直接呼べず、ブリッジ＋認証が必要とREADMEに明記されています。

一般

IDE/エージェントからKotroへHTTPで接続。

Cursor Chat

Cursorのクラウド経由のみ。SSRFポリシー制約でトンネル＋ブリッジ認証が必要。

Honesty
11 / 17
緑＝絶対安全ではない

Escape Lab

Escape Labの「Honesty note」により、緑ラン＝攻撃が常に防げた保証ではありません。
アウトカム一致の表示であり、未カバーシナリオがあることが明記されています。

主張の範囲

“検知・評価の再現”と“宣言アウトカムの一致”。

注意点

未カバーがあるため、完全防御を期待しない。

Takeaway
12 / 17
導入の見立て

Strong, Conditional

Kotroは「経路ごとの制御（MCP/LLM）＋証拠」をセットにする点で有望です。
ただしREADME範囲だけでは有効性の条件（設定・カバレッジ）を評価し切れないため、段階検証が必要です。

Security

MCPスキーマ固定・引数検証・危険操作承認。LLM注入検知とレダクション。

Risk

Escape Labは“完全保証”ではない。未カバーが存在。

Ops

KOTRO_MODE 段階運用とキルスイッチ、flight recorderで後追い確認。
