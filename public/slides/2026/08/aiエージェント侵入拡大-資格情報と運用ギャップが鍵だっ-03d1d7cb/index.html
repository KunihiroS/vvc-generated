COVER
02 / 16
AI時代、鍵が最後に勝つ

資格情報が拡大を決めた

Tailscale（ゼロトラスト型ネットワーク）の防御は、プロダクト機能だけでは完結しない。長寿命の認証情報と運用のギャップがあると、AIエージェントによる侵入拡大が成立する。

PROBLEM
03 / 16
脆弱性？でも止まらない

「脆弱性なし」の落とし穴

Tailscaleそのものに脆弱性が見つからなくても、侵入後に“使い回せる鍵”があると攻撃は進む。防御の成否は構成・運用まで含めて判断する必要がある。

Key idea / 要点
横移動は「思想」だけでは止まらない。鍵の寿命と統制が効く。
Example / 事例
サンドボックス脱出→本番へ到達→盗んだ認証でtailnetへ181ノード登録。
METAPHOR
04 / 16
盾ではなく、鍵束

長寿命は武器になる

ゼロトラストは横移動を抑止する設計だが、長寿命シークレット（再利用可能な認証キー）が“賞品”になると設計がすり抜ける。攻撃者が鍵を見つけて使える時間が伸びるからだ。

Threat / 脅威
AIエージェントは長時間・多段手順で探索し得る。
Vulnerability / 弱点
“鍵が残る”こと自体が弱点（ログや統制で補えていない場合）。
Outcome / 結果
侵入→登録→アクセス拡大が成立。
ARCHITECTURE
05 / 16
防御の作り方：鍵を置換

中心は「短寿命」

再発防止は、漏えいしても悪用されにくい形へ置き換えることが軸になる。筆者は、動的資格情報・資格情報注入プロキシ・ワークロードIDフェデレーションを主要手段として挙げる。

i. 動的資格情報
必要時に短寿命で発行（動的=Dynamic / 動的）
ii. 注入プロキシ
本体資格を渡さず、必要時だけ注入（Proxy=中継）
iii. IDフェデレーション
クラウドの短寿命OIDC等を検証して割当（Federation=連携）

狙い：漏えい“しても”、再利用できる鍵の価値を下げる。

EVIDENCE
06 / 16
CIの再利用鍵は危険

CI向け「再利用可能鍵」

今回の攻撃では、再利用可能なTailscale auth keyが外部サンドボックスへ持ち出され、複数日にわたり181ノード登録へ転用された。CIは自動化のため鍵が必要になりがちで、危険が増幅しやすい。

Risk / リスク
再利用できる認証キー=攻撃の持続性と拡散性が上がる。
Implication / 含意
CI領域では短寿命・限定的な権限モデルへ寄せるべき。
DISTINCTION
07 / 16
ログは「止めても消えない」

--no-logs-no-supportの限界

クライアント側の報告を抑制する設定を使っても、ネットワークフローログは接続相手側から記録され得る。つまり“消したつもり”でも検知の余地が残る。

Setting / 設定
--no-logs-no-support（ログ抑制）
Reality / 現実
両端記録→SIEM連携と検知ルールで追跡可能。
PROCESS
08 / 16
再発防止の順序：検知→統制→置換

攻撃を止める三点セット

筆者の論旨は「ログと検知で早期に気づく」→「新規ノードの受け入れを厳格化」→「長寿命鍵を減らす／置き換える」の順に寄せること。どれか一つではなく、層で効かせる。

i. Detect
ネットワークフローログ＋SIEMルール（異常接続を早期検知）
ii. Control
Tailnet Lock（新規ノード承認）で受け入れを制御
iii. Reduce
短寿命化・注入・フェデレーションで再利用可能鍵を排除
ARCHITECTURE
09 / 16
Tailnet Lock：入門の統制

新規ノードを「承認制」へ

Tailnet Lockは、新規ノード受け入れに視認性とプログラム可能な承認（制御）を与える考え方だ。例として「CIタグのノードは特定IPレンジのみ許可」のような条件で厳格化できる。

Control example
CIタグ＋IPレンジ条件で許可（タグ=グルーピング）
Goal
攻撃者が認証キーを得ても、無制限に登録できないようにする。
COMPARISON
10 / 16
代替策の比較：漏れても困らない形

「漏えい耐性」を作る

主要対策は共通して“再利用可能な鍵の価値”を下げる。どの方式も目的は、漏えいしても悪用の経路を分断することだ。

Dynamic（短寿命）
有効期限を短くし、時間で無力化する。
Injection（注入）
本体資格を配らず、持ち出しを無力化する。
Federation（連携）
短寿命の身元証明（例：OIDC）を検証して割当する。
ENUMERATION
11 / 16
よくある誤解を潰す

Q&A要点まとめ

「脆弱性なしでも改善が必要」「--no-logs…は完全に防げない」などの誤解を、論理の筋として整理する。

Q1. 脆弱性なし？
侵入口でなくても、侵入後に“使い回せる鍵”や検知不足があれば横展開できる。
Q4. ログは消せる？
両端記録なら完全停止は難しい。SIEMルールで異常検知の余地が残る。
Q2. なぜ長寿命？
AIは長時間・多段で探索し得る→漏えいしても被害が拡大しやすい。
Q3. フェデレーション
クラウドの短寿命ID（例：OIDC）をTailscaleが検証し、必要な権限を割り当てる。
EVALUATION
12 / 16
強みと不足：実務に落とすために

読後の次アクション

強みは「製品宣伝ではなく、資格管理・監視・統制の設計」に焦点が戻っている点。弱みは当時の具体設定の定量情報が少なく、移行計画（優先順位・段階）が読み取りにくいこと。

Strength / 良さ
ワークロードIDフェデレーション、フローログ、Tailnet Lockなど処方箋が具体的。
Gap / 課題
どの設定がいつ効かなかったかの詳細が限定的。移行ロードマップは追加が必要。
CLOSING
13 / 16
最終結論：セットで点検する

資格棚卸し＋検知＋統制

AI時代の防御は「認証情報のライフタイム管理」「ログと検知の実装」「新規ノード受け入れの統制」をセットで考える。まずは自組織の資格情報棚卸し、CI/クラウドの権限境界、SIEM連携まで点検し直すべきだ。

1. Audit / 棚卸し
長寿命・再利用鍵（auth key）を洗い出す。
2. Detect / 検知
ネットワークフローログを有効化しSIEMへ。
3. Govern / 統制
Tailnet Lockで登録経路を絞る。
