cover
読みではなく、強制へ
SIGILで“手順”を実行可能に
AIエージェントのスキルは、読ませるだけでなくコンパイルして必須工程を強制するべきだ、という主張を整理します。
キーワード: SKILL.md / AG-IR / Jac / Owner Test / Applicable-Mandate Compliance
03 / 16
problem
“理解”と“実行”は別
文脈依存の完了報告
文章として渡した手順は、モデルが“実行したつもり”で完了報告してしまう余地があります。必要なテスト実行や承認待ちが、必ず行われる保証になりません。
Prompt実行の特徴
手順遵守がモデル判断に依存
起きがちなズレ
検証を省略して完了報告
04 / 16
metaphor
プロンプトは“読んだ気”になる
テキストは命令にならない
スキルが“助言（advice）”のままだと、実行に必要な検証やゲートが制御フローに入りません。SIGILは手順を“プログラム（control flow）”に変換します。
読む
理解の整合性
実行
必須チェックの強制
SIGIL
コンパイルしてゲート化
05 / 16
architecture
SKILL.md → 実行フローへ
コンパイルの流れ
SIGILはMarkdown形式のSKILL.mdを入力に、必須ステップや検証を抽出し、AG-IRへ型付き中間表現として変換します。
1
必須要件を該当箇所から抽出
2
AG-IR（typed IR）へ変換しグラフ化
3
Jacエージェントへ機械的に落とし込み
06 / 16
architecture
“完了条件”をコードに寄せる
強制の要点
テスト実行→終了コード確認→合格時のみ完了、のような段取りをハーネス側の検証ノードやゲートで固定します。これにより手順遵守が実行上の制約になります。
文章だけ
省略余地が残りうる
SIGILコンパイル後
検証通過が進行条件
07 / 16
distinction
Owner Test
コード所有 vs モデル所有
Owner Testでは、決定が入力で定まる処理はコードが所有し、解釈や合成が必要な処理はモデルが所有します。抜けやすい“決定的チェック”をコード側へ移します。
Owner: Code
コマンド実行 / 終了コード読み取り / 指定ファイル生成
Owner: Model
要約 / 評価 / 解釈を要する部分

process
AG-IRとコンパイルゲート
漏れを“失敗”にする
SIGILはAG-IRへの変換時に、必須ルールの表現漏れや必須成果物の生成、承認段階の実ブロックなどをチェックします。
防ぐ
コンパイラが勝手に補う事態
検出
必須表現の漏れ
結果
コンパイル失敗として顕在化
09 / 16
evidence
30スキルの評価
Applicable-Mandate Compliance
30種類のエージェント・スキルで、「該当する必須ステップ（mandate）が実際に完了した割合」を測定します。平均ではなく“完了の実態”に焦点があります。
指標の意味
必須ステップが要求された形で完了した割合
観測した変化
完全実行が一般ケースへ寄る

12 / 16
comparison
なぜ効く？（要因の整理）
有効性の筋
SIGILは“助言”を“実行可能な制御フロー”に変え、コードでゲート・検証を所有することで、抜けやすい必須工程を強制します。
効いている可能性
AG-IRで必須要件を機械的に表現
効いている可能性
コンパイルゲートで前進条件を固定
一方で、外部ツール失敗・入力不足・スキル記述の誤りは別途起こり得るため、運用設計も重要です。
