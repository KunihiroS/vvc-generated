MCP SERVER
02 / 16
永続する開発環境
Reachpad MCPサーバ
AIコーディングエージェントが、リポジトリ投入→環境作成→実行→フォーク→再開まで行える“持続型クラウド開発基盤”です。
EN term / JP
Model Context Protocol / モデル文脈プロトコル: ツール呼び出しを共通化
Core idea
使い捨てではなく、停止後もディスク状態を復元（ただしプロセスは継続しない前提）
PROBLEM
03 / 16
“動いた”の誤認
LLMは 結果を取り違える
ストリーミング実行で「未終端」を成功と誤認したり、タイムアウト競合でクライアント側の誤った結論を採用したりしがちです。
Risk
非冪等（idempotentでない）コマンドの誤リトライ
Risk
“ログ”や“出力”の扱いで文脈が破壊される
Risk
環境は復元されても、実行プロセスは残らない問題の誤解
METAPHOR
04 / 16
コールドブート前提
リンクは 部屋、プロセスは別
ディスク（ファイル・依存関係・ビルド状態）は続くのに、プロセスは例外として継続しません。だから「同じ部屋＝同じ待ち受け」が成り立ちません。
Persistent state / 永続状態
停止後も復元：依存関係の再インストールを削減
No long-running process / プロセス非継続
pause後は“起動はされてもlistenしない”可能性がある
ARCHITECTURE
05 / 16
REST境界で統一
ツール呼び出しの 翻訳器
MCPサーバが、モデル/クライアントの要求をサーバ側のREST API（境界）へ落とし込み、SDK/CLI/サーバ自体がそれを翻訳する方針です。
Transport / 通信
stdio と Streamable HTTP を“分岐せず追加”で揃える
MCP meaning
共通方式でツールを呼ぶ（Claude Code / Cursor等）
State model
環境は持続、実行はコールドブート（継続しない）
CORE
06 / 16
“成功”の定義を締める
UNKNOWN/Refusal/競合
未終端ストリームは UNKNOWN 扱い、締切競合はサーバ側回答優先、失敗理由は refusal として返しモデルの次の行動を判断可能にします。
i. 未終端
未確定を成功扱いしない → UNKNOWNへ
ii. 締切競合
サーバ側の確定結果を優先（クライアント推測を抑制）
iii. 失敗理由
refusal を結果に含め、モデルが判断できる材料に
EVIDENCE
07 / 16
数値を決め打ちさせない
リミット/残量は サーバから
数値（リミットや残量）をクライアントで決め打ちせず、サーバから返して意思決定を頑健にします。
Goal
モデルが“前提を崩した状態”で再実行しない
Mechanism
クライアントの推測を抑え、サーバの確定値に寄せる
DISTINCTION
08 / 16
keep vs restart
“復元”と“再開”を分ける
環境は復元されても、pause後にプロセスがいないことがあるため、ポートリンクが直ちに機能するとは限りません。
What persists / 残る
ファイル・依存関係・ビルド状態（ディスク封印→復元）
What stops / 止まる
実行プロセス（コールドブート前提）と、listen待ち受け
SECURITY
09 / 16
GETをやめ、Originを絞る
HTTPは“ツール”として扱う
HTTP側はGETを使わず、ツールのリクエスト/レスポンスとして扱い、ブラウザ由来攻撃（DNSリバインディング等）を避けるためOrigin制御を入れます。
Transport safety
GET禁止：意図しない経路を避ける
Origin control
Origin制御でブラウザ攻撃面を縮小
Same semantics
stdio/HTTPで振る舞いがズレない方針
CREDENTIALS
10 / 16
境界で扱う
資格情報は ブローカーで処理
資格情報（秘密情報）は境界で処理し、資格情報の値が環境・ログ・ストアに入らないことを目標にします。
Intended property
“値を直接入れない”設計（境界処理で漏洩経路を狭める）
But read access exists
環境に書き込んだ資格情報は環境内で読める（運用次第でリスクが変わる）
PORT LINK
11 / 16
“プライベートURL”ではない
ポート公開リンクは 危険前提
リンクを知ることがアクセス可能性に直結し得る性質があるため、プレビュー的に扱うべきだと明言されています。
Behavior
再起動しても同じリンクが同じポート内容として機能
Security stance
短命化・期限・IP制限等はREADMEのみでは断定不可
Operational takeaway
共有手順とアクセス制御の前提を、必ず導入時に補完資料で確認
OPERATION
12 / 16
pause/再開の誤判定を防ぐ
運用の要点は 手順
READMEの境界理解が前提で、特に「環境復元」と「サービス再立ち上げ」を混同しないことが混乱を減らします。
Typical workflow
1) 環境復元を前提にファイル/依存を維持 → 2) 必要ならlisten側を再起動 → 3) ポート公開でリンク入手
LLM guardrails
UNKNOWN/refusal/競合優先に合わせ、再試行方針を“未確定を成功扱いしない”解釈に統一
TAKEAWAY
13 / 16
判断の基準が揃う
永続状態 × 安全な意味論
Reachpad MCPサーバは「ディスクは持続、実行はコールドブート、そしてモデルが誤る点をプロトコルで封じる」設計思想です。
1. 永続環境：再インストール/再ビルドの手戻りを減らす
2. 意味論：UNKNOWN/refusal/競合優先で“成功の誤認”を抑制
3. セキュリティ前提：Origin制御・資格情報境界・ポートリンクはプレビュー扱い
