見えない埋め込み、言葉で可能

統計指紋

プレーンテキストでも、LLMが次トークンを選ぶ「確率の偏り」を仕込めます。その偏りは長い文章ほど累積し、検出器は統計検定で痕跡を測定できます。

Problem
03 / 16

埋め込み領域がない

プレーンでも

画像やPDFのように不可視領域を埋めるのではなく、文章生成の「単語選択」の選好が情報担体になります。どのトークンを選ぶかが、結果として検出可能な“指紋”になります。

Metaphor
04 / 16

一粒は偶然、集めると差

累積偏り

単一の選択は人間でも起きるほど小さな違いですが、長文では微小な優先が連鎖して現れます。検出は「単語」ではなく「多数の小さな選択の合計」に反応します。

Architecture
05 / 16

確率を少し動かす

ウォーターマーク

狙いは“見えるメッセージ”ではなく、生成時の選択確率を微調整して分布をずらすことです。自然さは保ちつつ、設計された偏りだけが統計的に残るようにします。

Core
06 / 16

何が嬉しいのか

三つ

i 可能
平文でも“埋め込み”できる（冗長性があるため）
Plain textでも可能 / Plaintext watermark
ii 検出
統計パターンの有無をスコア化して測れる
Statistical detectability / 統計検出
iii 性質
コピーに強く、言い換えなどの編集に弱い
Robust to copy / Fragile to rewrite
Evidence
07 / 16

“個別の単語”ではない

統計の証拠

「howeverが入っている」だけでは意味がありません。重要なのは、鍵（規則）に基づく優先トークン集合が、通常より“驚くほど”多く観測されるかどうかです。

Process
08 / 16

検出の流れ

再構成→スコア

検出器は鍵に基づき、各位置で優先されるべきトークン集合を再構成します。その出現頻度が期待からどれだけ外れるかをスコア化し、統計的に判定します。

Distinction
09 / 16

断定 vs 証拠

言えること

検出器が言える
設計された統計パターンが含まれているか（確率的証拠）
含意判定 / Presence of pattern
検出器が言えない
どのモデルか・生成割合・誰が編集したかの特定（追加情報が必要）
特定不可 / Identity not revealed
Comparison
10 / 16

編集で証拠が薄れる

コピー

コピー
トークン列が保持されやすい → シグナルが残りやすい
Token sequence retained / 読み替えなし
言い換え
観測点の置換が増える → 選択履歴が薄れ検出確度が下がる
Rewriting breaks evidence / 証拠破壊
Security
11 / 16

鍵が意味を作る

秘密ルール

鍵がないと、第三者が「どの位置で何を優先すべきか」を推定し、信号を消す・偽装する攻撃が成立しやすくなります。鍵により、設計意図に基づく検出が可能になります。

Risk
12 / 16

二値化の危険

過度な断定

検出結果は「AIが書いた／誰が書いた」という確定ではなく、統計パターンの存在確認です。組織が断罪のように扱うと、誤りが起き得ます。

FAQ
13 / 16

よくある誤解

五つ

Q1
100%判定は不可：出力は“パターンの含有”の確率的証拠
Q2
単語単体より統計：長文で意味が安定し短文は偶然に近い
Q3
鍵が嬉しい：推定されにくく偽装・消去が難しくなる
Q4
回避は完全ではない：編集の範囲と種類・設計と検出閾値に依存
Q5
品質低下は必須ではない：分布の“少しの動かし方”で自然さを保つ
My opinion
14 / 16

単独の決め手にしない

多証拠へ

私は、この仕組みを出所推定の“単独の決め手”ではなく、多証拠の一要素として扱うべきだと考えます。特に誤判定が重大な領域では、手続き（追加検証や異議申し立て）が不可欠です。
