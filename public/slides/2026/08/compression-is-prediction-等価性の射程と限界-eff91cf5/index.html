圧縮と予測の一致点

Compression

＝ Prediction

「圧縮＝予測（compression is prediction）」は、いつ厳密に成り立ち、どこからスローガンになるのかを、等価な量と前提条件に分解して整理する。

前提：圧縮は原則可逆（可逆圧縮）。予測は確率付与（log-lossと整合）。
Problem
03 / 16

等価性がブレる理由

何を測るか

「圧縮の良さ」と「予測の良さ」が同じ最適化になるには、表現対象・直列化順序・モデル共有・復号契約を先に固定する必要がある。

Target / 対象
どのオブジェクト集合（同値類）を符号化対象にするか
Contract / 契約
復号後に何ができる必要があるか（復元のみ／部分アクセス等）
この前提が曖昧だと、符号長の意味も評価基準も決まらない。
Architecture
04 / 16

固定された世界

理想符号長

既定の確率モデル \(Q\) を「順序付き系列モデル」として合意し、系列 \(x_{1:n}\) を理想符号（算術符号等）で符号化すると、符号長は \(-\log_2 Q(x_{1:n})\) になる。

Payload / 符号長
L = -log₂ Q(x₁:n)
Prediction / 予測
逐次条件付き確率の累積 log-loss（chain rule）と一致
「符号化問題が固定された後」だけ、compression＝predictionが厳密に等価になる。
Equivalence
05 / 16

一致する最適化

同じ目的関数

同じ合意 \(Q\) の下では、「圧縮（ビット数最小）」と「予測（log-loss最小）」は同じ最適化問題になる。

i / 符号化
目的：理想符号長 \(L\) を最小化
ii / 予測
目的：累積 log-loss を最小化
iii / 一致
\(L = -\log_2 Q(x_{1:n})\) で等価
ポイント：ここでの「圧縮」は理想的符号長の評価（オーバーヘッド除外）として扱われる。
Distinction
06 / 16

本質：前に決める

何を表すか

現実の「圧縮」は、確率モデル適用の前にすでに分岐している。どの同値性を許すか、直列化する順序は何かが、符号化設計を決める。

Minification / 短縮化
「単に短く」でも復元可能性・同値性の定義が変われば圧縮が別物になる
Serial Order / 直列化順序
\(x_{1:n}\) の並び方が \(Q(x_{1:n})\) と log-loss を変える
この合意が固定されないと、「圧縮＝予測」はスローガンの域を出ない。
Model Choice
07 / 16

学習は別コスト

モデル共有問題

\(Q\) を学習して使う場合、符号長に加えて「デコーダが再現できるだけのモデルの記述長」も別途コストになりうる。

Missing Term / 落ちやすい項
モデルパラメータ（表現）を送る長さを log-loss に単純合算できないことがある
MDL / 二部記述
「モデル」と「データ」を分けて総量を比較する考え方
見かけ上の圧縮過大評価（オフライン学習・過学習）を避ける必要がある。
Entropy
08 / 16

log-lossは何を下げる

H(P)は下がらない

log-loss改善は一般に元分布のエントロピー \(H(P)\) を直接下げるとは限らない。多くはクロスエントロピーと、その中のミスマッチ（KL）を下げている。

Cross-Entropy / 交差エントロピー
H(P,Q)=H(P)+D_{KL}(P||Q)
Interpretation / 読み替え
改善＝主に \(D_{KL}(P||Q)\) の減少（確率のズレを縮める）
「エントロピーが下がった」と断言する誤解を防ぐための注意点。
Process
09 / 16

prequentialの発想

学習の織り込み

逐次更新（prequential等）では、パラメータ記述長を別に払う代わりに、オンライン予測の劣化として符号長に織り込むという見方ができる。

Before / 別払い
通常：モデル記述長を別項として扱う必要が出る
After / 織り込み
prequential：オンラインでのズレを通じて総コストに反映する
「何を符号長として数えるか」を契約として明示することが要点。
Access
10 / 16

圧縮だけでは足りない

復元契約

最短ビット列だけで評価すると、データ構造が要求するアクセス要件（ランダムアクセス、部分復号、検索）まで満たせない。

Variable-length / 可変長
エントロピー符号は前から復号して状態再構築が必要になりやすい
Checkpoints / 補助情報
ランダムアクセスにはチェックポイント等の追加情報が要る
したがって compression＝prediction は「復元の範囲の契約」に限られる。
Bits vs Use
11 / 16

同じ圧縮率でも別物

契約が違う

ビット詰めとエントロピー符号では、アクセスの容易さが変わる。圧縮率だけでは「使える形」になっているか判定できない。

Fixed packing / 固定長
位置対応が簡単になりやすい
Entropy coding / エントロピー符号
前依存が生じやすくアクセスに工夫が要る
Evaluation / 評価
符号長＋アクセス時間などを同時に最適化すべき
「短い＝速い」とは限らない（契約とデータ構造が支配する）。
Combinatorics

カウント版の見方

type class

ゼロ次経験エントロピーを「確率（最尤推定のlog-loss）」で説明する方法と、「型クラスの個数を数える」方法は、大きい極限でほぼ同じコストを与える。

Prediction view / 予測
最尤推定の log-loss をコストとみなす
Counting view / 組合せ
型クラス（type class）の個数を数える
予測だけに寄らない説明からも限界が導ける、という整理。

スローガンの正しい解像度

成立条件

「圧縮＝予測」は“符号化問題が固定された後”には正確に等価だが、契約（対象・直列化・モデル共有・復号要件）が暗黙に固定されていない限り不十分になる。

Fixed / 固定
合意モデル \(Q\) と符号化手続きが固定
Contract / 契約
復号後の使い方まで含めて評価すべき
「何が一致し、何が一致しないか」を常に分けて考える。

判断のための3問い

使い分け

次の3点を満たすほど、「予測を良くする＝圧縮を良くする」の解釈が強くなる。

i / 対象
復元すべきもの（同値性）は何か
ii / モデル
デコーダが知っている \(Q\) は固定か／共有されるか
iii / 契約
部分アクセス・検索などの要件は満たす契約か
モデル学習を含むなら「記述長」も総合評価に入れる。
