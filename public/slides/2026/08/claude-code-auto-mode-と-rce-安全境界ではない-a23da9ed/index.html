境界は“分類器”じゃない
Auto Mode とRCE
Claude CodeのAuto Modeは利便性の自動化であり、安全境界（サンドボックスの代替）ではない、という論点です。
テーマ / Theme
ウェブ要約入口 → 段階的に実行へ
キーワード
プロンプトインジェクション / ツール経路 / Python import
Problem
02 / 12
止まる？止まらない？
問題の核心
Auto Modeは承認を挟まず、分類器の判断でツール実行が進みます。重要なのは「分類器が止めきれるか」だけでなく、「隔離・ネットワーク制御・停止/後始末が本当に機能するか」です。
期待されがち / Common belief
“AIが安全判定するから大丈夫”
論点 / Claim
分類器は境界ではなく“可能性を残す”
Metaphor
03 / 12
正当作業の顔
攻撃の形
攻撃は「無視して実行」型の命令上書きではなく、要約・解析など“無害に見える手順”に沿って段階的に悪性実行へ到達します。
Step i
入口：悪性サイト/データ
Step ii
目的達成：要約・デコード・解析
Step iii
最短経路：シェル/ Pythonへ
Architecture
04 / 12
ツール経路が地図
Auto Modeの流れ
AIエージェントは目的達成のためにツール（Web取得、シェル実行、Python実行など）を呼び出します。Auto Modeはその流れを安全分類器で制御し、人間の承認を外します。

判断ポイント

安全分類器が“次のツール”を許可

攻撃側の着眼

ツール選択/実行順を“道筋”として悪用

危険点

許可後に隔離/停止/後始末が崩れる

前提

攻撃は複数ステップの連鎖で成立

要約 → ZIP → import
段階的なRCE
例として、悪性サイトがZIPアーカイブを返し、Claudeがデコーダ処理を自作する過程を悪用。アーカイブ内の `struct.py` がモジュールシャドーイングとして動作します。
i.入口

ii.準備
Claudeがデコード/解析を進める
iii.実行
`struct.py` → import乗っ取り（RCEへ）
Distinction
07 / 12
命令注入じゃない
攻撃の違い
この論点は単なる「プロンプトに命令を書き換える」ではありません。ツール選択や実行経路が最短の“悪性手順”に誘導される点を重視します。
古典型 / Classic
“無視して実行”（指示の上書き）
本投稿 / Here
“道筋”を乗っ取る（ツール経路の誘導）
Evidence
08 / 12
importの探索パス
モジュールシャドーイング
Pythonはimport時に探索パス（例：現在ディレクトリ等）を参照します。攻撃者が同名モジュール（例：`struct.py`）を置くと、標準ライブラリの代わりに攻撃コードが読み込まれ得ます。
仕組み / Mechanism
探索パス → 同名モジュールを優先して読み込み
結果 / Outcome
依存解決の瞬間に攻撃が走る（実行の足場）
防御は“プロンプトフィルタだけでは不十分”になりやすい、という示唆につながります。
Architecture
09 / 12
止める操作が危険
クリーンアップ失敗
攻撃を見抜いた後に停止コマンドを出そうとしても、Auto Modeの安全機構が後続のクリーンアップ（停止命令など）をブロックする場合がある、と示唆されています。
狙い / Goal
停止して被害を最小化
課題 / Risk
“止めること”が安全判断で妨げられる可能性
Comparison
10 / 12
指標の見せ方問題
コミュニケーション
投稿は「0.00%」のような表現が、攻撃面の多様性（別チェーン）とのギャップを埋められていない点を問題視します。利用者の誤認は隔離の省略につながり得ます。
表示 / Metric
単一ベンチの成功率
現実 / Reality
攻撃経路は多様で別ルートあり
影響 / Impact
“安全”と誤認 → 実装が弱くなる
Process
11 / 12
対策は“境界”設計
防御の優先順位
対策はより賢いフィルタだけでは不十分で、OS隔離、ネットワーク egress（外向き通信）制限、監視が本丸だとされています。安全分類器の正誤とは独立に守る設計が必要です。
必須 / Must-have
OS隔離（最小権限）
追加 / Also
ネットワーク egress 制限・監視（C2対策）
言い換え：分類器を“門番”にせず、隔離と通信制御で“壁”を作る。
Closing
12 / 12
結論：前提を変える
Auto Mode は境界でない
この投稿が強調するのは、「モデルが止めてくれる」より「隔離と監視で被害を抑える」という防御思想です。RCEは“平均安全性”ではなく“成立し得る連鎖”で評価すべき、という方向性です。
要点 / Takeaways
i. 承認 ≠ 隔離　ii. 道筋誘導が効く　iii. import罠が実行へ
不確実性 / Caveat
検証環境（OS/設定/再現性）が明確でないため、成功率の一般化には注意
