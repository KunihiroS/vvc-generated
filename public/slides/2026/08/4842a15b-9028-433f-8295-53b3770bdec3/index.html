メモリ問題の本質

Agentic Context Management

「保存・検索」だけでは長期会話の失敗を止められない。取り込み→構造化→多ストア同時取得→統合と忘却までを設計する。

対象：エージェントの“覚える”仕組み（エージェントメモリ／コンテキスト管理）
problem
03 / 14
長期ほど崩れる

限界 3つ

長期になるほど、入力（コンテキスト）を増やしても、RAGで引いても、ファイル保存でも、関連性・精度・運用コストが破綻しやすい。

context window（文脈枠）
長期で関連が薄れ、トークン/費用が増える。
RAG（ベクタ検索）
関連文書は取れても、更新・忘却・統合が弱い。
file storage（ファイル）
参照の取り回しが増え、再送・検索負担が膨張する。
long-run failure（長期劣化）
古い情報の残存、誤参照、エンティティ解決ミス。
この資料の立場：メモリ問題は「保存先」より「運用設計」で決まる
core idea
04 / 14
保存ではない

ライフサイクル 設計

Agentic Context Management（エージェンティック・コンテキスト管理）は、情報を「入れて、構造化して、必要時に引いて、忘れる」までを一連の設計にする。

I. ingest（取り込み）／取り込み
会話から何を記憶候補にするか抽出する。
II. structure（構造化）／構造化
意味を“テキスト”ではなく構造（エンティティ/関係）へ。
III. store（保持）／保持
複数ストアへ書き込み、用途別に保存する。
IV. retrieve+forget（取得/忘却）／取得と忘却
同時取得で統合し、Conscious forgettingで肥大とノイズを抑える。
一言：アルゴリズム改善ではなく、運用の“流れ”を作る
architecture
05 / 14
3ストア同時に引く

統合は 回収時

Synapの例では、会話ターンをDBへそのまま置かず、意味を抽出してベクタ・グラフ・ファイルへ非同期で書き込み、検索時に同時に回収して統合する。

Vector（ベクタ）／意味類似
関連度で引く（近い意味）。
Graph（グラフ）／関係推論
エンティティ間のつながりを辿る。
File（根拠原文）／根拠
出典になる原文ドキュメントへ到達する。

さらにバックグラウンドで統合（Consolidation）や意識的な忘却（Conscious forgetting）を行い、長期劣化に対処する。

ポイント：single-RAG中心ではなく、用途別ストアを束ねる
process
06 / 14
運用の流れを分解

ingest → forget

記憶は“残す”だけでなく、“更新し、統合し、不要になれば消す”ことが品質を左右する。

i. Extract（抽出）／抽出
エンティティ・属性・決定事項を取り出す。
ii. Entity resolution（統合）／同一人物
誰のことかを統合し誤参照を減らす。
iii. Async write（非同期書き込み）
応答待ち時間を増やさず保存を進める。
iv. Retrieve+Integrate（同時回収）
複数ストアを跨いで同時に引き、統合する。
v. Conscious forgetting（意識的忘却）
ノイズ増・肥大化を抑え、品質を維持。
vi. Consolidation（統合）
情報を整理し、参照漏れ・矛盾を減らす。
列挙 i, ii, iii はイメージ（実装詳細は資料外の可能性あり）

精度だけでない

15ms級 取得

長期メモリは処理量が増えるため、体験に直結する取得レイテンシ（回収速度）を要件として示している。

P50 recall latency
15ms未満（<15ms）
15msの提示
“15msの範囲”で回収できる前提を強調
async write
書き込みを待ちにしない（応答遅延を抑える）
why it matters
精度×速度が揃わないと運用で採用されにくい
性能はプロダクト採用に影響：長期ほど計算負荷が効く

distinction
09 / 14
RAGの外側へ

違いは 運用

最大の差は「保存/検索を良くする」ではなく、更新・統合・忘却といった運用の制御をパイプラインとして持つ点にある。

単純RAGの焦点
関連文書を引くことに主眼。
Agentic Contextの焦点
意味を構造化して保持し、回収時に統合する。
長期劣化への対応
Consolidation + Conscious forgetting でノイズを抑える。
エンティティ解決
同一人物の統合で誤参照を減らす。
bilingual（用語補助）: Agentic Context Management = エージェント・コンテキスト管理

数字は条件次第

確認すべき 前提

提示数値（92%など）を一般化するには、同一条件か、失敗の内訳は何かを追加で確認する必要がある。

再現条件

平均より失敗

安全性
忘却や統合の誤動作で誤情報が長期に残るリスク。
セキュリティ境界
暗号化の範囲（メタデータ/検索/鍵管理）を確認する。
採用判断：公開ドキュメントでセキュリティモデルと再現性を確認
closing
11 / 14
結論

メモリは 設計で決まる

Agentic Context Managementの価値は、長期で起きる参照漏れ・誤参照を“保存以外”のライフサイクルとアーキテクチャで抑える点にある。

期待できる点
三層ストア＋構造化＋統合/忘却で長期品質を維持しやすい。
導入時の要点
評価条件・失敗モード・監査性（削除/統合）を追加確認。
性能要件
async書き込みとP50<15ms級の取得が体験の鍵。
戦略的示唆
“長期文脈管理”がプロダクト差別化の中心になり得る。
この読み物のゴール：コンテキスト管理を“アルゴリズム”ではなく“運用設計”として捉える
