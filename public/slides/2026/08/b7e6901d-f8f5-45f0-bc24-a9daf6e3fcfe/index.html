Security boundary drift
要約が境界を動かす
AIエージェントのパイプラインで、変換（要約・復号・整形）を先に挟むと、ポリシーチェックが検査している「表現」と、実際に実行される「効果」が一致しないことがあります。
目標：どの時点で何を証拠として扱うべきか（evidence / capability）を、境界の同一性として整理します。
problem
03 / 16
検査対象がズレる
監査の見せ方
「要約した内容を検査したから安全」と言っても、要約が落とした危険シグナルが、実行に必要な意図・引数・副作用に残ることがあります。
Policy checks 参照
要約後のテキスト（summarized representation）
Execution 実行
元の意味／派生物（tools args / side effects）
metaphor
04 / 16
衣を着た証拠
要約は編集
要約は「無害な圧縮（compression）」ではなく、攻撃者にとって都合の良い形へ再構成する“解釈ステップ”になり得ます。
入力
外部データ／暗号文／不正指示
変換
要約・復号・整形（transformation）
判定
“安全”と見える派生物
architecture
05 / 16
境界はどこ？
境界＝同一性
重要なのは「順序」だけでなく、“許可判断が紐づくオブジェクト”と“実行されるオブジェクト”を同一視できるかです。
Before (誤りやすい)
要約→ポリシー→実行（別物が走る）
Instead (狙い)
派生物ごとの根拠（raw）を維持→効果直前で再評価
evidence
06 / 16
証拠が消える
rawが消失
要約が境界情報（プロベナンス／意図の要点／危険シグナル）を落とすと、ポリシーは本来検査すべき証拠を見ていません。
起きること
監査ログは“要約後”の内容でも、実行は別の意味で進む
結果
許可：要約という派生物 / 実行：元の意図・引数・副作用
distinction
07 / 16
アテステーションの限界
誰の機械？
ハードウェアアテステーションは「どのマシンで実行されたか」に強い一方で、「入力が安全として扱われて良い根拠を満たすか」を保証しません。
HWA attestation 証明
実行環境（プロセス／マシン）の身元
今回の争点
権限昇格に使うべき証拠が、要約で失われないか（raw根拠）
process
08 / 16
汚染追跡
taint / プロベナンス
復号・パース・要約などの変換ごとに汚染（taint）やプロベナンスを追跡し、意味が行動（効果）へ昇格する直前にraw側の根拠で再評価します。
変換点
decode / parse / summarize
管理
taint, provenance（ラベル）
昇格点
tool call /外部送信直前で判定
enumeration
09 / 16
設計の3要件
3つの実装
解決方向は一貫して「raw根拠で縛る」「派生物へ伝播する」「効果側で同一性を強制」です。
i
生のツール出力／原始バイト列を証拠として扱う
ii
変換ごとに汚染（taint）とプロベナンスを追跡する
iii
効果（capability）へ昇格する直前でraw側根拠に基づく再評価
comparison
10 / 16
順序 vs 境界
順序だけでは足りない
暗号化などで意味が生段階では見えない場合、「要約を先に検査すればよい」は成立しにくく、効果に結びつく境界で判断する必要が出ます。
順序中心（弱い）
“検査した”つもりでも、派生物が別物なら攻撃が通る
境界中心（強い）
capability（権限）とside effects（副作用）へ昇格する点で同一性を強制
evidence
11 / 16
digestで拘束
同一性ハッシュ
「検査したもの」と「実行されるもの」を結びつけるには、決定記録をdigest（要約ではなくrawに基づく参照）で拘束し、実行側が別入力を受け付けない設計が必要です。
検査の対象
digest(raw bytes) + stage id
実行側の縛り
許可されたdigest以外のtool args／副作用を拒否
distinction
12 / 16
“ラベル”は形骸化する
taintは改ざん耐性
プロベナンスやtaintラベルを付けても、それがモデルに書き換え可能なテキストとして流れると消えます。境界越えでも改ざんされにくい保持と、許可がその根拠に限定される統合が要ります。
失敗例
ラベルが“文章”として再生成され、弱められる
必要
ラベル保持の方式 + ポリシーが「その根拠でしか許可しない」実装
closing
13 / 16
Takeaway
要約より境界
要約→ポリシー→実行は、攻撃者にとって“監査が見た別物”を作る余地になり得ます。安全の中心は「証拠の同一性（raw↔派生↔効果）」をdigestや汚染追跡で実装的に縛ることです。
実装の最優先：効果境界でraw根拠に基づく再評価と、実行入力のdigest拘束。
