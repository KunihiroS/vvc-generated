2Dで“統合する”IDE / 統合IDE
49Agents
複数端末（tmux/ttyd系）と複数マシンの作業を、ズーム可能な2Dキャンバスに統合するオープンソース構想・実装。
Core / 핵심
無限キャンバスで“空間”管理
2D canvas workspace（空間ワークスペース）
Connection / 연결
ゼロSSH（意識不要）を目標
Relay（中継）＋ WebSocket

03 / 16
タブ地獄 / Tab sprawl
断片化
従来のIDEやターミナルは、タブ・分割ペイン中心で、端末・AI・管理情報が別々になりがちです。
Switch cost
切替の摩擦が増える
Context switching（文脈切替）
Multi-machine
環境ごとに手順が増える
Multiple hosts（複数ホスト）
AI loop
入力/出力の所在が散らばる
AI I/O（AI入出力）
結論：作業を“画面”ではなく“空間”として設計し直す必要がある、という問題意識が核です。

DISTINCTION
10 / 16
安全と運用 / Security & Ops
自己ホスト
“self-host（自前運用）”と“クラウド利用”の違いがあり、リレー運用主体やログ方針は導入形態で変わる可能性があります。
Self-host
自前で管理（責任も自前）
自分で運用（管理範囲が広い）
Cloud
提供側が運用（確認が重要）
運用主体は要確認（挙動差）
Zero SSH
“意識しない”が中心（内部実装は不明）
SSHの有無は要精査
結論
セキュリティ・プライバシーは“実測＋ドキュメント追補”が必要
導入判断は慎重に（特に企業）
