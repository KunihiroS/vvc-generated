Agent Mesh
02 / 16
耐久的履歴で統制
AI開発を再現可能に
Agent Meshは、AIエージェントが生む「依頼・意思決定・結果」を、チャット境界を越えてプロジェクトの共有履歴として管理します。 （durable history / 耐久的履歴）
中心メッセージ
人間の承認（human-only）を要として、承認済みの決定だけが有効になる設計で、状態の分散と曖昧さを減らします。
Problem
03 / 16
チャットは壊れやすい
前提が消える
AI作業はチャット単位で文脈が扱われ、時間が経つと「何を前提に」「誰が承認したか」が見失われがちです。 （context drift / 前提の漂流）
迷子
未対応の依頼や進行中状態が追いにくい
曖昧
決定履歴が散らばり、承認ポイントが不明確
Concept
04 / 16
依頼→決定→結果
REQ/RESで残す
Agent Meshは、REQ/RES（依頼/応答）、バックログ、決定（Decisions）を「耐久的な履歴」として追跡します。 （requirement / response / 決定）
要素 役割
REQ（依頼） 次に何をすべきかを固定化
RES（応答） AIの出力や応答を履歴として紐づけ
Decisions（決定） 提案→改訂→承認のライフサイクルで確定
Backlog（バックログ） 進行状況・優先度・次の仕事の基盤
Architecture
05 / 16
Workbenchが中心
見える化と承認点
Workbench（主要UI）で、チャット復元を減らし「未対応の依頼」「進行中」「優先度」「決定履歴」を人が把握できます。 承認プロセスもUI上で追えます。
状態
進行中・優先度を一目で
履歴
決定・結果をIDで辿れる
統制
承認ポイントを明確化
Process
06 / 16
提案→改訂→承認
決定のライフサイクル
Decisionsは「提案→改訂→承認」を持ち、承認以前の内容が意図せず引き継がれるリスクを抑えます。 ここが品質・安全性・説明責任に直結します。
i. Proposal
AIが意思決定を“提案”する
ii. Revision
提案を“改訂”して精度を上げる
iii. Accept
人間が承認して確定
有効性
決定IDにより承認済み改訂版だけが有効
Governance
07 / 16
人間だけが確定
human-only統制
エージェントは提案や改訂はできますが、承認（accept）は直接人間が行います。 “誰が何を許可したか”が履歴として残るため、ガバナンスが強化されます。
できること
AI：提案 / 改訂 / 出力
できないこと
AI：承認（accept）そのものは不可
Privacy
08 / 16
デフォルトはlocal
local-only設計
プライバシー面ではデフォルトでローカルのみ（local-only）です。Git共有（git-shared）は明示的なオプトインになります。
モード 共有の考え方
local-only 通常は .agent-mesh/ を git add 対象から外し、外部漏えいを抑える
git-shared（オプトイン） canonical config / event log / body files など“共有対象”を選ぶ
Evidence
09 / 16
追記型ログ + 検知
events.jsonlが軸
.agent-mesh/ 配下のローカルイベントログ（events.jsonl）を追記型（append-only）で残し、ハッシュチェーンで改ざん検知を行う考え方です。
保存
events.jsonl（追記型）
連鎖
ハッシュチェーンで履歴を繋ぐ
狙い
無断編集の“痕跡”を見つける
Distinction
10 / 16
担保できる/できない
改ざん検知は別物
ハッシュチェーンは“改ざん検知”であり、暗号による秘匿や強い本人性の証明とは別問題です。 監査用途では、担保範囲を理解して運用前提を整える必要があります。
できる
無断編集の“痕跡”検知（tamper-evidence）
できない
秘匿（encryption）や本人性（strong identity）的保証
Comparison
11 / 16
チャットは補助、Meshは基盤
置き換えではない
Agent Meshはチャットの代わりではありません。通常の会話は会話として残し、必要になったときだけ「依頼・決定・結果」を耐久的履歴に昇格させます。
視点 チャット Agent Mesh
役割 作業の対話 決定と成果物の履歴化
境界 チャット単位で文脈が区切れやすい REQ/RES/Decisions/バックログで跨ぐ
統制 承認が見えにくいことがある 人間の承認点が確定する
Cautions
12 / 16
Pre-1.0の注意点
導入は運用込みで
参照（IDリンク）検証や契約（managed repository contract）は“万能自動強制”ではなく、運用・導入設定次第です。 また、Pre-1.0で契約や仕様が変わり得ます。
i. 仕様
Pre-1.0：将来変更の可能性あり
ii. 検証
IDリンク整合の強制は運用依存
iii. 監査
改ざん検知＝本人性/秘匿の保証ではない
iv. 情報衛生
自動レダクション（赤除・削除）方針なし：入力に注意
Closing
13 / 16
まとめ：再現性×追跡性
Human + History
Agent Meshは、AI開発の再現性・追跡可能性を高めつつ、人間の承認を中心に安全に進めるための設計です。 チャット分散を減らし、決定を確定させるまでを“耐久的履歴”に閉じます。
要点 1
Workbenchで状態と承認点を可視化
要点 2
Decisionsは承認済み改訂版だけが有効
要点 3
local-onlyが基本、監査は運用前提で
