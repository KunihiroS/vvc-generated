02 / 16
Gitで規約を配る

Norms

AIコーディングエージェントが守る「チームの規約（norms）」を、リポジトリで一元管理し、生成物へ自動同期します。
/ ノームズ：規約の再利用可能な指示
PROBLEM
03 / 16
指示が散らかる
散在するルール
AIへの“指示”はドキュメントに散らばりがちで、更新が追いにくく、エージェント側の参照も揺れます。
/ 結果：統一性と再現性が落ちる
痛み
属人的な指示が増殖する
痛み
最新化（更新反映）が漏れる
METAPHOR
04 / 16
ソース・オブ・トゥルース
規約は部品
Normsは、規約を文章ではなく「Gitで管理される部品」にして、必要な形へ展開できるようにします。
/ Source of Truth（単一の真実）
入力
.norms/ 配下の Markdown
出力
AGENTS.md / Claude / Cursor / Copilot 用
ARCHITECTURE
05 / 16
変換と展開
syncで揃える
`.norms/` を「規約の本体」とし、`norms sync` がエージェント向けファイルへ変換・同期します。
場所
.norms/norms/（norms 定義）
生成物例
AGENTS.md / CLAUDE.md / norms.mdc / copilot-instructions.md
ENUMERATION
06 / 16
normの要素
id と scope
各 norm は安定した `id` を持ち、`applies_to` で適用範囲（例：`packages/**`）を決めます。
i
id：変更に強い識別子
ii
applies_to：対象パスで適用決定
PROCESS
07 / 16
導入は3手
init → propose → sync
まず `norms init`。その後、規約を「追加・更新」→ `norms sync` でエージェント向けに反映します。
i
norms init
ii
norms propose
iii
norms sync
補足
norms は Markdownなので手編集も可能

09 / 16
編集ルール
.norms を直す
生成アダプタは編集せず `.norms/` 側を編集する前提です。`norms sync` により復元・更新され、上書きの可能性があります。
推奨
source：.norms/ を更新
注意
generated：出力は同期で更新される
COMPARISON
10 / 16
属人指示 vs 規約
更新の透明性
Normsは「規約をGitで管理」することで、変更履歴を追跡し、エージェントへの反映を自動化しやすくします。
従来

Git履歴 + 自動生成で再現性が上がる
DISTINCTION
11 / 16
検証の導線
explain と lint
`norms explain` と `norms lint` により、スコープ一致や宣言されたコンフリクトを説明・検証できます。
explain
「どのnormが効くか」を確認
lint
適用・衝突のリスクを検出
EVIDENCE
12 / 16
懸念点も明確に
優先度が鍵
入力情報だけでは「衝突時にどちらが勝つか」「優先度の仕様」が十分に示されておらず、normが増えるほど理解が難しくなる可能性があります。
/ だからこそ explain / lint が重要
不明
衝突解決の優先度ルール
負荷
規約数増でレビュー/運用コスト増

13 / 16
結論
ガバナンスを自動化
Normsは「AIに渡すルールの統治」をGitと同期で支え、規約の統一・最新化・検証可能性を高めます。
