Discovery tax を断つ

発見税を MCP でゼロにする

AIエージェントが毎回「README探し→試行→当てる」を繰り返すコストを、MCP（Model Context Protocol）とツール登録で減らす考え方です。
キーワード
Discovery tax（発見税）/ MCP / Runfile
狙い
探索の削減＝トークン/実行回数/品質揺れを抑制
PROBLEM
03 / 16
毎回、初手から探す

発見税とは

セッション開始時に、AIが README や Makefile / package.json を読んで「テストの実行方法」を探し直す無駄が Discovery tax です。
無駄1
トークン消費
無駄2
誤った試行（例：make test→失敗）
無駄3
会話の品質低下（自信の揺れ）
bilingual: Discovery tax（発見税）＝「当てにいく探索コスト」
EVIDENCE
04 / 16
“失敗が残る”が痛い

探索は損失を複製する

誤った実行とエラー文が文脈に残り、次の回答が慎重になったりトーンが落ちて、最終的な出力が鈍る可能性があります。
コスト面
トークン枠・ツール呼び出し回数が増える
品質面
失敗履歴→自信低下→対話テンポ/精度が揺れる
単なる「費用」ではなく「信頼性の低下」を含む点が本質
METAPHOR
05 / 16
探すから、使うへ

カタログで決め打ち

MCPはツール情報（名前・説明・引数の型など）を構造化して渡し、「探す」代わりに「選べる」状態を作ります。
従来
README/Makefile を読み、推測して試す
MCP
ツール台帳から最短ルートで呼び出す
bilingual: MCP（モデル文脈プロトコル）で「機械可読な入口」を用意する
ARCHITECTURE
06 / 16
Runfile＋MCPサーバ

登録で前処理

タスク（例：test、deploy）を Runfile に定義し、MCPサーバ経由で AI にツール登録します。
入力側
Runfile: test / deploy を宣言
提供側
MCPサーバでツール名・説明・引数型を公開
結果：エージェントは「ファイル探索」から「ツール呼び出し」へ移行
PROCESS
07 / 16
初動を1回にする

runで揃える

セッションを跨いでも、エージェントは同じ「run → test」相当のツールを呼ぶだけで済み、探索の分岐が消えます。
i
ツール一覧を参照（探索しない）
ii
必要なタスクだけ1回呼び出し
iii
以降の再現性が上がる
bilingual: 再現性（reproducibility）＝手順がぶれにくい状態
COMPARISON
08 / 16
数字は“比較”の形

削減の目安

提示例では、従来は約6回のツール呼び出しと約2,500トークン消費、MCP利用は約1回と約100トークン消費です。
従来
約6回 / 約2,500 tokens
MCP
約1回 / 約100 tokens
“Discovery tax”が探索回数と文脈消費に直結する、という読み
DISTINCTION
09 / 16
ゼロの意味を絞る

“ゼロ”は探索部分

本文の強い言い方「発見税はゼロ」は、主に“探索による無駄”が減ることを指します。
減るもの
README探し・推測・誤コマンド試行
増え得るもの
Runfile / MCPサーバの整備・保守コスト
探索コストを“設計コスト”へ置換する理解が安全
DISTINCTION
10 / 16
効果の前提が必要

定量の条件不明

約6回→1回、2,500→100トークンの比較は状況依存で、対象プロジェクトの規模や README の明確さなどが不明です。
必要条件
エージェント仕様・バージョン
必要条件
リポジトリ構造（README/Makefile品質）
必要条件
MCPツール記述の粒度
一般化して断定する前に、少量計測で確認すべき
EVALUABLE
11 / 16
導入時の論点セット

検討すべき4点

MCPで“使う”へ移す設計思想は合理的ですが、効果検証と安全設計がセットになります。
技術
推論負荷/誤コマンド選択を減らす
安全
権限・ネットワーク・隔離（sandboxing）の設計が必要
運用
Runfile更新とタスク整合性で再現性を維持
投資対効果
探索削減 vs 登録/保守コストの見合い
bilingual: 安全性（safety）/ 再現性（reproducibility）を同時に担保
CLOSING
12 / 16
結論：探索を設計に変える

“毎回探さない”

AIに毎回「読む→当てる」をさせず、MCP＋Runfileで“最初から使える形”に整備すれば、待ち時間とコスト、品質の揺れを減らせます。
やること
タスクを Runfile 定義→MCPでツール登録
確認すること
自分のリポジトリでツール呼び出し/トークン/失敗要因を計測
“ゼロ”は探索の話。導入後の保守と安全は別途必要

参考（概念）

本スライドはユーザー提供要約に基づくため、下は関連概念の参照先（MCP/ツール登録）です。
MCP
Model Context Protocol（ホスト/クライアント/サーバ、ツール一覧の提供などの概念）
JSON-RPC
MCP 通信の基盤として述べられることが多い（リクエスト/レスポンスのやり取り）
ツール登録（タスクランナー）
Runfile 等で定型コマンドを宣言し、MCPサーバで構造化して公開する発想
sandboxing
AIがコマンド実行する場合の隔離・権限制御（安全設計の一般論）
必要なら：あなたのプロジェクト（言語/テストコマンド/CI/Makefile有無）に合わせて Runfile 粒度を提案できます
