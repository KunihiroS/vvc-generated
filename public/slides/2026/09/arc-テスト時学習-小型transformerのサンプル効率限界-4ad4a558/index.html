サンプル効率の限界

Test-time Training ARC

入力グリッド→出力グリッドを解くARCで、小型Transformerを「評価中にも学習させる」設計により、少数例での高スコアを狙う取り組みです（効率の検証が主目的）。

Idea / 要点
evalタスク側の学習更新で推定精度を押し上げる
Why / 目的
「損失」だけでなく「少数サンプルでどこまで行けるか」を測る
注：本スライドはユーザー提示の要約・論点を読みやすく再構成したものです。
Problem
03 / 16
ARCは少数推論

メタラーニング 試験

ARCは各パズルでルールが変わるため、trainでは得た仕組みから少数の例で新ルールを推定する力（meta-learning）が問われます。

Train / 学習
正解ラベルが見える例でルール推定能力を獲得
Eval / 評価
正解ラベルが隠され、推定が必要
Key / 焦点
サンプル効率：少数で高精度に到達できるか
Approach
04 / 16
情報を列に変換

Grid → Token 列

入力出力グリッドをトークン列に変換し、小型Transformerで「タスク条件つきに変換規則」を学習・推定します。

表現 / Encoding
クロスタスク学習のためのタスク埋め込み + 3D RoPE
学習 / Learning
evalパズルのtrain側相当を用いてテスト時に重み更新
bilingual：サンプル効率（Sample efficiency）= 少数サンプルで性能を出すこと。
Result

低コストで高得点

ARC-1 / ARC-2 得点

Transformerを小規模に訓練し、テスト時学習を入れることで、ARC-1文脈で約44%前後、さらにARC-2で約7%を達成したと報告されています。

ARC-1
~44%（ARC-AGI文脈のスコア帯）
ARC-2
~7%
精密な評価条件（提出手順・推論の扱い）は再現で必須です。
Architecture

Transformerを近代化

設計の改善点 連鎖

ベースライン改善は複数要素の積み上げで、Transformer近代化・データ多様性・層数増に加え、特に効率面で拡張回数を減らす方向が強調されています。

Modernize
SwiGLU、RMSNorm
Data
多様性・シャッフル改善、拡張/コスト調整
Capacity
層数増 + （効率のため）拡張回数を削減
Key Change
07 / 16
出力のみ損失

Input損失を 外す

大きな変更として「入力トークンは学習対象から外し、出力トークンの損失だけで学習」する方針が採用されたとされます。

Before
入力も損失に含む学習
After
出力損失のみ（実質的に教師あり寄り）
報告では入力を外してスコアが上がる一方、テスト損失は悪化する挙動があるとされています。
Evidence
08 / 16
表現が効く

3D RoPE と タスク埋め込み

アブレーションでは、3D RoPEやタスク埋め込みを外すとスコアが大きく落ちる一方、保持することで高いベースラインが得られたと報告されています。

Keep
3D RoPE + per-task埋め込みで性能維持/向上
Remove
これらの除去で大幅ダウン（重要な表現設計）
Data / Aug
09 / 16
対称性で拡張

色・回転の 整合

推論時の対称性（色やダイヘドラル変換）に対応するデータ拡張・逆変換を組み込み、誤差を抑えながら候補生成を安定化させる狙いがあります。

Aug
色変換
Aug
ダイヘドラル変換（回転・反転等）
Map Back
逆拡張（候補を元の座標系へ）
拡張回数の増減は計算コストにも直結します（サンプル効率の論点）。
Controversy
10 / 16
損失とスコアがズレる

Loss逆相関 の謎

出力損失のみへ変更したことで、テスト損失は悪化したのにスコアが上がる現象が報告されています。

観測
テスト損失↑…でもスコア↑
示唆
「損失＝汎化性能」単純対応ではない可能性
成功/失敗モードの内訳など、追加解析が必要という論点が提示されています。
Risk
11 / 16
リークが致命傷

ARC-2重複 フィルタ

ARC-2にはARC-1の重複が含まれるため、無防備に学習へ混ぜると記憶でスコアが出てしまうリスクがあります。

問題
同一/類似タスクが学習側に混ざる可能性
対策
重複773パズルを慎重に除外（と説明）
再現では「除外手順の透明性」と「更新に使う範囲」が信頼性の鍵です。
Interpretation
12 / 16
許容範囲の解釈

Test-time training 是非

テスト時学習は「テストの正解ラベルを事前に知る」ことを禁止する競技趣旨との境界が焦点になります。

主張（要旨）
隠された出力ラベルは学習に使っていない
注意点
実装が「どの情報で更新したか」を確認する必要
情報流（何が見えて何が更新に使われるか）が再現・評価の根幹です。
Closing
