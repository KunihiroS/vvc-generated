01 / 15
メールでローカル実行
Dear Machine × Machtiani
GmailなどのメールでPCへ指示し、ローカルでAIエージェントを動かすための「クライアント＋実行管理（ハーネス）」の考え方をまとめます。
Local-first（ローカル優先）とgitベース記憶が核です。
problem
02 / 15
常時起動が要る？
操作UIを外へ
開発や調査では、PCを常に開いて指示するのが面倒になりがちです。
そこで「メール」を操作UIにして、遠隔でもローカル実行を継続する設計が狙いです。
（例：スマホからタスク指示 → 結果は同じスレッドで追跡）
architecture
03 / 15
二層構造
Client と Harness
Dear Machineが「メール↔PC」を仲介し、Machtianiが「長時間セッションと反復実行」を扱う下層ハーネスになります。
これにより、同じメール会話（スレッド）を進行の単位にできます。
Dear Machine
メール受信でローカル側タスクを起動し、結果を同じ会話として返す
Local client（ローカルクライアント）
Machtiani
長時間セッション／iteration（反復）／並行スレッドを「実行管理」する
Execution harness（実行ハーネス）
metaphor
04 / 15
講師とワーカー
軽い制御
巨大な1つの制御ループではなく、instructor（講師）とReActワーカーを階層的・非対称に配置します。
講師は文脈継続に集中し、ワーカーが重い実行（ツール呼び出し等）を引き受ける想定です。
flow
05 / 15
ReAct の責務分離
実行を切る
ワーカー側は隔離された継続として動き、結果だけが講師側へ戻る流れが描かれています。
「制御」と「実行」を分けることで、履歴やツール呼び出しの混線を減らす狙いです。
i
講師が文脈を継続
ii
ワーカーがツール操作
iii
結果のみを返す
sessions
06 / 15
メール＝スレッド
Threads/Sessions
「Threads and sessions are the same thing」と読める運用思想により、メールスレッドが進行単位になります。
これにより、タスクの継続・追跡が自然になります。
継続性
同じ会話でゴールや状況を引き継ぐ
追跡性
進捗・結果がスレッド履歴として残る
memory
07 / 15
クラウド無し
git ベース記憶
メモリは「ローカル、非クラウドベース」で、gitを活用する方針が示されています。
ローカル主導で履歴管理し、開発用途に相性が良い方向です。
期待できる価値
データ主権・継続性・差分追跡
不足情報
何を／どの粒度で保存し、削除・秘匿をどうするか
parallel
08 / 15
並行スレッド
複数実行
目的の異なる検討を同時に進めるため、複数スレッドを走らせられる想定です。
さらに講師・ワーカー・バックエンドが独立したモデル設定を持ち得る点も読み取れます。
要素 読み取れる設計
単位 メールスレッド＝セッション
並行性 スレッド単位で独立に反復・継続
モデル選択 エージェントごとに設定（例：バックエンドの選択）
safety
09 / 15
“標準”が鍵
サンドボックス注意
安全分離（サンドボックス付き）にはアダプタ作成が必要になり得ます。
標準アダプタはサンドボックスを持たない可能性がある、という注意が明示されています。
安心に必要
最小権限・隔離・監査（ログ）・承認フロー
未確定
隔離の範囲、失敗復旧、権限逸脱リスクの具体
examples

現場で使う
メール運用の例
「メールで投げる」「端末を開いていなくても進む」「外出時にスマホで指示」といった運用が想定されています。
また、ターミナルの watch運用（例：`--attach`）の言及があり、参加者がイメージしやすい構成です。
mobile

attach

導入判断
段階的に
強みは「メールを操作UIにして、ローカルで長時間実行を回す」ことです。
ただし、セキュリティ（サンドボックス／権限／ログ）と、gitメモリの保存設計は追加確認が必須です。
最初の一歩
ローカルで低リスクに試す／メール本文を制限
確認ポイント
アダプタの隔離・最小権限・監査ログ・削除/秘匿
