次は“出来の良し悪し”

Sloppiness

LLMがコード生成で「解ける」ようになった後、問題になるのは“動くか”ではなく“無駄や複雑さがどれだけ混ざっているか”です。ここでの焦点はずさんさ（sloppiness）を測る試みです。

Bilingual: sloppiness（ずさんさ／無駄の多さ）

テスト通過

隠れテストでの検証が効くため、LLMは形式的に正しいコードを大量に出しやすいです。しかし“読めない・直せない”という実害は、テストだけでは見えにくいのが問題です。

04 / 18
何が“ずさん”か

無駄と偏り

sloppinessは「コンパイルやテストが通るか」から切り離し、運用・保守を難しくする要因として捉えます。具体的には重複、過剰な抽象化、冗長な記述、複雑さの偏りなどです。

重複（クローン / 同種処理の増殖）
冗長（必要以上の記述・手続き）
抽象化過多（意図が見えにくい）
複雑さ偏り（一部関数に負荷集中）
保守困難（読み直し・修正が増える）
判断依存（tasteが絡む領域）
Bilingual: sloppiness（ずさんさ） / taste（審美眼）

Judge

LLMに採点させる「AI as a judge」は、単純な1〜10スコアだとランダム性に近くなり得ます。A/B比較でも、出力の見せ方や命名の揺れで嗜好が変動し得る点が危険です。

単純スコア

Implication: 評価としての代替になりにくい

測り方を比較

3軸

コード品質の評価手段を、(1) AI審判、(2) 人間審査、(3) LOCなどの単純指標として比較します。LOCは有望な手がかりにもなる一方、最適化で指標が壊れる危険があります。

① AI審判（judge）
② 人間審査（taste依存）
③ LOC（代理指標の罠）
One slide one message: LOC “危険”の要点を先に置く

SlopCodeBench

測定設計

SlopCodeBenchは、sloppinessを2つの指標に分解して捉えます。中心はVerbosity（冗長性）とErosion（複雑関数への侵食／質量集中）です。

Verbosity
冗長になりやすい行の割合
Erosion
複雑関数へ質量が集中する度合い
Bilingual: Verbosity（冗長性） / Erosion（侵食）
evidence

計測の結果

約2倍

報告値では、エージェント生成コードは既存リポジトリよりVerbosityとErosionが大きい傾向が示されます。数値例：冗長性0.33 vs 0.15、侵食0.68 vs 0.31です。

Agent 0.33 / Repo 0.15
Erosion

Takeaway: LOCより“形の違い”を拾う

なぜLOCでない？

形の指標

VerbosityとErosionは、単なる行数依存ではなく、コードの“性質”に寄せた代理指標です。LOC最適化のゲーム化を避ける方向に意味があります。

Verbosity
AST-Grep検出行＋クローン行の比率
Erosion
循環的複雑度が高い関数へ“質量”集中
Bilingual: AST-Grep（静的パターン検出） / cyclomatic complexity（循環的複雑度）

反復の現実を再現

チェックポイント

SlopCodeBenchの評価設計は、反復・コンテキスト消失を模倣します。複数ラウンドの間にチェックポイントでコンテキストを消すことで、人がエージェントを使う“蓄積”の失敗に近づけています。

複数ラウンドで指示＋テスト
中間でコンテキストを消去
悪い判断が積み上がる
One message: “蓄積する失敗”が見える設計

厳格条件が崩れる

0%警告

全チェックポイントで全テスト通過という厳格条件では、最先端でも0%になる可能性があると警告されます。ここが“積み上がり現象”のサインです。

意味

評価の限界

全部は測れない

一方で、sloppinessの“すべて”はこの2指標だけでは測れない可能性があります。依存関係の複雑化、設計意図の欠如、命名・抽象化の適否、ドメイン整合性などは未捕捉になり得ます。

Erosionの副作用

性能領域

Erosionは循環的複雑度に強く依存するため、アルゴリズム的に複雑な関数が必要な領域では高評価になりにくい可能性があります。性能要求が高い処理は、必然的に“複雑”になり得ます。

想定リスク
必要な複雑さでも“侵食”扱い
例示
性能要求の高い処理
Implication: 指標は文脈付きで解釈が必要

結論

測り方が勝負

sloppinessはtasteが絡むため、完全自動評価・完全自動改善で置き換えるのは簡単ではありません。だからこそ、測定設計を工夫し続ける必要があります。

要点
“正しさ”と“ずさんさ”を分けて測る
警告
反復で判断が蓄積し、合格率が崩れる
