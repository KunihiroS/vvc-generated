ブラウザでレビュー起動
trynix-preview

GitHub ActionsでPRのNix成果物（/nix/store）を“リンク経由で起動”し、レビュー体験を速くする実用化の話です。

problem
03 / 16
CIは“読む”中心
体験のズレ

従来のCIはテスト結果をログで返すことが多く、成果物の準備や実行環境の用意が必要で“確かめるまで”が遠くなりがちです。

Before
ログ確認 → 成果物取得 → 実行環境準備
レビューの手戻りが増える
Goal
リンクを押すだけで“起動して確認”
実行可能なフィードバックへ
architecture
04 / 16
Actionは“準備係”ではない
責務分離

trynix-previewはビルドやキャッシュ提供をしません。すでに存在するNixストアパスをPRに提示し、ブラウザが参照できる形へ導きます。

trynix-preview の役割
評価相当 → ストアパス解決 → PRコメント（起動リンク）
外部が担う前提
Nix成果物の生成 → Cachix等でキャッシュへ投入（成果物が既にある）
レビュー担当者
PRを触らずリンククリックで“起動”して検証
キモ（条件）
キャッシュに対象の/nix/storeパスが存在すること
metaphor
05 / 16
リンクは“部品の住所”
/nix/store

成果物を“実行ファイル”ではなく“アドレス（/nix/storeパス）”として扱うため、同じ内容なら同じ到達先に寄せられます。

Nixの考え方
内容依存で成果物が参照可能
再現性ある到達先
レビューへの効果
PR固有の成果物を“リンクで呼び出す”
動作確認へ最短ルート
process
06 / 16
実運用の流れ（概要）
3ステップ

ポイントは“いつものCI”とは違い、Actionはリンク生成に徹することです。全体は短いループになります。

i
キャッシュへ積む（Cachix等）
対象の成果物がすでに存在する状態
ii
PRで trynix-preview がストアパスを解決
nix eval相当の考え方で参照先を確定
iii
PRコメントに“起動リンク”を残す
レビュー担当者はクリックで検証
成功条件
参照先がキャッシュにあること
リンク先が“動く”
enumeration

Actionがコメントするもの
起動リンク

トリックは“任意の /nix/store パス”をブラウザの実行環境へ接続する情報として提示する点です。

対象例
. #default に対応する成果物など
記事内の具体例
接続に必要な要素
キャッシュのURL / 公開鍵など
ブラウザ側が参照できるため
comparison
08 / 16
“リンクで起動”の価値
検証が近い

ログ読解から“実行確認”へ寄ることで、レビューの距離が縮みます。特に再現性が高い成果物ほど効果が出ます。

従来
CIログ中心（読む負荷）
実行には追加の手順
trynix-preview

レビュー体験を実行へ変換

09 / 16
万能ではない：性能
起動1〜2分

大きなバイナリでは起動に1〜2分かかることがあるため、主要テスト基盤として“置換”するのは難しいと整理されています。

向く
小〜中規模のバイナリ / レビュー段階の素早い検証
フィードバックループ短縮
難しい
巨大成果物の本格的な代替CI
遅延が期待値を超える
distinction
10 / 16
セキュリティ：フォークPR
allow-unsafe

フォーク由来PRを扱う際は、actions/checkout の allow-unsafe-pr-checkout: true のような設定が必要になる点が明示されています。

目的は“安全制約の範囲で実行可能にする”ことですが、運用側で脅威モデルと対策（キャッシュ分離など）を固める必要があります。 Security（安全）: フォークPRは攻撃面が増えやすい
architecture
11 / 16
キャッシュ分離を推奨
混線回避

PRビルド用キャッシュを分離することが推奨され、フォークがメインキャッシュへ書き込むリスクを避ける設計思想が示されています。

推奨
PRビルド用キャッシュを別に持つ
名前空間・運用分離
狙い
メインキャッシュへの不適切な書き込みを防ぐ
利便性とリスクの両立
distinction
12 / 16
導入判断の観点
使い所

性能・前提・安全性の3点で適用範囲が決まります。合うなら“レビュー補助線”として強い武器になります。

前提
成果物がキャッシュに存在する（Action単体では作らない）
性能
1〜2分の起動遅延が許容できる範囲か
安全
フォークPR設定とキャッシュ分離をどう担保するか
結論
“全CI置換”より“レビュー段階の検証強化”向き
closing
13 / 16
結論：レビューを実行へ
次の一手

trynix-previewは、PRに“起動リンク”を残すことで、CIログ中心から実行確認へレビュー体験を前進させます。

まず確かめる
対象のバイナリサイズと起動時間（1〜2分が現実的か）
運用で固める
キャッシュ分離、フォークPRの設定、失敗時の運用方針
（入力データだけでは不足情報がある）
