Project Opal
02 / 16
タスク実行型AI
Opal（オパール）
Microsoft 365 Copilot から起動できる「タスク実行型AI」で、文章生成よりも“手順を進める”ことに寄せた設計です。
整理：狙い／仕組み／利点／注意点
Reading Deck
Problem
03 / 16
“使えるAI”の条件
実務の壁
業務AIには、監査できる証跡・手順の再現性・アクセス制御・人の介入ポイントが必要です。
生成の限界
回答は出ても、実際の申請や証跡収集までは完結しない。
統制の限界
外部サイトへの勝手アクセスや、説明不能な操作はリスクになる。
安心して自動化するための要件
—
Core Idea
04 / 16
キーワードは“実行”
計画→実行
Project Opal は、ユーザーの作業記述を実行計画に変換し、管理された環境で手順を順序立てて進めます。
i. 入力
Copilot 上で作業を記述（シナリオ起動）
ii. 計画
手順を分解し、必要ツールと順序を作成
iii. 実行
専用クラウドPCで操作を行い、観測可能にする
タスクベース設計（手順のある業務向き）
—
Architecture
05 / 16
安全で観測可能
専用Cloud PC
実行は Windows 365 Cloud PC 上で行われ、モデルの判断だけでなく“どこで何をしたか”を追える設計です。
実行環境
Windows 365 Cloud PC（Entra-joined / Intune-enrolled）
操作方法
Edge を使ったコンピュータ操作（Computer-Use）で手順を進行
“管理された実行”が前提
observability
Observability
06 / 16
見える化
Activity
リアルタイムの観測として、アクティビティビューに計画・操作・タイムラインが記録されます。
計画
実行の見取り図（何を順番に行うか）
操作
どのステップで何をしたか
タイムライン
時系列の追跡（監査・振り返り）
“止めて確認できる”設計
pause / handoff
Handoff
07 / 16
人の介入
引き継ぎ
ユーザーは必要に応じて一時停止し、Windows 365 Cloud PC の操作を引き継げると説明されています。
どこで止める
入力が必要なステップで、ブラウザ通知やタイムラインで把握
プライバシー
ユーザーが引き継いでいる間はスクリーンショットを保存しない
“自動”と“管理”の両立
—
Security
08 / 16
デフォルト拒否
Allow list
アクセス制御は allow list による“デフォルト拒否”。実行中に参照できるサイトは組織が許可したドメインに限定されます。
制限
許可されていないサイトはアクセス不可（ナビゲーションが制限）
狙い
データ流出リスクや意図しない外部サイト操作を抑える
勝手さを減らす実務上の要点
access control
Governance
09 / 16
ITが作る“運用”
オプトイン
Project Opal は管理者の設定が前提で、配備はオフから開始・Windows 365 Cloud PC プールや allow list、ガイダンスを整える必要があります。
i. 有効化
オプトイン（管理者が有効化）
ii. 環境
Cloud PC プールの選定・設定
iii. ルール
allow list / シナリオスターター / 組織固有指示
“ツール導入”ではなく“運用設計”
supervisor
Examples
10 / 16
適性が高い領域
反復タスク
例として、証跡収集、申請ワークフロー、HR手続き、オンボーディングのチェックリスト実行などが挙げられています。
監査
コンプライアンス監査の証跡収集
申請
承認が絡むグループ加入申請
人事
勤怠・休暇申請／オンボーディング手続き
手順が明確で反復性が高いほど効果
task-based
Distinction
11 / 16
“生成”との違い
実行寄り
目的は回答作成ではなく、要求を実行計画へ変換し、必要な手順を順序立てて進めることです。
従来（文章中心）
指示・説明はできるが、実システム操作や証跡収集は完結しにくい
Opal（タスク実行）
計画・実行・観測・介入（pause / handoff）まで含めて業務を進める
監査証跡・申請フローの自動化が狙い
—
Cautions
12 / 16
注意は“運用の設計”
導入前提
記事は early で、体験は大幅に変わり得ると明言。制度設計・許可リスト整備・入力情報の取り扱い・ログ監査などが不可欠です。
決めるべきこと
allow list、Cloud PC プール、シナリオスターター、ガイダンス、人の介入ポイント
不確実な点
失敗時の補償や責任分界、ログ保持期間や粒度、コストなどは本文だけでは確定できない
PoC（試験導入）→段階拡張が現実的
early
Closing
13 / 16
結論
段階的に
Opal は「答えるAI」から「手順を進めるAI」へ寄せ、観測可能性・監督・allow list により“業務AIの実務要件”へ正面から対応します。
推奨
可逆性が高い領域から開始
併用
人のレビュー工程＋監査ログ
拡張
PoCで学習しルールを固めて拡大
