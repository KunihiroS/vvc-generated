宇宙で学ぶ・推論する

Suncatcher

Project Suncatcher（プロジェクト・サンサッチャー）は、低地球軌道（LEO）でAI計算（機械学習の推論・学習）を大規模に回すための物理検証を目指す研究計画です。

Bilingual / 概要
Space as a compute base / 宇宙を計算基盤へ
Focus / 焦点
TPU durability · Thermal · Laser links / TPU・熱・レーザー通信
Problem
03 / 16

「計算」は物理に縛られる

宇宙条件

宇宙（特にLEO）は振動・加速度・放射線・温度・真空などが重なり、地上の常識通りに半導体と冷却が動きません。

Vibration / 振動
打上げ由来の揺れ（最大10gの言及）
Radiation / 放射線
bitflipなどの計算エラー影響
Vacuum heat / 真空冷却
対流なし → 放射で熱を捌く設計が必須
Why now
04 / 16

太陽と“耐久”の勝負

LEO

LEOでは日照が長く、太陽光発電が地上より有利になり得ます（記事では最大約8倍の期待）。だからこそ「計算基盤」を現実に近づける検証を始められます。

Power / 電力
長い日照 → 発電面で有利（約8倍の期待）
Reality check / 実データ
できるか否かは推定ではなく軌道実証へ

最初は“動作確認”

TPU in orbit

最初の狙いは、宇宙環境でGoogleのTPUが実際に動作し、耐久性と熱・放射線影響をデータとして取れるかを確認することです。

Launch / 打上げ
Transporter-18に搭載（報道：2026/10/1）
Test / 実データ
振動・加速度・放射線・冷却を観測
Goal / 結論
「成立性」→ 次段の衛星クラスタ設計へ
Evidence
06 / 16

壊れる要因を測る

耐久性

TPUは打上げの振動・加速度と放射線下で、計算エラー（例：bitflip）をどれだけ生むかを、地上試験と軌道での観測で確かめます。

Acceleration / 加速度
最大10g、部品で50〜100gの言及
Radiation / 放射線
UC Davis：Trillium TPUが想定量を上回る耐性（5年ミッション）
Thermal
07 / 16

熱は最大ボトルネック

真空冷却

宇宙は空気の対流がなく、冷却は主にラジエータ等の放射に依存します。AI計算は発熱が大きいため、熱設計の失敗は即故障につながり得ます。

On Earth / 地上
対流で熱が逃げやすい
In Space / 宇宙
対流なし → 放射冷却中心
Approach / 方式
ヒートパイプ＋ラジエータなどを検討
Process
08 / 16

“試して学ぶ”順序

段階検証

一気に完成を狙うのではなく、最初は「何がうまくいき、どこが壊れるか」を特定する学習フェーズにします。

i Start
軌道上でTPU動作・耐久を測定
ii Iterate
熱・放射・故障モードを設計へ反映

衛星クラスタへ：必要条件を詰める

計算には“接続”が要る

Laser links

複数のTPUを衛星群で扱うには、衛星間通信の帯域がボトルネックになります。記事はレーザー通信を想定し、超精密な追尾が鍵だと述べます。

Bandwidth / 帯域
通信が不足すると計算性能が活きない
Precision / 精密追尾
互いに動く中で高精度な向き合わせ

良い点と限界

評価

強みは、耐久性・放射線・冷却・通信を工学課題として分解し、地上試験と軌道実証で確かめる姿勢です。一方で、性能・稼働時間・現実条件での継続運用の定量は不足しています。

Strength / 強み
実データで“仮定”を減らす
Limit / 限界
スケール時の総合ボトルネックは未確定
Closing
13 / 16

道筋は見えた

結論

現時点で言えるのは「宇宙AI計算基盤の道筋（検証項目と課題の種類）が明確になってきた」ということです。経済的・社会的な成立は、追加の定量情報に依存します。

次の問いは一つ：宇宙で取れる成功率と性能が、運用コストに見合う規模まで伸びるか。
