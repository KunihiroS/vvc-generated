WebLLM serverless

WebGPUを使って、LLMの推論をブラウザ側で動かす“実行基盤”です。（WebLLM = ブラウザ内LLM推論エンジン / serverless inference）

PROBLEM
03 / 16
導入は簡単に見えて…

期待差

「サーバ不要」は魅力ですが、実際はモデルDL・端末性能・WebGPU対応が体験を左右します。さらにキャッシュや失敗時設計がないと、滑らかに動きません。

05 / 16
計算はクライアントへ

WebGPU

推論をブラウザ内で実行し、WebGPUで高速化します。モデル/WASM/トークナイザは取得が必要なので、初回ロードが最初の壁になります。

強み（体験）
サーバコスト削減 / ユーザデータを外へ出しにくい
壁（要設計）
WebGPU対応差 / DL待ち / メモリ消費

06 / 16
UXを守る仕組み

Worker

Web Workerで計算を別スレッドに分離し、UIの応答性を保ちます。重い処理をフロントから切り離すのが“動く”より大事です。

Web Worker
計算（推論）をバックグラウンド化 / UIフリーズ回避
Service Worker
再訪時の再取得を抑える / ライフサイクル管理

DISTINCTION
09 / 16
“本当に互換？”

差分あり

APIの“使い方”はOpenAI互換を目指しますが、細部では差があります（例：`model`パラメータの扱い、`CreateMLCEngine(model)` / `engine.reload(model)` など）。

同じ方向
ストリーミング / JSONモードなど周辺概念
確認が必要
バージョン・パラメータで互換性差が出る可能性
EVIDENCE
10 / 16
壊れてない？検知

SRI

config/wasm/tokenizerにハッシュを指定し、不一致ならデフォルトでエラー（または警告）にできます。成果物の改ざんや破損を検知する方向性です。

SRI（Subresource Integrity）：ハッシュ不一致 → エラー/警告
ARCHITECTURE
11 / 16
モデル差し替え

model / model_lib

推論実行に必要なWASMライブラリ（`model_lib`）と、重み・メタデータ（`model`）を分けて差し替え可能にしています。

model_lib
推論実行用WASM（ライブラリ）
model
重み・メタデータのURL（モデル成果物）

ただし互換性（model_libがモデルに対応しているか等）は利用側の検証が必要です。
