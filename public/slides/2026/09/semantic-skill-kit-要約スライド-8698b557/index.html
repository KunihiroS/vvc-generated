Semantic Skill Kit
02 / 16
知識を「スキル」に

生成する 汎用

Semantic Skill Kitは、Markdown知識ベースから「トピック別のエージェント用スキル」を自動生成するためのフレームワークです。検索と参照の方式を semantic / routed から選べるのが核です。

03 / 16
読ませ方が難しい

知識を 再利用 したい

エージェントにとって、関連するガイドへ誘導して「必要な本文だけ」を参照させることが難題になります。更新・運用も含め、混ざらない設計が重要です。

04 / 16
ビルドと実行を分離

build / watch / export

知識ベース更新（build/watch）と、エージェントの利用（search/retrieve、または生成済みSKILL利用）を分けます。これにより、バージョン混合のリスクを下げます。

運用
search → retrieve（本文取得）
生成
build / watch（整合性重視）
配布
export（再利用可能スナップショット）
安全策
失敗時は部分公開を防止
コア
05 / 16
2つの探し方

semantic と routed

semanticは意味検索で関連チャンクを絞り込み、routedはLLMでタスク向けのルーティング索引を生成します。どちらも「参照」に重点があります。

semantic
ローカル埋め込み（例：MiniLM）+ 類似度検索
routed
ベクトル化しない / LLM APIで導線ツリー生成
比較
06 / 16
コストと制約が違う

選び分けの軸

semanticはGPUやAPIキー不要でローカル完結。routedはビルド時にLLM API課金が起こり得ます。運用要件に応じて使い分けます。

実行時API
semantic：不要（ローカル検索）
ビルド時API
routed：exportで発生し得る
必要環境
semantic：埋め込み実行（例：Transformers.js/ONNX）
生成物
routed：参照Markdown中心（インデックス/カタログ）
semantic
07 / 16
意味で絞る

ローカル 検索

semanticはMarkdownを見出し構造でチャンク化し、ローカル埋め込みでベクトル化します。類似度で関連文書候補を絞り、必要なガイド本文を参照用に返します。

1 i.
Markdownチャンク化
2 ii.
ローカル埋め込み生成
3 iii.
類似度で絞り込み

補足：searchはメタデータ（ランキング）だけを返し、本文はretrieveで取得します。

routed
08 / 16
導線を作る

LLM で ルーティング

routedはベクトル検索や埋め込みモデルを使わず、LLM APIで「どのセクションがどんなユーザタスクに関係するか」を案内ツリー/索引として生成します。運用は参照とインデックス中心です。

生成時
導線ツリー / ページ索引をビルド
実行時
参照用Markdownとカタログを使用

例：export --mode routed は、ルーティング生成のためのコストが発生し得ます。

運用
09 / 16
壊れない工夫

atomic と watch

watchは安定性条件を満たすと再ビルドします。ビルド失敗時は部分スキルを公開しないなど、整合性の保護が設計されています。

watch
一定の安定性 → 再ビルド
整合性
検索/推論中の変更はスナップショット公開を見送り
失敗時
ビルド失敗 → 部分公開しない
差分更新
incremental rebuild（変更があれば差分のみ更新）

キャッシュの扱い

routing-cache と offline

routedビルドでは応答が routing-cache に保存され、--offline はキャッシュのみでビルドします。キャッシュは知識ベースデータとして扱うべき、とされています。

--offline
キャッシュ前提で再生成
注意
キャッシュ内容が出力品質に影響
注意
11 / 16
品質は検証が必要

モデル依存の 不確実性

semanticの類似度閾値（例：0.3）やチャンク設定はドメイン依存です。routedのルーティング生成もモデル品質に依存するため、誤誘導率や正確性は事前評価が必須です。

semantic
類似度閾値（例：0.3）調整が必要
routed
ルーティング事実性はモデル依存
検証
代表質問セットで回帰テスト
互換性
プラットフォーム参照の保証は限定的
FAQ
12 / 16
よくある誤解

答えは 2モード

semanticとroutedは「検索の仕方」と「生成の責務」が異なります。代表的な疑問を短く整理します。

Q i. semanticとrouted
semantic：類似チャンク本文参照 / routed：LLMで導線索引生成
Q ii. routedで検索は?
ベクトル検索を作らない方針（MiniLMロードもしない）
Q iii. 課金タイミング
routedの生成（export --mode routed）で発生し得る
Q iv. search vs retrieve
searchはメタデータ、本文はretrieveで取得
結論
13 / 16
使うなら設計と検証

強みは 分離 と 統制

Semantic Skill Kitは、build/watch/exportで段階分離し、routedでは実行時APIを前提にしない方針が強みです。運用では、キャッシュ管理・閾値調整・代表質問での品質検証までセットで評価するのが現実解です。

まず
semantic / routedの目的を明確化（コスト/制約）
次に
代表質問セットで回帰テスト（誤誘導・正確性）
