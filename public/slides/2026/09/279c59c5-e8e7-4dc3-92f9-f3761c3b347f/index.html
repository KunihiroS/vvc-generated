04 / 16
エージェント運用

ハーネス＝枠組み

ハーネスは、LLMがターンごとに入力・出力する手順や状態の持ち越し方を定める「運用ルール」です。

Standard harness
内部推論の引き継ぎをリクエスト間で保持せず、コンテキスト超過時は単純な切り捨て（rolling truncation）になりやすい。
Provider Adapter
推論保持＋文脈圧縮（compaction）を“実行ループ”に組み込み、要点を次ターンへ継続。
狙い
長い探索で「理解の土台」が崩れず、無駄なやり直しを減らす。

Distinction
06 / 16
何が違う？

鍵は 保持 と 圧縮

特化ハーネスは新アルゴリズムというより、次ターンへの「推論保持（reasoning retention）」と「文脈圧縮（compaction）」の設計だと説明されています。

推論保持 / Reasoning retention
前回までの思考過程や要点が、リクエストをまたいで引き継がれる。
文脈圧縮 / Compaction
長時間探索でも要点を要約として残し、コンテキスト喪失を抑える。
Process
07 / 16
失敗の反復

Standard は やり直し に寄る

Standard harnessでは、推論が保持されにくく、コンテキスト超過時に古い情報が切られやすいため、毎ターンほぼ“再開始”になりがちです。

状態
ターン間で内部推論が引き継がれにくい
喪失
rolling truncationで過去が失われる
結果
同じ失敗を繰り返す／長期理解が薄まる
Process
08 / 16
改善の流れ

Provider は 継続 を作る

Provider Adapter harnessは、実行ループで推論保持とcompactionを組み込み、長い探索でも土台が崩れにくい状態を目指します。

1
前回の推論（要点）を次ターンへ保持
2
探索が長くなるほど圧縮で保持情報を整理
3
失敗の修正が積み上がり、手数が減る

正解率だけじゃない

ARC-AGI-3は正解率だけでなく、「到達までの少ない手数」（人間中央値との相対効率）も反映します。

Accuracy

10 / 16
価値の焦点

改善は 長期一貫性 に直結

推論が捨てられると同じ罠に落ちやすい一方、保持されれば「前回の失敗を踏まえた修正」が可能になり、探索効率が上がります。

破棄型 / Drop
失敗の再利用ができず、同種エラーを繰り返す。
保持型 / Retain
方針や修正を積み上げ、到達までの手数が減る。

誤解の回避

99.9% ＝AGI証明ではない

99.9%はARC-AGI-3という閉じた2Dパズル条件での精度・効率であり、現実のオープンエンド問題への同等汎化を示すものではありません。

ARC-AGI-3 の性質
閉じたゲーム環境（決定論的・ルール学習なしの前提）
外挿の注意
現実は非決定的で、観測・目標・制約が多様—別検証が必要
Skepticism

透明性の穴

opaque な 推論状態

Provider Adapter harnessは推論状態をopaqueに扱い得るため、同条件再現や第三者検証の難しさが残る可能性があります。

再現で不足し得る点
保持対象の粒度、保持形式、compactionの要約規則、失効条件
論点

まとめ

結論：モデル＋ハーネス

ARC-AGI-3の「99.9%」は、モデル性能単独では説明しにくく、推論保持と文脈圧縮を含む特化ハーネスが長期タスクの一貫性と効率を押し上げた、と読むのが中心です。

Core message
評価は“モデル”だけでなく“実行環境設計”まで因果分解する。
Boundary
閉じた2Dパズル指標であり、汎用知能の到達証明ではない。
