Governance patterns
02 / 16
ガバナンスを「実行」へ
AIエージェント統治：実行可能パターン
理念やドキュメントではなく、システムが判断できるルール（decision table/DMN）としてガバナンスを提供します。
Open-source “3点セット” / MIT / runtime enforcement の上位に置く発想
Problem
03 / 16
空白は「判断」側
配管 vs 意思決定
アクセス制御・サンドボックス・監査・コスト管理などの配管は土台ですが、「正しい判断条件」を自動化しきれないことが多いです。
配管（plumbing）
本人確認、隔離（sandboxing）、ポリシー執行、ログ、など
空白（governance decision）
所有者は妥当か／いつ遮断するか／棚卸しはいつ必要か
Metaphor
04 / 16
ルールがチェッカーになる
DMN＝判断の 地図
DMN（decision table）は、入力の組合せごとに出力（承認/遮断/照合実行…）を決め、解釈ブレを減らします。
入力（条件） ロジック（表） 出力（決定）
ID整合性、コスト指標、在庫の有無… トリガー＋判定＋根拠（provenance） 承認／遮断／照合サイクル起動
Architecture
05 / 16
オープン・ガバナンス・パターン
3点セット + 実装テンプレ
意思決定テーブルだけでなく、トリガー条件・根拠（provenance）・隣接パターンとの関係まで整理し、「完全なパターン」として提供します。
Decision table / DMN
入力組合せ→挙動を定義し、テスト前提で設計
Provenance
判断の根拠を追跡できるように含める
agent365-template
Microsoft Agent 365向けテンプレ（agent365-template.json）
Core
06 / 16
中核リスクを3つで
ID・コスト・在庫
統治の現実的な論点として、(1) 所有者整合性、(2) コスト急増への遮断、(3) 未登録エージェント見落としを扱います。
i. ID整合性
エージェントIDの所有者とスポンサー割当の整合性
ii. コスト遮断
予算上限・ブレーカー（遮断）判断
iii. 在庫照合
存在確認できないエージェントを見落とさない周期
Evidence
07 / 16
「読むだけ」を終わらせる
decision-tableで強制
ガイドラインではなく、decision-table.dmnとして入力量と出力を対応づけ、運用者がシステム判断へ組み込みやすくします。
テスト前提
「すべての入力組合せでテスト」という設計思想
判断の明確化
入力漏れ・曖昧な解釈を減らし、監査にも寄与
Distinction
08 / 16
配管の上に載る
Runtime enforcementの 上位
本パターン群は、ランタイム強制（runtime enforcement）が既にある場合、その上に置く「ガバナンス決定ルール」として位置づけられています。
レイヤ 役割
Runtime enforcement（執行） ポリシーや安全機構を実行して事故を防ぐ
Governance decision（判断） いつ/何を/どの根拠で承認・遮断・照合するかを決める
Process
09 / 16
導入時に必要な順
あなたの指標へ 翻訳
そのまま使うのではなく、自組織のID基盤・コスト指標・イベントに合わせて、入力データと例外を設計します。
i. トリガー
どのイベントで意思決定を起動するか
ii. データ
所有者、スポンサー、コスト、在庫状態を何で表すか
iii. 境界
失敗時・例外時の扱いをどうするか（監査含む）
Comparison
10 / 16
ドキュメント偏重から脱出
「判断」まで落とす
多くのガバナンス情報が配管や理念に偏りがちな一方、ここは“チェックすべき質問”を決定ルールとして提供します。
偏りがちな形
監査手順やガイドライン中心（実行条件が曖昧）
本パターン
質問→トリガー→decision table/DMN→出力（強制しやすい）
Risk Focus
11 / 16
運用で破綻しやすい
ID / コスト / sprawl
権限不整合、予算超過、未登録エージェント（sprawl）の見落としは、事故や統治不能に直結します。
ID整合性
誤権限や説明責任の欠落を招く
コスト遮断
暴走を止める閾値と意思決定が鍵
在庫照合
見えない存在を減らし統治不能を防ぐ（sprawl）
Limitations
12 / 16
完璧ではない
検証が必須
現状有姿（As-is）でサポートなしの前提で、抜粋だけではデータスキーマや監査ログ要件の詳細が不明です。
前提が必要
ランタイム強制が成熟しているほど効果が出やすい
組織で適合
入力イベント、指標、例外設計、テスト、監査を自組織仕様で整える
ライセンス：MIT（利用・改変・配布が可能）
Closing
13 / 16
導入の結論
雛形を持ち込み、 自分のルールへ
本リポジトリは「そのまま完璧」ではなく、判断ロジックの雛形として持ち込み、組織の運用・監査要件に合わせて実装する資産です。
DMN（Decision Model and Notation）／ガバナンス意思決定ルールとして読み替えるのが最短ルート
