02 / 16

履歴を資産化する

txcript 読み取り

AIコーディングエージェント間で「セッション履歴」を共通モデルへ変換し、検索・閲覧・編集（クロップ）・継続を可能にするためのツールです。

目的

移植性（portability）を上げ、作業ログを再利用可能にする

前提

セッション＝会話＋推論＋ツール実行＋結果などの履歴

出典：提示された公開情報（GitHub README等）にもとづく要約
problem / 矛盾
03 / 16

単純コピーが崩れる

移植の壁

エージェントごとに保存形式や表現できる情報が違うため、テキスト移植だけでは再現性が落ちたり、ツール呼び出しやメタデータが欠落します。

起きること

会話は残っても、推論・ツール・付随情報の粒度が合わない

結果

「同じログから続けたい」が難しくなる

見落としやすい点：会話だけではコンテキストが閉じない
metaphor / 中継
04 / 16

トランスクリプト共通化

同一視点へ

txcriptは「共通のtranscript（トランスクリプト）モデル」を基盤に、エージェント差を吸収して同じ操作（検索・閲覧・編集・継続）へ寄せます。

In

Claude Code / Codex等のセッション形式

Core

共通transcriptモデルへ変換

Out

別エージェントへ「引き継いで継続」

比喩：翻訳ではなく「運用のための中継」
architecture / 機能
05 / 16

変換＋運用導線

できること

変換（convert）を中心に、検索（query）、閲覧（view）、トリミング（crop）、JSONエクスポート、別環境での継続（continue）などを支援します。

変換

エージェント固有形式 → 共通transcript

継続

受け側の表現能力を反映しつつ続きを実行

運用

list / view / crop / export / continue

連携

MCP経由で読み取り専用ツールとして列挙・検索・読取

例：`run.json` のような交換用JSONが「continue」に使われます
comparison / 何が違う
06 / 16

“同じ続き”が狙い

Exportだけでない

txcriptの中心は「エクスポート」ではなく、別エージェントでの作業継続（continue）に直結する形でトランスクリプトを引き継ぐことです。

従来

形式差で再現性が下がり、続行の手戻りが発生

txcript

アダプタで差を吸収し、受け側へ反映して継続

Claude Code → Codex のような「乗り換え」前提
enumeration / 中核
07 / 16

中核はここ

continue 指向

txcriptの価値は、ログを見返すだけでなく「次の実行へ渡す」点にあります。

i

セッションの相互変換＋継続（continue）

ii

共通transcriptモデルで検索・閲覧・編集（クロップ）

iii

CLI/ライブラリ/Rust/JSで導入の幅を確保

iv

MCPで読み取り専用のログ連携

番号は要約の順序であり仕様そのものを表すものではありません
evidence / 根拠
08 / 16

差分吸収の前提

転送できない分もある

保持される情報は「ソースが記録している内容」と「宛先が表現できる内容」に依存し、対応外フィールドは失われ得ます。

失われ得る例

推論表現、ツール呼び出し、メタデータの粒度

注意点

継続できても“完全一致”とは限らない

実務では「必須情報」を事前に見極める必要があります
distinction / ローカル
09 / 16

ライブとローカルの差

“探索”は別物

ライブアカウント（例：Claude Chat、ChatGPT）はWeb API等の読み取りや制限が絡み、ローカル探索とは挙動が異なるとされています。

ライブ

プライベートAPIを利用し、ログ再利用に制約があり得る

ローカル

ライブアカウントをスキップし、明示的に指定する方針

引用可能な差分は提示情報の範囲に依存します
process / 運用
10 / 16

一覧→切り出し→継続

実務フロー

セッションをリストし、必要部分をクロップして、交換JSONにしてから別エージェントへ continue する流れが想定されています。

i list

過去セッションを列挙

ii crop

検索した範囲だけトリミング

iii continue

`run.json`等を使って引き継ぎ継続

CLI導線は Rust/JSでも同様の概念で使える想定です
evidence / 安全
11 / 16

セッションは危険になり得る

安全配慮

セッション履歴には個人情報や秘密情報が含まれ得るため、セキュリティポリシーや敵対的セッション対策（例：パスバリデーション強化）が言及されています。

対策の方向

敵対的ファイル入力への防御、パスバリデーション強化

運用の宿題

権限を絞り、利用範囲とデータ取扱いルールを決める

具体的な保証範囲は追加資料での確認が必要です
distinction / リスク
12 / 16

“できる”≠“完全同等”

再現性の限界

最大の懸念は、欠落する情報が出るため、継続時に文脈がどの程度再現されるかがソースと宛先に依存する点です。

主リスク

ツール結果・推論表現・依存ファイル等の欠落

対処

導入初期は重要データを優先して差分を検証

「継続できる」と「同一文脈で再現できる」を混同しない
closing / 要点
13 / 16

作業ログを資産へ

結論

txcriptは、エージェント間のセッション差を吸収して“作業継続可能なログ資産”にするための、運用寄りのインフラです。

強み

変換＋検索・閲覧・クロップ＋continue、MCP連携まで揃う

前提

欠落は起き得るため、必須情報の確認と実験が重要

References（要約元）

・Claude Code / Codexのような複数エージェントにおけるセッション差
・MCP（Model Context Protocol）の考え方（読み取り専用ツール連携）
