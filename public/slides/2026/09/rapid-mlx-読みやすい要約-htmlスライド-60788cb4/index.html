02 / 14
Local で速く、互換で広く

Rapid-MLX

Apple Silicon 上の“ローカルLLM推論エンジン”を、OpenAI/Anthropic互換APIとして提供するプロジェクト。 チャットからエージェント運用までを一気通貫で狙います。

Key idea：ローカル推論 + API互換（drop-in）で既存のAIアプリ資産をそのまま活かす。
PROBLEM
03 / 14
“速い”だけでは足りない

導入摩擦

ローカルLLMは速くても、既存クライアントやIDE、エージェント資産が“そのまま動かない”と運用が止まります。 そこで互換APIと検証体制が重要になります。

困りごと
ローカル化でAPIや入出力仕様がズレる
互換がないとアダプタが必要
狙い
OpenAI/Anthropic互換で“置き換え前提”
drop-in（アダプタ最小）を目指す
ARCHITECTURE
04 / 14
OpenAI 風に話す

互換 API

Rapid-MLXはOpenAI/Anthropic互換のエンドポイントを提示し、クライアント側の変更を抑えます。 例として /v1/chat/completions、/v1/responses、/v1/messages などが列挙されています。

Chat
/v1/chat/completions
Responses
/v1/responses
Messages
/v1/messages
Also embeddings / audio / videos まで拡張点がある（opt-in extras）。

ローカル推論だけでなく、クライアントや既存エージェントの“ワイヤ検証”を通して動作を確かめます。 Tier-1エージェントをリリースブロッカーにする方針が示されています。

検証ポリシー

互換“風”ではなく実行で担保

TTFT が体験を決める

prefill / decode

性能は TTFT（Time To First Token）と prefill / decode の切り分けで説明されます。 “最初の応答の速さ”と“生成の伸び”が別指標として見える化されます。

TTFT
最初のトークンが出るまで
体感の“待ち”に直結
prefill / decode
入力処理 / 生成フェーズ
どこで時間が伸びるか分解
EVIDENCE
07 / 14
“条件付き”の数値

ベンチの前提

測定は特定条件（例：8K、キャッシュクリア、M3 Ultra/256GBなど）で行われ、TTFTやトークン率、MLXメモリ観測が示されます。 そのため、他環境への一般化には前提確認が必要です。

指標
TTFT / トークン率 / メモリ Active-Peak
“計測可能”を優先
注意
条件依存（環境差で再現が揺れる）
温度・負荷・電源モード等
MEMORY
08 / 14
RAM を守って速く

量子化 + KV

量子化（4bit/8bitなど）でモデルを小さくしつつ、KVキャッシュ（継続バッチング等）で推論中の計算・メモリを効率化します。 AppleのMLXスタック前提でスループットを狙うのが核です。

量子化
4bit/8bitでモデルを圧縮
必要RAMと速度のバランス
KVキャッシュ
継続バッチング・キャッシュ活用
同一サーバ内の効率化
GUIDE
09 / 14
RAMティアで選ぶ

推奨モデル

RAMティア別に推奨モデルが整理され、OOM（Out of Memory）を減らす運用ガイドになっています。 例：8–15GBは lfm2.5-2.6b-4bit、32GB+は qwen3.8-27b-4bit。

〜15GB
lfm2.5-2.6b-4bit
32GB+
qwen3.8-27b-4bit
Why：インストール/ピッカーと整合し、CIで差分を検知する説明がある。

SECURITY
11 / 14
“ローカル”の条件

外部公開に注意

「nothing leaves your Mac（$0 per token、クラウド送信なし）」を目標にしつつ、サーバを外部公開する場合は認証が必要になります。 Cursorのようにルーティングが変わるケースでは、APIキー設定や前提の崩れに注意が促されています。

基本
ローカル完結を目標
APIキー不要の例もあり
注意
外部公開は認証が必要
Cursorは localhost 前提が崩れる
LIMITATIONS
12 / 14
“速さ”と“品質”は別

量子化の解釈

4-bitビルドの差分は未測定である旨の注意があり、AI Indexのような指標は“精密リリース全体”前提に依存します。 数値の読み取りは「速度中心」「前提条件あり」を前提に慎重に行うべきです。

未測定
4-bit build の差分
速度以外の一般化に注意
注意
AI Index をそのまま同等視しない
品質評価は別軸になり得る
