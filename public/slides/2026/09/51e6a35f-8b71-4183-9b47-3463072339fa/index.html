Release Lens
02 / 18
エージェントがチームに

v0.21.0

NousResearch「Hermes Agent」(2026-08-31)の要約：マルチエージェントを“会話と運用”として扱える方向に強化。
対象読者：一般 / 技術は必要最低限（英語用語＋短い日本語）
Problem
03 / 18
配線から運用へ

体験の差

従来の「複数エージェント」は裏側の仕組み（plumbing）に寄りがちでした。今回の焦点は“誰が何をしているか”を会話の形で見せることです（Bot Mode）。
従来
マルチは見えにくい（監査・指示が難しい）
今回
“チーム会話”として運用しやすい
鍵：Bot Mode / グループチャット / 相互DM（peer）
Core Idea
04 / 18
Bot Modeがデフォルト

チーム化

Bot Mode（デスクトップ内蔵）がデフォルトオン。エージェントに“名前・顔（アバター）・名簿（ロスター）・グループチャット”が付き、見える運用へ変わります。
Name
ボット識別
Avatar
アバター表示
Roster
メンバー一覧
Group Chat
Discord風運用
効果：俯瞰しやすい／@メンションで指示しやすい
Process
05 / 18
cronに“文脈”

継続性

cron（定期実行）に永続メモリとcontinuity=trueが導入。毎回ゼロからではなく、前回までの出力・観測を引き継ぎます。
前回の引継ぎ
重複排除（デデュープ）
定期ブリーフ
昨日の文脈を踏まえる
目的：定期タスクの“品質劣化（ゴールドフィッシュ化）”を抑える
Architecture
06 / 18
delegate_taskを制御

ライブオーケストレーション

delegate_taskでサブエージェントをライブに制御可能。途中で軌道修正・停止し、部分結果を保持してコストと手戻りを下げます。
途中制御
停止・修正（軌道修正）
部分保持
成果を“捨てない”
品質/コスト
JSONスキーマ検証・コスト表示
方向性：当てずっぽう → 品質とコストを見ながら運用
Evidence
07 / 18
MCPが運用窓口に

コマンドセンター

MCP統合（MCP = 外部ツール/サーバ統合の規格）。複数のMCPサーバをダッシュボード的に管理し、運用負担を軽減します。
運用支援
健康チェック / 再認証誘導
見える化
コスト・使用量の可視化
効果：MCP設定の“考古学”を減らす
Process
08 / 18
読むから動かすへ

ブラウザ強化

デスクトップ内蔵ブラウザをエージェントがナビゲート・クリック・読取する機能が強化。調査やデバッグが“観察”から“操作”へ広がります。
Navigate
移動
Click
操作
Read
読取
注意：外部Web操作は監査と権限確認が前提
Security
09 / 18
承認制で事故抑制

自己改変を緩めない

エージェント指示ファイルやメモリストアへの書き込みに承認が必要に。プロンプトインジェクションで“自己改変”され得る経路を抑えます。
Before
書き込みが自動だと危険
After
承認でガードレール
また秘密漏えい対策・危険コマンド検知なども記載
Distinction
10 / 18
“信頼性”も同時に

運用の安全弁

本リリースは、運用・可視化・安全性・信頼性を同時に引き上げる方向。結果として“業務で使えるチーム”に近づけます。
Observability
何が起きたかを追える
Trust
誤動作の抑制
Recover
失敗からの回復
用語：observability（観測可能性）
FAQ
11 / 18
FAQ: Bot Mode

何が変わる？

エージェントがプロフィールとして扱われ、名前・アバター・ロスター・グループチャットが用意されます。複数エージェントの会話が一つの部屋で進み、@メンションで呼び出せます。
理解
“誰が話しているか”が可視化
操作
特定ボットに指示が飛ばせる
用語：peer（相互DM）
FAQ
12 / 18
FAQ: cronの記憶

前回を参照？

cron agents は永続メモリと継続性を持ち、continuity=trueで前回の出力を次回へ引き継ぐとされています。モニターモードでは変化がないとLLMをスキップする仕組みも記載。
continuity=true
文脈の引継ぎ
スキップ
無駄推論の削減（モニターモード）
注意：詳細なデータフローは本テキストでは確定できない
My Opinion
13 / 18
最大の強み

見える運用

最大の利点は、マルチエージェントを“チームの会話”として運用可能にしたこと。cron記憶とdelegate_taskの途中制御は、現場の失敗コストを下げる方向に働く点が説得力があります。
cron memory
継続運用で品質を保つ
delegate_task
途中で止めて修正できる
用語：delegate_task（サブタスク委譲）

Takeaway
15 / 18
結論

“チーム運用”へ

v0.21.0は、会話的なBot Mode、cronの継続性、ライブな並列制御、MCPの統合運用、承認制セキュリティで“使えるチーム”に前進したリリース。
導入の勘所
データ保持・ログ・権限、信頼境界、失敗時の回復
次の一手
設定を確認し、まず限定スコープで運用テスト
用語：observability（観測可能性） / continuity（継続性）
