Jev × 音声 × 実行

voice-browser 設計思想

音声入力でブラウザ操作を行う Node アプリを、意図推定と安全ゲートの観点で整理します（Jev・Web Speech API・Playwright連携）。

PROBLEM
03 / 16
誤操作の恐れ

音声は 曖昧

音声認識の誤りや途中発話（partial transcript）により、意図の誤推定から誤クリック・誤入力が起こり得ます。

ARCHITECTURE
04 / 16
3つの変換

音声 → 意図 → 操作

1) 認識 / Recognition
Chrome/Edge Web Speech API
日本語: 音声→文字（partial transcript含む）
2) 推定 / Intent
Jev（TypeSafe System One / jev-1.13.0）
日本語: “生成”せず候補から選択
3) 実行 / Execution
閾値ゲート後に Playwright
日本語: click / input / move 等
安全装置 / Safety
対象候補・破壊操作・完了判定
日本語: confirm / 番号オーバーレイ / wait 条件
PROCESS
05 / 16
先回り判断

partial で 実行

“音声を待たずに”決められるものは、partial transcript の段階で Jev に意図推定を依頼し、最短で先回り実行します。

速度目標
約250〜350ms
dbounce 200ms、推定遅延平均330ms（README記載の目安）
前提
閉集合アクション優先
クリック/移動など、途中で意味が変わりにくい意図
DISTINCTION
06 / 16
待つべきは待つ

自由文は 遅延

検索・タイプのように途中で意味が変わる意図は、最終結果や無音待ちで事故を抑えます。

閉集合 / Closed-set
click / move など
partialでも確定できる場合は早めに実行
自由文 / Free-text
search / typing
最終transcript（または無音）を待つ
EVIDENCE
07 / 16
“生成しない”

Jevは 選択

Jev は文章生成を行わず、抽出された候補（要素ID・サイト種別・テキスト断片・URL断片等）から最適なものを選びます。

返答の形
候補 + 確率 / confidence
is_command・complete などの質問に対する判定情報
安全への利点
想定外の文字列生成を抑制
検索クエリ/入力内容/URLは “生成” ではなく選択
ENUMERATION
08 / 16
ゲートが鍵

閾値で 実行

実行前に複数の条件（is_command / intent.confidence / complete / target.confidence など）を満たした場合だけ、Playwright が動きます。

意図判定
is_command
発話がコマンドかを判定
確信度
intent.confidence
意図クラスの信頼度で制御
完了 / 対象
complete / target.confidence
コマンド完了と対象要素の確からしさ
DISTINCTION
09 / 16
曖昧なら確認

クリックは 番号

クリック候補が曖昧な場合、ページ上に番号オーバーレイを出し、話者が番号を発することで人間が確定します。

対象候補
UI要素の候補ID
“最も適切”を確率で選ぶ設計
失敗時の逃げ道
番号で手動解決
閾値不足・曖昧性が残るときに委ねる
