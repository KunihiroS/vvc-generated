シークレット検出の改善
BPE効率
候補抽出の後段フィルタに「Token Efficiency（トークン効率）」を加えることで、エントロピーだけでは難しい“非日常性”を捉え、精度（precision）と再現（recall）の両立を狙います。

なぜ難しい
entropy限界
エントロピー（ランダムさ）は有効ですが、シークレットの本質である「人が書く分布から外れた稀さ」を十分に分離できません。Base64・UUID・依存関係など、性質の違う文字列が似た“ランダム風”に見えるのも原因です。

2段階
一般的なシークレット検出は、(i) 正規表現などで候補を広く拾い、(ii) 追加指標で本物っぽさを絞ります。Token Efficiencyはその(ii)のスコアリングに追加する“別の視点”です。

Token Efficiencyの定義
文字列 / トークン
BPEトークナイザで文字列を符号化し、「文字列長 ÷ トークン数」を Token Efficiency として定義します。値が低いほど、トークナイズ上“理解されにくい＝非日常的”とみなします。
計算
Token Efficiency
= length / tokens
解釈
低いほど“分割が増える”
→ 稀寄り
EVIDENCE
07 / 16
なぜBPEが効く
分割の差
BPEは頻出する文字ペアを統合するため、自然な文章は少ないトークンで表せます。一方、未知で非自然な並び（典型的にシークレット候補）は分割が増えやすく、その比率差がシグナルになります。
自然言語っぽい
少トークンで表現
→ efficiency高め
シークレット候補っぽい
多トークンに分割
→ efficiency低め

別の物差し

運用判断の要点
再キャリブレーション
著者の主張は候補生成後の“後段分類”であり、正規表現ルールセットや前処理、CredData側ラベルの誤り可能性などにより再現性に不確実性が残ります。導入時はアラート疲労と見逃しのバランスを前提に、組織環境で再評価し、cutoffを経験的に合わせる設計が必要です。

まとめ
次の一手
Token Efficiencyは、エントロピーの“ランダムさ”だけでは弱い“非日常性”に別信号を与える後段フィルタとして有力です。F1改善の報告に加え、トークナイザ依存や弱いパスワードの盲点があるため、既存検出器（Betterleaks等）に併用しつつ、しきい値調整で運用最適化するのが現実的です。
