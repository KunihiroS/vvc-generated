運用フローは4ステップ

作成→投入→観測→継続

セッションを作成し、準備完了後にタスク投入し、ストリーミング/Webhookで進捗や追加入力を把握し、同じセッションに追加タスクで継続します。

i. セッション作成
状態の入れ物を用意

エージェントに実行開始
iii. 進捗観測
出力ストリーミング／Webhook
iv. 追加タスク
同一セッションで誘導・継続

“durable”の要点

ターン跨ぎで継続

メリット

11 / 16
ガバナンスは最優先

データレジデンシ注意

データレジデンシは米国のみ対応で、Zero Data Retention（ZDR）には対応していません。セルフホスト型サンドボックス選択でもZDR適格にならないと明記されています。

データレジデンシ
米国のみ対応
Data Residency（データ所在地）
ZDR（保持なし）
非対応
Zero Data Retention（保持ゼロ）
結論
情報取り扱い要件（コンプライアンス/保持ポリシー）を事前確認必須

導入の安全な進め方

強みは明確、確認も必須

Agents APIは管理された実行ハーネスとして強力ですが、この断片だけではイベント形式や失敗時回復、権限モデルの詳細が不足します。導入前にガバナンスと仕様確認を補完して設計に落とすのが安全です。
