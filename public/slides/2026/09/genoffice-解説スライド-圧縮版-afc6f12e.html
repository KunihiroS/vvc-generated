GenOffice / genoffice
01 / 18
AIは“編集の中核”へ
オープンソース AIオフィス
GenOfficeは、Microsoft Office形式（.docx/.xlsx/.pptx）を開いて保存しつつ、PDFやMarkdownもローカル中心で扱うデスクトップアプリです。 特徴は、AIをチャットの付属品ではなく“編集ワークフロー”の中核として統合する点です。
Problem
02 / 18
互換性が壊れる
編集の信頼
変換→再保存は、レイアウト崩れや差分（Word側の勝手な変更）を生みやすく、編集資産の“信頼”を損ねます。 GenOfficeはこの問題に対して、バイト保全と意味構造に寄り添う編集を主張します。
Core Idea
03 / 18
AI＝編集エージェント
ブロック差分 diff
AI編集は「文書全体を作り直す」のではなく、ブロック単位の編集差分（スナップショットやdiff）として扱う設計です。 これにより、どこがどう変わったかを追いやすく、再現性の方向を強めます。
Edit Unit（編集単位）
ブロック / 段落 / スナップショット
Target（狙い）
意味構造に沿った更新
Architecture
04 / 18
共通エンジン層
Electron アプリ群
GenOfficeはElectron上で複数アプリ（Docs/Sheets/Slides/PDF/Markdown/Shell）を提供し、背後に共通のエンジン層を持つ構成です。 これにより、同じ編集思想をファイル種別へ横断適用しやすくします。
Docs
Word (.docx) 互換
Sheets
Excel (.xlsx) 互換
Slides
PowerPoint (.pptx) 互換
PDF
ページ上編集 / ローカル変換
Markdown
ローカル中心の取り回し
Byte-preserving
05 / 18
壊さない保存
バイト保全（byte-preserving）
DOCXでは、編集した“汚れた段落”だけをOOXMLフラグメントとしてパッチし、他のエントリは原本のバイト列を保持する方針を掲げています。 目標は「Wordに気づかれない」差分を抑え、互換性を壊しにくくすることです。
Approach
差分パッチ（段落単位）
Benefit
レイアウト崩れ・余計な差分を抑制
PDF Editing
06 / 18
“塗る”ではない
真のテキスト編集
PDFはカバーアップ（見た目の上書き）ではなく、段落選択とリフローを行い、ページ内容ストリームを書き換えることで編集を目指します。 さらにフォント保持も目標に含めています。
Input（狙う操作）
段落選択 / リフロー
Mechanism
内容ストリーム書き換え
Local Conversion
07 / 18
クラウド不要
PDF→Office 完全ローカル
PDF→Word/PowerPoint/Excelへの変換は「完全にローカルでオンデバイス」とされています。 スキャンPDFはmacOS/WindowsのシステムOCRで編集可能テキストへ変換する流れです。
Conversion
オンデバイス完結（クラウド送信なし）
Scan PDF
システムOCR → 編集テキスト
AI Backend
08 / 18

BYOK / キーなし 両対応
AI機能はネットワーク前提ですが、BYOK（各種LLM APIキー持ち込み）と、Gensparkのキーなしサインインの両方に対応するとされています。 Claude/OpenAI/Gemini等やOpenAI互換エンドポイント（base URL + key）も選択肢です。
