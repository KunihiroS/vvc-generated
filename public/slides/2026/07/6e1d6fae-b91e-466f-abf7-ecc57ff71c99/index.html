Claude 5世代の文脈設計

context engineering

ルール・例・検証を“全部最初に”渡す設計を見直し、必要十分な文脈だけを段階的に与える。 （文脈設計：context engineering / 文脈工学）
前提
Claude Code / エージェントは「必要に応じて開示」
狙い
衝突なく、過不足なく判断材料を渡す
Problem
03 / 18
“強い縛り”の副作用

過剰制約

従来のベストプラクティスは、システムプロンプト / CLAUDE.md / Skills / ユーザー要請の総体に“強い制約”を入れがちだった。 Claude 5系では、それが不要になり得る。
起きること
文脈の衝突（例：残せ／コメントするな）
結果
モデルが整理して考える余地が減る
Evidence
04 / 18
80%削除でも悪化せず

判断力

Anthropicは、Claude Codeのシステムプロンプトのうち80%以上を削除しても、コーディング評価で測定可能な悪化が見られなかったと述べた。 （＝“縛り”の絶対量が減っても成立する余地）
示唆
モデルがより良い judgement をする
設計への翻訳
文脈側が過剰に縛られていた可能性
Metaphor
05 / 18
最初は“全部”ではない

段階的開示

文脈は“事前に全部見せる台本”ではなく、必要になった場面でページをめくる設計にする。 （progressive disclosure / 漸進的開示）
最初
方針・最小の判断材料
必要時
検証・詳細・参照を呼び出す
Architecture
06 / 18
文脈は“複数ソース”

衝突点

文脈はシステムプロンプト / CLAUDE.md / Skills / メモリ / artifacts 等の総体。 同一リクエスト内で矛盾があると、重くボトルネック化する。
入力
ユーザープロンプト
土台
システムプロンプト
運用
Skills / CLAUDE.md / メモリ
成果
artifacts（例：HTML mockup）
判断
ツール呼び出し・検証
落とし穴
矛盾する指示が同時混入
Distinction
07 / 18
“縛る”より“整理”

簡略化

新世代モデルでは、ユーザー意図に到達するために必要な範囲でモデルが整理して考える余地を残す。 そのために“制約の簡略化”を優先する。
やめる
全体を縛る細かい一般ルールの過剰投入
やる
衝突する一般ルールの削除／明確な優先順位
Process
08 / 18
小さく変えて検証

運用

「削ったら終わり」ではなく、まず小さく変更→品質指標で検証→矛盾を除去の順で進めるのが堅実。 （評価設計とセット）
i
文脈の一部（例：ルール量）を削る
ii
タスク品質で比較（指標・統計・分散）
iii
衝突（矛盾）点を特定して再整備
Architecture
09 / 18
例より“設計の言語”

ツール設計

ツールの使い方“例”を大量に載せるより、パラメータ・列挙型・状態遷移などで意図を自然に伝える。 （tool definition を表現力で作る）
従来寄り
例文を増やして誘導
推奨
入力形式（型）と制約で自動探索を助ける
Process
10 / 18
必要な検証だけ呼ぶ

遅延ロード

検証（review/verification）や詳細文書は常に渡さず、スキルとして分離して必要時だけ呼び出す。 ツール定義側も遅延ロードで文脈肥大を抑える。
早期
実行可能な最小情報のみ
判断後
疑わしい点だけ検証スキル
結果
品質向上・ノイズ低減
Architecture
11 / 18
CLAUDE.mdは軽く

焦点

CLAUDE.mdに“何でも倉庫”を作らない。軽量にし、リポジトリ固有のつまずきどころ（gotchas）中心にする。 （貯蔵庫化の防止）
入れる
repo固有の gotchas / 必須の前提
入れない
一般論・ベストプラクティスの全部盛り
Process
12 / 18
Skillsはガイドに留める

参照の設計

Skillsは過剰に縛る“規約”ではなく、必要時に情報探索できるガイドとして設計する。 参照ツリーや分離で、読み込み時間とノイズを下げる。
役割
検索・誘導（必要時に開示）
粒度
大きくしすぎない（分割）
運用
調整しやすい形に保つ
Evidence
13 / 18
リスクと対策

安全

制約を減らすほど誤解・逸脱のリスクはゼロにならない。特に安全・法務・セキュリティでは、削るのは“重複/衝突の一般ルール”に限定する。
リスク
最悪ケース回避が弱まる可能性
対策
テスト／監査／ガードを評価設計とセットで実施
Closing
14 / 18
今日からの要点

要約

Claude 5世代前提では、縛り・例・最初の全提示を減らし、段階的開示／遅延ロード／軽量な CLAUDE.md／表現力あるツール設計へ寄せる。
i
過剰制約を外す（矛盾を減らす）
ii
例よりツール定義（型・列挙・状態）
iii
段階的開示＋遅延ロードで文脈肥大を防ぐ
