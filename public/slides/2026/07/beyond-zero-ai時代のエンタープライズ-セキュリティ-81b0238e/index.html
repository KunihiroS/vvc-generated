AI時代の“ゼロ”再設計
Beyond Zero
信頼境界を「アプリ」ではなく「行為×資源（action×resource）」へ細分化し、機械の速度で認可判断する次世代原則です。
EN: trust boundary / Authorization / Context / Intent / Challenge / Containment　（JP gloss）
PROBLEM
03 / 16
人の速度が限界に
追いつかない
AIエージェントは大量データへ高速にアクセスし、アクセス要求の“粒度と速度”が急増しています。
その結果、「人間ベースの認証・認可」や「事後調査（SecOps）中心」では防御の時間に余裕がなくなります。
METAPHOR
04 / 16
免疫システムの発想
“その場”で抑える
攻撃や不正の兆候を見たら、後から追うのではなく、その瞬間に“強さを調整して介入”します。
Challenge（追加確認）
正当性の説明・承認・本人確認などを要求する“要求型”介入。
Containment（封じ込め）
危険度が高いときアクセスを強く止める“封じ込め型”介入。
ARCHITECTURE
05 / 16
行為×資源へ分割
信頼境界の縮小
信頼境界（trust boundary）を「アプリ／ツール」単位から、「個々の行為」と「個々のデータ資源」へ縮めます。
Before（従来）
アプリ単位で信頼しない／都度確認する設計が中心。
After（Beyond Zero）
同じアプリでも操作内容が違えば、資源単位で細かく制御。
ARCHITECTURE
06 / 16
二層で判断する
床と天井
静的ポリシー（floor: 最低限の許可／不許可）と、動的推論（ceiling: 文脈・リスク・意図で追加介入）を併用します。
静的（Static）
コンプライアンスの“床”を固定して検証可能性を確保。
動的（Dynamic）
リスクが高いときだけ摩擦（Challenge／Containment）を上げる。
狙い
完全な動的化で起きがちな“形式的検証の難しさ”を回避。
PROCESS
07 / 16
低遅延：前処理で支える
Contextを先に用意
アクセス時の推論を重くしないため、事前に前処理（preprocessing）で文脈情報を“キャッシュ”します。
誰（Who）
人／組織、実行主体の属性（agent identity含む）
何（What）
目的の操作（action）と対象データ（resource）
どの仕事（Job）
担当作業と業務文脈（context）
どの感度（Sensitivity）
データ分類に基づくリスクの前提
PROCESS
08 / 16
兆候→即時介入
読み取り速度で勝つ
過剰権限、意図（Intent）と実行のズレ、資格情報の不正使用などの兆候をトリガに、チャレンジ／コンテインメントへ移ります。
入力（Signals）
文脈・意図・実行履歴・認可結果・資格情報の整合
出力（Actions）
拒否／チャレンジ／封じ込めをポリシーと連動して即時実行
EVIDENCE
09 / 16
調査を“予備動作”にする
後追い→統合
従来はログ収集→分析が中心でしたが、Beyond Zeroではリスクシグナルで自動調査を走らせ、次の判断へ即時反映します。
従来
アクセス後に“解析”し、次の対策を検討
Beyond Zero
アクセス時に“判断＋介入＋学習”を回す
目標
攻撃者の機械速度に対し、防御の速度を近づける
DISTINCTION
10 / 16
ゼロトラストとの差
言い換えではない
Beyond Zeroはゼロトラスト（BeyondCorpの考え方）を土台にしつつ、信頼境界を“アプリ”から“行為×資源”へ移し、機械速度の判断へ寄せます。
粒度
アプリ単位 → 行為×資源単位へ（同一アプリ内でも制御差）
時間軸
事後調査中心 → その場評価・介入中心へ
COMPARISON
11 / 16
Challenge vs Containment
介入の強さ
両者は同じく“介入”ですが、目的と解除条件の考え方が異なります。
Challenge（追加確認）
拒否前に正当性の追加説明や本人性確認、承認要求などを求める。
Containment（封じ込め）
危険が高い場合にアクセスをより強く止め、解除には追加手続が必要になり得る。
EVALUATION
12 / 16
有望だが、詰めが要る
導入の論点
方向性は合理的ですが、誤検知・性能・属性精度・監査の設計不足が導入リスクになります。
指標
誤検知率、レスポンス遅延、検知カバレッジなど定量評価が必要。
前処理品質
Context/Intent推定が外れると、コンテインメントが不必要に増えうる。
説明・監査
拒否／チャレンジ理由の説明責任、ログ粒度、人のレビュー基準が重要。
運用設計
評価・是正の責任分界（誰が判断し、どう改善するか）を明確化。
