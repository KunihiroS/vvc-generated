LOCAL LLM ON MICROC0NTROLLER
02 / 16
超低資源で“動作”を作る
ESP32-S3でLLM
ESP32-S3（約8ドル）上で、TinyStories学習の28.9Mパラメータ規模の言語モデルを動かし、外部サーバなしで文章生成した報告です。
Key idea（要点）
Per-Layer Embeddings（埋め込み参照の読み出し最適化）
Measured（速度）
約9–10 tokens/秒（短い物語の逐次出力）
THE CORE CONSTRAINT
03 / 16
全部載せる誤解
SRAM 不足
言語モデルは「パラメータ＝高速メモリ（SRAM）に丸ごと載せる必要がある」と誤解されがちですが、SRAMが小さいマイコンではそれが成立しません。
現実
SRAMは少ないが、FLASH/（場合により）PSRAMは大容量
狙い
必要な分だけ参照し、SRAM消費を抑える
MAIN TAKEAWAY
04 / 16
作戦は“読み出し”
FLASHに置く
モデルの大部分を高速メモリに載せず、埋め込みテーブル（約25Mパラメータ分）をFLASH側に置き、トークン生成のたびに必要な行だけを読み込む設計が鍵です。
1
埋め込みテーブルをFLASHへ
2
生成時は“必要な部分のみ”参照
3
SRAM制約を突破
MEMORY HIERARCHY
05 / 16
役割分担（SRAM/PSRAM/FLASH）
量子化と階層
4-bit量子化によりモデルを約14.9MBへ小さくしつつ、SRAM/PSRAM/FLASHというメモリの違いに合わせて配置することで成立しています。
4-bit
モデルサイズ：14.9MB（前提）
メモリ例
SRAM 512KB / PSRAM 8MB / FLASH 16MB
※上記は入力データ中で示された典型値として扱い、「単一の工夫」ではなく組み合わせで成立、という点が重要です。
PER-LAYER EMBEDDINGS
06 / 16
“参照”の粒度を上げる
Per-Layer Embeddings
Per-Layer Embeddingsは「埋め込みテーブル等の大部分を“必要な分だけ”参照できる形にして、メモリと計算の負担を調整する」という考え方だと説明されています。
狙い（何を得る）
大容量をFLASHに置いても、SRAM枯渇を回避
注意（入力データの限界）
具体アルゴリズムは省略されており、厳密理解はリポジトリ資料が必要
WHAT IT CAN / CANNOT
07 / 16
汎用LLMではない
タスク限定
推論や“考える部分”が小さいため、質問応答・指示追従・コード生成・事実知識の保持などの汎用的なLLM能力は期待できない、と明言されています。
できる（期待）
短く簡単なストーリー生成（TinyStories由来）
できない（明示）
Q&A / 命令実行 / コード生成 などはしない（できない）
PERFORMANCE
08 / 16
体験速度が鍵
約9 tokens/s
ESP32-S3上で end-to-end 約9.5 tok/s、純計算部分で約9.7 tok/sという主張があり、理論だけでなく実装の成立を支える材料になっています。
end-to-end
約9.5 tok/s（全体の体感）
純計算
約9.7 tok/s（計算側の目安）
※速度は温度・電源・クロック設定・表示処理やI/Oの影響を受け得るため、条件確認が重要です（入力データからは詳細が欠ける）。
TRUST & NUMBERS
09 / 16
自己点検あり
数字の透明性
パラメータ会計に関する自分のバグがあり、修正後に数字が変わった旨が記載されています。透明性は評価できますが、再現性の厳密検証にはRESULTS.md等の確認が必要です。
良い点
バグと修正が明示される（自己点検）
不足しがち
測定条件・品質指標・比較対象までの詳細は別途必要
FAQ QUICK CHECK
10 / 16
理解の前提
まずYes/No
入力データのFAQ相当を、読み違えがちなポイントから短く整理します。
Q1：サーバなし？（Connectivity）
はい：none、すべてデバイス上で実行（オフライン想定）
サーバ送信なし：端末内生成
Q2：28.9Mは“全部載る”？
いいえ：埋め込みテーブル約25MをFLASHへ、必要な行だけ参照
全部SRAM保持しない（メモリ節約）
Q3：Per-Layer Embeddingsは何？
大部分を“必要な分だけ”参照できる形にし、メモリ/計算の負担を調整する考え方（詳細はリポジトリ要確認）
DISTINCTIONS
11 / 16
意義の置き所
LLM万能ではない
この報告の核心は「大規模モデルが何でもできる」ではなく、「超低資源環境でも動作可能性を、アーキテクチャとメモリ設計で実現した」点です。
主張（価値）
28.9M相当の“動作”を成立させた設計パターン
期待しない（限界）
汎用の知識保持・指示追従・Q&A の性能は目標外
MY OPINION
12 / 16
強みとリスク
工学の学び
最大の価値は、メモリ階層（SRAM/PSRAM/FLASH）を前提にした具体工夫で“成立”まで示したこと。一方、品質評価の比較や測定条件は入力データだけでは判断しづらいです。
強み（Tech）
FLASH参照で成立条件を具体化
強み（Ops）
端末内完結で体験デモ向き
リスク（Quality）
品質指標・比較対象・条件の確認が必要
