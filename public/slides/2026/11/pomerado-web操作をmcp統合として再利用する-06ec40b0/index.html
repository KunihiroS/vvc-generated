Web操作を“呼べるAPI”へ

Pomerado MCP

自然言語でWebタスクを説明すると、ブラウザ操作の手順をMCP統合（integration）として生成し、後でツール呼び出しとして再利用できます。

Problem
03 / 17

毎回“手順をやり直す”

その場操作の限界

Playwright などで毎回ブラウザを操作すると、サイト変更に弱く、同じ手順を何度も作り直すコストが発生します。

痛み
UI変更・DOM変更で壊れる / 再実装が必要
結果
自動化が“再利用可能な部品”になりにくい
Metaphor
04 / 17

探索→統合→再利用

“台本”を作って
後で読む

Pomeradoは、最初にタスクを“探索しながら”統合を作り、以後は生成物をMCPツールとして呼び出します（探索は初回寄り）。

i.探索
ブラウザ上で手順を生成
ii.一般化
例入力を元に統合を形成
iii.再利用
MCP呼び出しで高速実行
Architecture
05 / 17

mint / run を分離

責務を
切り分ける

統合生成（mint）と統合実行（run）を分けることで、実行時の依存や負担を局所化しやすくします。

mint（生成）
統合の作成・レビューに OpenAI API キーが必要（提示情報ベース）
run（呼び出し）
モデル呼び出しを行わない（少なくともREADME相当の説明）

鍵となる設計意図：コスト/レイテンシ/実行時モデル障害の影響を減らす。

Architecture
06 / 17

統合はコードとして残る

監査しやすい
成果物

integrationはフォルダ単位で保存され、設定ファイル（例：pomerado.json、deployment.json）と合わせて管理できます。

保存されるもの
src/ 配下の統合コード + 組み込み設定
運用上の利点
レビュー・バージョン管理・再配布がしやすい
Comparison
07 / 17

“その場” vs “部品化”

再利用性の
差

自動化を都度実行するのではなく、統合としてMCP化しておくことで、同目的処理を高速・安定に実行しやすくなります。

Playwright型
毎回手順実装 / サイト変更で手直し
Pomerado型
最初に統合を生成し、以後はツール呼び出し
Evidence
08 / 17

HARなし・録画なし

低い導入障壁

自然言語によるタスク記述から統合を生成できるため、HAR（記録）やスクリーン録画の準備なしでPoCを始めやすい点が強調されています。

必要前提
自然言語タスク説明
準備物
HAR/録画は原則不要（提示情報）
効果
作業対象サイト変更でも構築負担を抑える
Distinction
09 / 17

read / write の境界

安全側に
設計

Authority（権限）で read（参照）と write（変更）を区別し、writeのときはユーザー確認を挟む設計思想が示されています。

read（参照）
取得・確認に限定（情報閲覧中心）
write（変更）
フォーム送信/予約など。エージェントがユーザーに ask（提示情報）

運用の要点：必要最小権限（least privilege）で組む。

Process
10 / 17

minting（生成）の流れ

統合を作る
手順

mintingでは「探索→例入力→一般化→統合生成」を経て、統合がコードとして保存されます（提示情報からの整理）。

入力
自然言語のタスク記述（例入力を使う）
出力
integration（MCPツール）として保存

続くrunでは、この統合を呼び出して目的の処理を実行します。

Evidence
11 / 17

ログイン・2FAも想定

現実のサイトへ

ログインが必要なサイトや2要素認証があるサイトでも動作するとされています。運用では「何が保存され、何が保存されないか」を確認する必要があります。

読み取り
ログイン中でも“保存しない方向”の趣旨が示唆（提示情報）
確認すべき点
入力の記録範囲 / 資格情報の扱い / 再試行時の整合性

決定性
同一入力で同一DOM遷移か / 成功率の定義が必要
失敗復旧
自己修復の限界 / 再ミント戦略 / 差分検知の有無
破壊的操作
possible_commit示唆あり。ロールバック/冪等性も設計する
closing
13 / 17

結論

まず小さく
検証

Pomeradoは、Web操作をMCP統合へ落として再利用性と運用分界を高める方向性が強い一方、決定性・安全性・復旧戦略は対象サイトでの検証が前提です。

所与情報（提示README相当・要約本文・FAQ）：mint/run分離、read/write、ログイン扱い、再ミント/修復の示唆。
MITライセンス / 要件：Node 24.21以降（Web検索で要件が明記されていた旨）。
getting-started ガイド：macOSまたはLinux、OpenAI APIキー、MCPクライアントのローカルstdioサーバ対応が前提として列挙（提示要旨）。
過去の話題：ブラウザエージェントの認証境界（タブ指定だけでは分離されない、タスク別プロファイル/最小権限が重要）。
