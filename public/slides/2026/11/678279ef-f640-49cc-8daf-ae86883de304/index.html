ハーネス最適化

モデル だけ見てない？

「モデルを変えるなら、ハーネスも見直すべき」を、大規模ベンチマークで裏づけた要点です。

ハーネス（実行環境・手順・ツール渡し・ループ構成）次第で、通過率（pass rate）とコスト（特に1タスク/1パスあたり推論費）が大きく動きます。
Problem
03 / 16
誤解の源

性能=モデル

LLMの比較は「モデル性能」に寄りがちですが、エージェントは“実行枠組み（ハーネス）”で挙動とコストが変わります。

見落とされやすい点
モデル以外の：実行環境・ツール呼び出し・反復（ループ）設計
結果として起きること
通過率と費用の関係が、ハーネス差で入れ替わる
Eval Design

比較の土台

v1.1は、ハーネス22種×モデル5種×タスク62種×各4試行で、ランキングと統計的信頼性を強化しました。

狙い

Metrics
05 / 16
何を見たか

2軸評価

コスト効率は「pass rate」と「cost（失敗込みの実コスト）」の組み合わせで判断します。

pass rate
合格した割合（タイムアウト/インフラエラー/報酬ハッキングの扱いも設計に依存）
cost per pass
平均コストを pass rate で割り戻した指標（“失敗込み”の実コスト観点）
結局の評価は「通過率が高い」かつ「お金が増えすぎない」ハーネスの見つけ方になります。
Core Idea
06 / 16
最適は固定しない

モデル変更で ランキング崩れる

モデルを切り替えると、パレート的に優位なハーネス群（コストも通過率も良い）が入れ替わります。

“最安”寄りと“通過率高”寄りが、モデルごとに相対順位を大きく動かすのがポイントです。
Evidence
07 / 16
代表例

Codex CLI

Codex CLIはあるモデルでは上位でも、別モデルでは相対的に大きく順位を落とします。

GLM-5.3
1位（1パスあたり $0.803）
Kimi-K3
16位（同 $1.78 前後）
「良いハーネスを探す」だけでは足りず、「使うモデルに合わせて選び直す」必要が示唆されます。
Tradeoff
08 / 16
高コスト万能じゃない

重いほど勝つ？

高コスト＝高いpass rate ではありません。コストと通過率の順位相関はモデルごとに幅が出ます。

観測
コスト順位と pass rate 順位の相関が一定でない
時に
負の相関が出る（“重いのに通らない”方向が起こり得る）
意味
「軽量/高性能」ではなく多目的（通過率×コスト）で選定
Cost Drivers
09 / 16
効く要因

ステップ数

費用に効く要因は、プロンプト長やツール数よりも「ステップ数（各ステップでコンテキスト再送）」でした。

なぜ効く
ステップ増 → 再送トークン増 → 推論コストが累積
含意
“賢さ”より“軌跡（軌道）の長さ”が財布に直結
つまりハーネスは、単なるプロンプト最適化だけでなく反復回数の設計が鍵になります。
Failure Cost
10 / 16
失敗に吸われる

64.5%

失敗側にコストの大半が偏っています。スコア対象費用の64.5%が不通過側で発生し、タイムアウトも含まれます。

観測
不通過側（失敗側）に費用が偏在（64.5%）
示唆
途中で止める・無駄推論を抑える設計が重要
“最後まで回答してしまう”などの挙動は、コストだけでなく運用リスクにも繋がります。
What to do
11 / 16
実務手順

プライベート検証 しよう

モデルが説明できる部分は大きいですが、ハーネスの影響も無視できません。よって候補ハーネスは自社データで短時間検証すべきです。

i
モデルを先に決める
ii
候補ハーネスを数個に絞る（例：通過率寄り/コスト寄り）
iii
自データで pass rate と cost per pass を同時に確認
最適は固定ではないため、「順位の一般化」ではなく「自分のタスクでの最適」を取りに行きます。
Cautions
12 / 16
外挿の注意

前提が変わる

Basetenの価格体系・キャッシュ挙動・評価タスク仕様に依存するため、他環境で順位が入れ替わる可能性があります。

価格/配分
キャッシュ入力がコスト変動要因（入力コストのうちキャッシュ分 42%、出力 33%、その他入力 25%）
タスク差
評価は62のterminal tasks。UI操作/長時間継続/特定ツール前提では別最適が起こり得る
報酬ハッキング対策も監査実装ですが、タスクが変われば“抜け”の形も変わり得ます。
Closing
13 / 16
結論

モデル更新のたび ハーネスも更新

最終メッセージはシンプルです。モデルを変えたら、あなたのタスクで候補ハーネスを（通過率×コストで）検証してください。

特に焦点は「ステップ数」と「失敗時の早期停止」。ここがコストの大半に影響し得ます。
