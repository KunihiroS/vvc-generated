COVER
02 / 16
最新指針を“注入”する
Modern Web Guidance
コーディングエージェントが古い実装に引き戻されないよう、最新のAPI・性能・アクセシビリティ・フォールバック指針を、検索→取得→コンテキスト挿入で支援します。
search 探索
必要なガイドをローカル検索して関連付ける
retrieve 取得
ガイドIDに紐づく指示をコード生成コンテキストへ
PROBLEM
03 / 16
古い発想に“寄る”
LLMバイアス
エージェントは学習データやそれっぽい推論の影響で、最新のWebベストプラクティスから外れた実装へ流れやすい問題があります。
Risk 実害
性能低下・互換性破綻・アクセシビリティ不足
Root 原因
“必要な文脈”が生成時に欠ける
Goal 狙い
必要時だけ最新指針を差し込む
METAPHOR
04 / 16
地図を渡す
Context Map
ガイドは“知識”ではなく“航路”です。エージェントの入力へ直接挿入して、迷いやすい分岐（フォールバック、互換性、実験機能）を安全側に誘導します。
挿入点 どこ
コード生成コンテキスト（context window）
誘導先 どう
Progressive Enhancement（段階的強化）と責任あるフォールバック
ARCHITECTURE
05 / 16
検索→取得→注入
CLIフロー
エージェント実行時に `search` で関連ガイドを見つけ、 `retrieve` でガイドIDの指示を取り込みます。外部通信やAPIキーに依存しにくい設計方針です。
search 探索
タスクに合うガイドを関連付けて選ぶ
npx ... search
retrieve 取得
コードパターン・注意点・フォールバックをコンテキストへ
npx ... retrieve
EVIDENCE
06 / 16
実装指針の“中身”
安全な採用
ガイドは機能紹介ではなく、採用の判断基準（互換性、性能、アクセシビリティ、フォールバック）を一体として扱うことで、実務の落とし穴を減らします。
Performance 速さ
軽量フォールバック／無駄な負荷を抑える
Accessibility a11y
ユーザー影響（見え方・操作性）まで考慮
Fallback 代替
重いポリフィルや第三者バンドルを避ける
DISTINCTION
07 / 16
“許可制”で抑える
Origin Trial
Origin Trialや不安定機能は、検索で見つかっても採用は開発者の明示許可（CLI設定や `.mwgrc` 等）によりガードされます。
Found 見つかる
検索に出ることと採用を分離
Adopt 採用
opt-inがない限り `retrieve` の対象外になり得る
PROCESS
08 / 16
互換性ターゲット
Baseline
Baseline互換性データで「どこまでを前提にするか」をプロジェクトごとに設定できます。既定は Baseline Widely available とされています。
Default 既定
Baseline Widely available
Override 変更
AGENTS.md / CLAUDE.md などで別Baseline目標を指定
EVIDENCE
09 / 16
評価で“校正”
Evals
誘導あり/なしを比較し、Playwright等の自動採点や実タスクで有効性を継続的に測り、ガイドを磨く運用が説明されています。
Compare 比較
Unguided → Guided のパス率を追う
Measure 測定
実Webアプリテスト・自動採点
Uplift 改善
誘導による成功率向上（例：37ポイント改善など）
COMPARISON
10 / 16
人間向けと別物
ドキュメント差
人間向け資料は読んで理解が必要ですが、本ツールは検索→取得→指示注入までをCLIが担い、エージェントが古い実装へ寄る前に方向づけます。
Human docs 読む
理解しないと適用できない（要手作業）
Modern Web Guidance 注入
文脈へ直接“ルールとパターン”を挿入（要手作業を削減）
DISTINCTION
11 / 16
懸念点も明確
限界とリスク
有効性は示唆されますが、(i) ガイド選択精度、(ii) プロジェクト固有要件との不整合、(iii) 誤誘導時の被害評価の網羅性は資料だけでは読み切れません。
Mis-retrieval 誤選択
search照合精度やタスク粒度で外れる
Mismatch 不整合
設計思想・既存コンポーネント制約で破綻する可能性
Impact 被害
a11y実害や誤誘導の大きさの定量範囲が不明
PROCESS
12 / 16
導入の現実解
テスト前提
結論としては価値が高い一方、導入後はCI・E2E・アクセシビリティチェックで“適用範囲”を確定するのが現実的です。要点はターゲット互換性とopt-in方針を明示することです。
Set policy 方針化
ターゲット互換性・Origin Trial opt-inを `.mwgrc` 等で明確化
Verify 検証
E2E／a11y／互換性確認をCIに組み込み、誤誘導を抑え込む
CLOSING
13 / 16
最新へ誘導して回す
あなたの条件で
Modern Web Guidanceは、最新Webの“正解”を直接実装させるのではなく、エージェントが辿る経路を安全側へ整える仕組みです。強みを活かすには、ガイド採用の前提（互換性・許可制・検証）を揃えます。
