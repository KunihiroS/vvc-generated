ワークフローを“コード化”する

Agent SDKエージェント開発

Agent SDKは、Cursorのマネージドエージェントを“プロジェクト”として定義・評価・デプロイできるSDKです。単発の自動化ではなく、運用に統合された形で増やせます。

便利がズレる属人化

PRレビュー、セキュリティ確認、インシデント調査、コンプライアンスはチームごとに判断基準が違います。賢いだけのエージェントは運用ルール（ポリシー）と噛み合わず破綻しやすいのが課題です。

07 / 15
標準で揃う“運用の柱”

品質担保の要素QA

Agent SDKは「評価」と「イベントリプレイ」を標準サポートし、重要ワークフローが期待通りかを確かめつつ改善を回せます。
評価（Evaluation）
変更後に期待へ到達しているかを検証
リプレイ（Replay）
同じイベントを再実行して差分を追跡
運用の属人芸を減らし、“良くなった”を検証しやすくします（ただし評価の粒度・保証範囲は追加確認が必要）。

DISTINCTION
10 / 15
自作/既成との差分

二択を崩すFit

従来は「既成ワークフロー前提」か「ゼロから自作」の二択になりがちでした。Agent SDKは、チームの働き方に合わせて迅速に作り、同じように運用・改善できる点を狙っています。
従来 A
既成製品：運用差分が詰まりやすい
従来 B
ゼロから自作：品質保証・再現が重い
対してSDKは、ポリシー順守・コード管理・評価/リプレイ・deploy導線を一つの枠に寄せます。

“導入前の確認ポイント”

安全性と運用の穴Go/No-Go

文書から読み取れない実装詳細もあります。導入判断では、セキュリティ/権限境界、評価の信頼性、運用監視、失敗時のリトライ方針などを自組織要件で確認する必要があります。
セキュリティ
最小権限・監査ログ・秘密情報の扱い
信頼性
評価がどの失敗モードまでカバーするか
リプレイ/評価があるほど安心材料は増えますが、保証範囲は定量で確かめたい領域です。
