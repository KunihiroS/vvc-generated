Problem
03 / 16
fzfが“効かない”理由
入力が奪われる
通常のシェルではキー入力がシェルへ届き、fzf の統合（CTRL-Tなど）が動きます。ところがAIエージェント操作中は、キー入力がシェルではなくエージェント側に渡ってしまい、連携が失敗します。
通常（shell連携）
キー → fzf 起動

シェルが入力を受け取り、fzf の候補選択結果をカーソル位置へ挿入します。

AIエージェント中
キー → エージェント

キーがシェルに届かないため、fzf 統合が“発火”しません。

Metaphor
04 / 16
tmuxが“鍵番”になる
tmuxが先回り
tmux を挟む発想は「キーの受け取り順序を固定する」ことです。まず tmux がキーを捕捉し、fzf を floating ペインで開き、選択結果を元の入力欄へ戻します。
i
tmuxが捕捉

ペイン内で何が動いていても、tmux側のショートカットを優先。

ii
fzfをfloating

tmux-fzf-complete が fzf を別レイヤで起動。

iii
書き戻し

選択した候補を、AI入力欄のカーソルへ“挿入”します。

Architecture
05 / 16
tmux-fzf-completeの役割
体験をシェル並みへ
tmux-fzf-complete により、AIエージェントのプロンプト入力中でも tmux が先にキーを受け、fzf を floating ペインとして呼び出せます。
Key flow
tmux → fzf → 挿入

選択結果は「元ペインの入力欄」へキー入力として返送。

要点
統合の安定性

エージェントUIに左右されにくくなり、「いつでもCTRL-T的操作」が維持されます。

Process
06 / 16
“次の入力”を作る
出力を材料にする
AIエージェントが出したパス/URL/文章を、そのまま fzf の候補にして次のプロンプトへ再利用します。コピペではなくキーボード中心の編集体験になります。
fzfでの参照
ALT-F/D/U/P/S

カテゴリ別に「ファイル/ディレクトリ/URL/パス/文章」へ切り替えて探索。

文章の扱い
折り返しを復元

インデントを除き、引用しやすい形へ整えて戻す（コピペより再利用が速い）。

Evidence
07 / 16
速度が効く場面
手入力を減らす
この仕組みは、ファイルパスやコミットハッシュなどの手入力負担を下げ、レビュー指示・追記・参照の往復回数を削減します。
入力対象
パス/URL

画面上の候補を即検索して挿入。

入力対象
文章

引用しやすい復元で次のプロンプトへ。

入力対象
Git参照

コミット/ブランチ/タグ/リモートへ。

Enumeration
08 / 16
Gitオブジェクト補完
fzf-git.shでレビューが速い
fzf-git.sh により、コミットハッシュやブランチ/タグ/リモート等の Git オブジェクトを tmux 側から補完できます。
tmux側ショートカット
PREFIX g

シェルの CTRL-G 相当として扱い、Gitカテゴリ補完へ。

例
g h / g p

PREFIX g h：commit hashes / PREFIX g p：GitHub PR（pr.fzfがPATHにある場合）

Distinction
09 / 16
floating/popupの差
tmux 3.7以降が条件
floating pane の挙動は tmux 3.7 以降で必要とされます。旧バージョンでは popup になる場合があり、体験が完全に同一ではない可能性があります。
必要
tmux 3.7+

floating ペインとして fzf を安定起動。

注意
旧版は差分

popup挙動などで、挿入体験が変わることがあり得る。

Distinction
10 / 16
alt-screenで候補が減る
scrollbackは命
エージェントがフルスクリーン描画（alt-screen）を行うと、tmux の scrollback が保持されず、fzf が参照できる範囲が狭まります。候補の網羅性が落ちるので設定調整が必要です。
何が起きる
scrollback消失

fzfが参照できるテキストが「現在表示分」に限定されやすい。

対策
alt-screen調整

Claude Code / Codex で alt-screen を無効化、または履歴保持に寄せる。

“効率化”の中身
何が良くなる？
単に別ツールを使うのではなく、「キー入力の受け渡し」を設計して、生産性のボトルネックを戻します。
Practical
日常の短縮

各ペインで tmux キーバインドが一貫。

Technical
依存条件

tmux 3.7+、fzf 0.74.0以降、Ruby等が絡む。

Strategic
出力→入力ループ

大きな出力を検索し、次の指示へ変換。

Evidence
12 / 16
導入時の落とし穴
検証が必要
環境差（端末の描画方式、キーバインド競合、Ruby必要条件、fzf最小要件など）で挙動が変わる可能性があります。特に「挿入先が正しいか」「書式が意図通りか」を確認してください。
リスク
キー競合

誤挿入や意図しない起動につながる恐れ。

情報制約
参照範囲

scrollbackが保持できないと補完精度が下がる。
