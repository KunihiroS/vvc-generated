DOORY / 概要
02 / 16
ブラウザ編集・自分のサーバー
Doory
テンプレートから制作し、レイヤー編集で仕上げて、画像・PDF・動画/GIFを書き出せるデザインエディタです。無料（課金ロックなし）かつオープンソースで、セルフホストできます。
開始
アカウントなしでも可
(アカウント作成は任意)
保存
基本はブラウザ側
(クラウドは選択式)
運用
Docker Composeで起動
(API/DB/共同編集含む)
PROBLEM
03 / 16
“便利”が前提化する
課題
一般的なデザインツールは、アカウント作成やクラウド利用が前提になりがちです。すると、コストやデータ管理の自由度が下がることがあります。
よくある前提
ログイン前提（アカウント）
クラウド保存前提（委託）
起きる困りごと
料金の増加・機能制限の可能性
データの置き場所を選びにくい
そこでDooryは、“体験（Canva的）”と“所有権（自前運用）”を両立する方向性を打ち出しています。
METAPHOR
04 / 16
クラウドの代わりに
自分の倉庫
Dooryは、編集作業を“ブラウザ上の道具箱”に置きつつ、実データは自分の管理下に置く考え方です。セルフホスト（Self-host）は自由度の代わりに運用責任も増えます。
道具箱（編集）
レイヤー／マスク／曲線テキストなどを操作
リアルタイム共同編集も想定
倉庫（データ）
アプリ・API・DB・保存を自分のサーバーで管理
アップロードも自分側の設定に依存
読み替え：便利さは維持し、所有権を取り戻す。
ARCHITECTURE
05 / 16
Docker Composeで一括起動
起動
Docker Composeで、アプリ・API・データベース・ライブコラボレーションまでまとめて起動できるとされています。つまり、編集機能に必要な周辺要素もセットで扱える設計です。
Web
ブラウザで編集（デザインエディタ）
(UI)
API / 通信
保存・読み込み・連携
(API)
DB / コラボ
リアルタイム編集（例：WebSocket）
(DB + Live)
重要：セルフホストは“簡単に起動できる”一方で、SSL/バックアップ/監視などの継続運用は別途設計が必要です。
FEATURES
06 / 16
本格編集（静止画だけじゃない）
機能
Dooryは、テンプレ編集に留まらず、レイヤー／マスク／フィルタ／曲線テキストなど“制作寄り”の操作を挙げています。さらにアニメーションや音声、動画/GIF書き出しにも触れています。
レイアウト編集
レイヤー操作（グループ、並べ替え）
マスク／フィルタ／定規／スナップ
表現・出力
アニメーション（入退場 27、強調 12、ページ遷移 16）
画像＋MP4/WebM＋アニメGIF
日本語で言うと：“飾り付け”より“制作ワーク”に寄せた編集体験です。

Canvaと何が違う
比較
比較表の論点は、Dooryが“無料・オープンソース・セルフホスト・アカウント任意・インフラ自主管理”に重心を置く点です。これにより、コストと所有権の前提が変わります。
Doory
無料（Pro planなし）
オープンソース／セルフホスト可能
アカウント不要で開始可（クラウドは任意）
Canva（一般的な傾向）

機能や提供形態が有料枠に寄る場合がある
どちらが“機能完全一致”かは検証が必要ですが、前提（自由度／所有権／コスト）は大きく違います。

PROCESS
09 / 16
作業の流れ
編集
アカウントなしでも作業を始められ、ゲスト作業はブラウザに保存されます。クラウドに保存したい場合だけ、アカウントを作る設計が説明されています。
Step i
テンプレート or 白紙から開始
（制作の入口が軽い）
Step ii
レイヤー／テキスト／マスク編集
（制作寄りの操作）
Step iii
多ページ・アニメーション作成
（動画/GIFも視野）
Step iv
書き出し（PNG/JPG/SVG/PDF/MP4/WebM/GIF）
（用途に合わせて出力）
要点：編集→保存→書き出しがブラウザ起点で完結しやすいことが強みです。
DISTINCTION
10 / 16
“共同制作”を想定
チーム
リアルタイム共同編集やコメントがあるとされ、制作チームでのワークフローを変えます。フロントにYjsを使う点も、共同編集を成立させる技術選定として示されています。
できること
リアルタイム共同編集（同時反映）
コメント（やり取りの可視化）
実運用で確認
権限管理（誰が編集できるか）
衝突解決・監査ログ・データ保持ポリシー
READMEからは運用詳細が読み取りづらいので、チーム導入では追加確認が必要です。
SECURITY
11 / 16
自由度＝責任
運用
セルフホストはデータを自分で管理できる一方、運用責任も生まれます。バックアップ、監視、脆弱性対応などを設計しておく必要があります。
必要になりやすい
バックアップ（復旧）
継続管理
監視（稼働確認）
守ること
脆弱性対応（更新）
また、保存先（S3互換など）や保持期間は構成に依存します。.envやストレージ設定を確認しましょう。
TAKEAWAY

選ぶ基準
結論
Dooryは「Canvaのような体験」を、オープンソース・無料・セルフホストで置き換える方向性が明確です。特にアカウント不要とデータ自主管理は強い説得力になります。
向いている人
コストを抑えたい
データの置き場所を自分で決めたい
チームで共同制作したい
導入前の確認
性能・書き出し互換
権限/ログ/保持方針
SSL・バックアップ・運用設計
まとめ：編集体験を重視しつつ、所有権と自由度を優先する選択肢です。
