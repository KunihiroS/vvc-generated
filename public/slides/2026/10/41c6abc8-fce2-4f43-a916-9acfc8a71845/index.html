Context Filter
02 / 16
検索後の選別力
レポート
品質を決める
GPT Researcher は「検索→スクレイピング→選別→ライターLLM」の流れでレポートを作ります。 Context Filter は、どの文章を“読ませるか”を決める最重要レバーです。
（Context Filter：文脈フィルタ / 有用抜粋抽出）
Problem
03 / 16
全文投入の罠
ノイズ増
コスト増
スクレイピングされるページは多く、その大半は質問に直接役立ちません。 全文をライターLLMに渡すほど、不要情報で迷いが増え、遅延とコストも膨らみます。
目的：必要な“抜粋”だけに絞る（絞るほど精度が上がる）
Flow
04 / 16
工程の位置
次は
選別
Context Filter は「検索の次」に来て、レポート生成の前に動きます。 まずチャンク化し、各チャンクの有用性を評価して、ライターLLMに渡す抜粋を絞ります。
i. 入力
検索結果ページをスクレイピング
ii. 分割
チャンク化（最大文字数・分割・オーバーラップ）
iii. 評価
各チャンクの「質問への有用性」をスコア化
iv. 抜粋
スコア上位をライターLLMへ
Filters
05 / 16
4つの方式
Jev / keyword
embeddings / none
比較されるフィルタ方式は 4 つです。 似た文章を探す系から、“有用性で確率評価する”系、“フィルタしない”系まで揃っています。
（Jev：有用性スコア / keyword：語彙検索 / embeddings：ベクトル類似 / none：無フィルタ）
Jev
サブクエリへの役立ちを確率スコアで評価
keyword
BM25ベースの語彙検索
embeddings
埋め込みの類似度で選別
none
全ページ（実質フィルタなし）
Default
06 / 16
デフォルト設計
鍵で
自動切替
デフォルトは TYPESAFE_API_KEY の有無で決まります。 あるなら Jev、ないなら API不要の keyword が使われます。
条件 採用フィルタ 目的
TYPESAFE_API_KEY あり Jev 有用性スコアで精度最大化
TYPESAFE_API_KEY なし keyword 導入容易・低障壁
How Jev
07 / 16
類似度ではない
有用性評価
ルーブリック
Jev は「類似度」ではなく、「この文章はサブクエリにどれだけ役立つか」をスコア化します。 4段階ルーブリックに基づく確率スコアとして返し、直接答えや部分的答えに繋がりやすい抜粋を残します。
入力
チャンク（抜粋候補）
評価軸
サブクエリへの役立ち度（4段階）
出力
確率スコア（＝有用性スコア）
狙い
話題一致だけの文章を抑える
Benchmark
08 / 16
関連率ベンチ
Jevが最多
関連
ベンチマークでは、保持した抜粋の関連率が Jev で最も高くなりました。 Jev：73% / embeddings：46% / none（無効フィルタ）：33% です。
関連率＝関連するテキストとして採用された割合（資料内の評価）

33%
結論
“有用性”で選ぶ方が抜粋が効く
Head-to-Head
09 / 16
精度勝負
同コスト帯
勝ち越し
同コスト帯で比較すると、Jev は embeddings よりレポート精度で優位でした。 head-to-head（直接対決）で 15勝 / 3敗 の結果です。
対戦
Jev vs embeddings
条件
同じコスト帯
結果
15勝 / 3敗
意味
抜粋選びが最終品質に直結
Why works
10 / 16
ノイズ低減
少ない読了
賢い読了
単に“多くの情報”ではなく、“ノイズを減らす”ことで品質が上がると示唆されています。 Jev は embeddings より送るトークン総量が少ない一方、関連テキスト量は大差がなく、ライターが不要情報に引っ張られにくくなります。
Jevの特徴
送るトークン総量が少ない
維持される点
関連テキスト量は大差なし
効果
不要情報の読み込みが減る
結果
生成の信頼性が上がる
Speed & Fallback
11 / 16
堅牢設計
失敗しても
文脈ゼロ回避
Jev は失敗（鍵不足・ネットワーク・レート制限など）しても keyword へフォールバックします。 embeddings も構築不能なら keyword に戻り、文脈が空になるリスクを下げる設計です。
Jev失敗
→ keywordへフォールバック
embeddings失敗
→ keywordへ戻る
狙い
contextが得られない事態を回避
補足
チャンクセットが小さいと none に近い挙動にもなり得る
My Take
12 / 16
実務の結論
Jev推し
ただし検証
結論としては「一般的には Jev が有利、ただし keyword も十分実用的」です。 そして“目的ベース”で選び、自環境で再現テストして最適化する姿勢が安全です。
おすすめ
デフォルトは Jev（可能なら）
現実解
鍵なし・低障壁なら keyword
注意
ベンチ条件依存（28タスク・評価モデル等）
検証
質問タイプで最適設定が変わり得る
