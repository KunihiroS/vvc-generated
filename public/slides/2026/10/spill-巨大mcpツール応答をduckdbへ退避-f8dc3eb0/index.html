Spill
02 / 18
巨大応答、退避して節約
Spill / スピル
MCPの“巨大なツール応答”をそのままプロンプトに載せず、ローカルDuckDBへ保存して必要部分だけSQLで取り出す仕組みです。
Input
MCPツール結果（JSONなど）が巨大化
Action
閾値超だけ自動保存（Spill）
Output
AIへdescriptor＋SQLで必要分だけ
問題
03 / 18
50,000トークン級
Token爆増
MCPツールの応答が大きいと、そのままエージェント文脈に入ってトークン数・遅延・コストが増えます。
まず起きる
巨大JSONをそのまま渡す必要が出る
→ パース/再提示の負担も増える
困りごと
「必要な行だけ」なのに全文が流れる
→ 目的の集計・絞り込みに到達しづらい
発想
04 / 18
JSONを流さない
退避という判断
巨大な中身は“プロンプトの川”ではなく、ローカルDBという“貯水槽”へ流して、必要な水だけくみ上げます。
Before
tool_result JSON → そのまま文脈へ
After
tool_result（巨大のみ）→ DuckDB保存 → descriptor＋SQL
全体像
05 / 18
Spill→DuckDB→SQL
流れで理解
SpillはMCPのPostToolUseイベントをフックし、条件に合う巨大出力だけをDuckDBテーブル化して、AIはSQLで必要部分を取得します。
i. フック
MCP PostToolUse を監視
（入力：ツール応答）
ii. 判定
32KiB超かつ形が対象なら保存
それ以外はpass through
iii. 参照
AIへdescriptor＋SQL → DuckDBが実行
（出力：必要部分のみ）
介入条件
06 / 18
“常に”ではない
閾値で最適化
Spillは巨大化問題を“自動介入”しますが、必ずしも全てを保存するわけではありません。必要なときだけ介入します。
条件 (検知)
MCPツール応答サイズが32KiBを超える
→ まずサイズ
条件 (形)
JSONオブジェクトの配列が非空
例：直接JSON配列、テキスト内埋め込み、structuredContent 等
対象外
エラー、バイナリ／混在ブロックなどは pass through（そのまま）
何が起きる
07 / 18
descriptorへ圧縮
生JSONを回避
AIには巨大データそのものではなく、保存されたデータセットの“コンパクトな説明（descriptor）”が渡されます。
descriptor（例）
テーブル名・列・型・要約方針（必要情報のみ）
→ モデルに渡すのは最小限
SQLで取得
必要な列だけ、必要な集計だけを SELECT で
→ 読み込み・出力を絞る
データ化
08 / 18
ネストは“文字列化”
構造の扱い
ネスト配列や型が混在する部分は、JSONテキストとして保存します。欠損値はSQLのNULLとして扱われます。
ネスト/混在
ネスト構造や配列、型の混在 → JSONテキストとして保存
（そのまま再現しやすい）
欠損
値が欠ける → SQLの NULL
（クエリで扱える）
セキュリティ
09 / 18
SELECTだけ
多層ガード
単なる保存ではなく、安全策を多層化します。SQLは読み取り中心に制限し、DuckDB側も読み取り専用や外部アクセス無効を前提にします。
SQL許可
SELECT中心＋WITH / SHOW / DESCRIBE / EXPLAIN
ミューテーションや複数ステートメントは禁止
DuckDB運用
読み取り専用・外部アクセス無効・拡張ロード無効
→ 実行時の危険範囲を縮小
ワークフロー
10 / 18
自動で差し替え
介入点は最小
ワークフロー自体は変えずに、“巨大出力だけ”を退避することで、エージェント側の設計負担を抑えます。
通常時
32KiB未満 → そのままAIへ
巨大時
条件一致 → DuckDB保存＋descriptor生成
AIの役割
SQLで絞り込み・集計し、必要だけ返す
制約
11 / 18
上限あり
500行の壁
性能・応答サイズの都合で、保存・検索・出力に上限があります。巨大データ“全量そのまま”用途には注意が必要です。
保存/保持
500行キャップ
大量を丸ごと扱う設計ではない
出力
32KiB出力キャップ
SQL結果の戻りにも上限
導入運用
12 / 18
クライアント分離
Cursor/Codex/Claude
クライアント別にフック設定やインストール/アンインストールを分離し、他設定に干渉しないことを重視しています。
設定分離
Cursor / Codex / Claude Codeで別ファイル前提
可逆性
例：spill uninstall cursor のように除去可能
→ 無関係な設定を触らない
結論
13 / 18
分析向き
必要だけ取る
Spillは“安全に・局所的に・効果的に”巨大応答問題を緩和し、特に集計/絞り込み中心のエージェントに適しています。
強み
生JSONを渡さず、トークン節約と遅延低減
安全
SELECT許可＋読み取り専用・外部無効でガード
注意点
500行・出力32KiB・型/形の前提に制約あり
日本語要約
巨大なMCPツール結果を“DBへ逃がし”、AIは“SQLで必要分だけ”取りにいく。
