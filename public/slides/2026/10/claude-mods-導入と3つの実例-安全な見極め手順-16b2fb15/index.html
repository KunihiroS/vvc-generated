Claude Mods

Claude Codeの拡張「Mods」はイベントへ差し込んで挙動まで変えられます。だからこそ、便利さと同時に導入前の見極め手順（validate）をセットで押さえます。

Problem
03 / 16
強力＝不確実

安全の論点

Modsは「設定」ではなく、Claude Codeの内部イベントへコードを差し込みます。結果として、画面・プロンプト・ツール呼び出しの扱いが変わり得ます。

変わるもの
UI（ペイン/帯/ボタン）・プロンプト処理・ツール呼び出し
生じるリスク
ユーザー権限で動く可能性があり、何が起きるかを確認必須
Metaphor
04 / 16
差し込み注射

「イベント」へ
割り込み

Modsは、Claude Codeが発生するイベントの流れに対してTypeScript/JavaScript関数を差し込みます。以降の処理は“拡張が主導”できるため、挙動を読む必要があります（日本語：イベント差し込み）

入力
会話・画面生成
介入点
hooks（フック）/ calls（呼び出し）
出力
UI・プロンプト・ツール処理が変化
Architecture
05 / 16
何を確認する？

validate中心

導入前に「claude plugin validate」で、受け取るイベントと呼ぶAPI（callsの一覧）を読み取ります。これが安全評価の“最初の入口”です。

見るべき
hooks / calls（どのイベントに触れるか、何を許可するか）
コマンド例
claude plugin validate
Evidence
06 / 16
できること

挙動まで
書き換え

Modsはプロンプトやツール呼び出しの扱いを変更でき、画面へペイン追加のようなUI改善も可能です。便利さが“実装修正”として出てくる点が特徴です。

プロンプト
指示の差し替え/誘導
ツール呼び出し
停止/差し替え/やり直し
画面UI
ペイン・帯・ボタン等の追加/改変
Enumeration
07 / 16
まず3つ

著者の
実例

記事で紹介される3つのmodsは目的が明確です。まずは小さく、評価しやすいものから試すのが実践方針です。

i. prompt-rail
長文セッションで既存指示へ戻るための導線
ii. md-prompt
入力欄Markdownを見やすくする（呼ぶAPIが少ないのが利点）
iii. qa-guide
質問ダイアログに文脈と選択肢の影響を添える
Process
08 / 16
読む順番

validateの
読み方

validateの出力は「どのイベントを受け取り、何を呼ぶか」の地図です。callsのAPI名を見て、ファイル/プロセス/ネットワーク/モデル/プロンプト等の範囲を推定します。

手順
①hooks確認→②calls確認→③期待機能と一致するか照合
観点（例）
md-promptが触れる領域が少ないほど、試しやすい
Distinction
09 / 16
過信は禁物

validateは
保証ではない

記事は「validateは安全を保証しない」と明言しています。callsの一覧はAPI名までで、実際に何が起きるかはソース差分やコード読解が必要になり得ます。

なぜ保証できない？
プロセス起動など、実体はソース次第で変わる場合がある
運用ルール
更新が来たら再評価（再validate＋必要ならソース確認）
Comparison
10 / 16
settingsと別物

hooks/skill/MCPと
何が違う？

最大の違いは、modsがClaude Codeプロセス内でイベントに介入できる点です。結果として画面改変や挙動差し替えが現実的になります。

Modsの特徴
イベントに差し込む→挙動やUIを直接変える
他の仕組みの位置
settings hook / skill / MCPは同等の画面改変はできないとされる
Distinction
11 / 16
権限＝ゼロではない

permissionsの限界

権限設定を厳しくしてもリスクはゼロになりません。denyルールがClaudeのツール呼び出しに効いても、modが別経路でプロセスやファイル操作を行える可能性があるためです（日本語：権限限界）

Claude側deny
ツール呼び出しは抑止され得る
別経路
$.fs.read / $.process.spawn等の可能性
結論
防げる範囲は限定的→運用設計が必要
Closing
12 / 16
定常運用にする

導入後まで
回す

実務では「APIが少ないmodから試す」「導入前validate→必要ならソース読解」「更新時に再validate」「権限と運用ルールを合意」の順が有効です。

最小ステップ
①md-promptのような小さめを選ぶ→②validateでcallsを確認
チーム合意
disableAllHooks / safe-mode等の運用方針、再評価の頻度を決める

Claude Code / Claude Mods
ModsがClaude Code内部イベント（hooks/calls）へ差し込める拡張であること、UIや挙動まで変えられる点。
validate
claude plugin validateでイベントとAPI（calls）を確認するが、安全保証ではない／更新時に再評価が必要。
具体例（3つ）
prompt-rail / md-prompt / qa-guide：それぞれの目的と、最初は呼ぶAPIが少ないmodから試す助言。
権限の限界
denyが効いても別経路（例：ファイル/プロセス操作）でリスクが残り得るという注意点。
