COVER
02 / 16
人に“押して”を渡す

big-arrow 読み物

AIエージェントが止まる「許可・同意・認証」の瞬間に、macOS画面へ矢印とラベルを一時表示して、次の人の操作先を最短で示します。

核心
クリックせず・入力せず
目的
“ここを押して”を可視化
日本語用に用語は併記します：bigarrow（big-arrow）、AIエージェント（AI Agent）、アクセシビリティ権限（Accessibility permissions）。
PROBLEM
03 / 16
会話だけだと遅い

“最後の一手”問題

権限ダイアログ（Allow）、2FA、同意確認など、人間が最後に操作すべき場面でエージェントは止まりがちです。

止まる理由
人の同意が必要
エージェントの苦手
“どのボタン？”を指示
結果
説明が長くなる／誤操作の恐れ
METAPHOR
04 / 16
ホワイトボード指差し

矢印だけの介入

bigarrowはクリック・入力・画面キャプチャをしません。代わりに「このボタンです」と視覚で一瞬だけ案内します。

bigarrowがやる
矢印＋テキスト（--text）表示
bigarrowがやらない
クリック／タイプ／キャプチャ
運用の安心感は「人が操作する」という線引きから生まれます（Safety：安全性）。
ARCHITECTURE
05 / 16
描画は止めない設計

フォーカス非奪取

矢印の表示がユーザー操作を邪魔しないことが目標です。前面アプリが変わらないことをテストで確認した記述があります。

目的
フォーカスや入力フローを壊さない
工夫
イベント処理で“奪取”を抑制（例：NSApplication.run()不具合の修正）
運用
短時間表示＋自動消去で後始末を最小化
ENUMERATION
06 / 16
対象指定の多様性

見つけ方を複線化

エージェントが“指し示すべき対象”を外すとズレます。そこで指定方式を複数用意し、安定性を上げる方針です。

ラベル系
--element（アクセシビリティのラベル）
座標・矩形
--at / --rect
ウィンドウ
--app / --window
Peekaboo
--snapshot 等のJSON連携
前面化
必要に応じて --window App のみで済む場合も
PROCESS
07 / 16
止める・見せる・片付ける

自動終了の設計

“描きっぱなし”を防ぎ、運用負担と事故リスクを下げる仕組みが複数あります。

時間
--duration（一定時間で消える）
命令停止
stop --all（全停止）
所有プロセス
CLAUDE_PID等の終了で消去
セッションクリア
--hookで後始末
DISTINCTION
08 / 16
クリックボットではない

UI介入の線引き

bigarrowの最大主張は「代理操作しない」ことです。矢印は“説明”ではなく“行動の場所”を指します。

bigarrow
ここを押して → 人が実行
典型的エージェント
クリック/入力まで自走しがち → リスク増
同意確認や2FAのような誤操作コストが高い領域で、危険な自律性を抑えられます。
EVIDENCE
09 / 16
“現場”の複雑さ

多環境テストを強調

マルチディスプレイ、Space/フルスクリーン、Stage Managerなどの画面状態での動作確認が言及されています。

座標の難所
ネガティブ座標ディスプレイ対応
画面状態
Space変更・フルスクリーン
構成変化
途中でのディスプレイ抜き差し
品質
クリック貫通／フォーカス不変／CPU計測／実ウィンドウサーバ
位置ズレ対策
“どこを指すか”を複数方式で担保
ARCHITECTURE
10 / 16
エージェント連携の入口

exit code / JSON

終了コード（exit code）や--jsonにより、エージェントが次の判断（リトライ、質問、フォールバック）を機械的に行いやすくなります。

入力不正
対象指定ミスを判定
対象未発見
見つからなかった状況を区別
権限欠落
必要権限が足りないと検知
“デモで終わらない”ための制御ループ設計（Control loop）が見える点が重要です。
COMPARISON
11 / 16
安心設計の対比

リスクを減らす要点

信頼の源は、誤操作を減らすUI介入、フォーカス非奪取、後始末、自動終了にあります。

Safety
クリックしない／クリック貫通
UX
フォーカス非奪取で邪魔しない
Reliability
--duration・stop --all・--hook
限界（Risk）
--elementは環境依存で不安定になり得る
対策（Fallback）
座標指定やPeekaboo等で補う前提
FAQ
12 / 16
よくある疑問

6秒で要点

運用イメージを掴むための、主要なQ&Aの短縮版です。

Q1
bigarrowは“指すだけ”です（クリック／入力／キャプチャしない）。
Q2
必要な権限は主にアクセシビリティ（描画本体は不要寄り）。
Q3
フォーカス非奪取を意識し、前面アプリが変わらないことをテスト。
Q4
マルチディスプレイ・Space・フルスクリーンで動作確認がある。
Q5
“ここを押して”は矢印＋--text、必要に応じて--sayで補助。
Q6
--elementは常に安定しない場合があり、座標指定へフォールバック。
CLOSING
13 / 16
最後は人へ

結論：安全なUI部品

bigarrowは「AIが最後のクリックをやらない」ことで誤操作リスクを抑えつつ、“押す場所”を視覚化する実装部品です。

価値
説明の遅れを矢印で圧縮
設計
クリック貫通／フォーカス非奪取／自動消去
注意
Web要素（--element）の安定性は環境次第
