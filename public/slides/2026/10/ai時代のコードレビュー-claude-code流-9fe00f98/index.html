AI CODE REVIEW
02 / 16
人が読まない—壊れない

AI時代のコードレビュー

「AIが大量にPRを作る」現実で、レビューをゲートから“継続的な安全確認（スペルチェック）”へ置き換える設計思想。 （Claude Codeチームの流れ）
キーワード：自動検出 / 人の判断 / 複数層 / 高速ロールバック
（自動化は読む作業を減らし、復旧を速くする）
PROBLEM
03 / 16
従来レビューが破綻

Diff依存の限界

従来のコードレビューは、差分（diff）を人が読み、潜在バグやスタイル問題を“最後の関門”で止める設計だった。 しかしAIが大量にPRを出すと、その人手は追いつかず、手戻りやインシデントの増加リスクが出る。
従来
人が読んで承認＝品質の代理指標
AI時代
PR数が増え、読むための時間が足りない
SHIFT
04 / 16
レビューの役割再定義

「読む」から守るへ

レビューの目的を「人が読んだか」ではなく、 壊れうること（何が起こるか）を自動チェック＋人間判断の適切分担でカバーすることへ置き換える。
目的①
事前発見（先読み）
＝何が壊れるか
目的②
文脈共有（context）
＝チームで理解を揃える
CONTINUOUS
05 / 16
ゲート→スペルチェック

一回勝負をやめる

画面上の承認に集中するのではなく、PR作成前から複数段階で検証し、必要な場合だけ人間が意思決定する。 レビューを“連続プロセス”として設計する。
PR前
AIが段階検証（検出）
（日本語：段階的検証 / だんかいてきけんしょう）
PR中
必要箇所のみ人が判断（承認）
マージ後
ガードレールで安全性維持（復旧前提）
LAYERS
06 / 16
見逃し前提の多層

層×層で吸収

「どれかが全てを検出する」ではなく、後続の層と復旧手段で見逃しを吸収する。 CI・セキュリティ・マージキュー・機能フラグ・段階リリース・高速ロールバックを組み合わせる。
自動チェック（例）
lint / 型 / テスト / ビルド / セキュリティレビュー
復旧手段
リバート（revert）/ フラグ無効化 / マージキュー再実行
WORKFLOW
07 / 16
低リスクは自動

リスク別分担

変更内容をリスク分類（例：Quick/Standard/Deep）し、承認人数や“必ず人が必要な領域”を変える。 これで人の注意を高リスクに集中できる。
低リスク
自動チェック＋セキュリティ通過なら人は不要
中リスク
人1人で承認（例）
高リスク
人2人などで厚く承認（例）
GUARDRAILS
08 / 16
削減を“安全”で証明

revert/障害率を監視

「人の関与を減らしたから良い」ではなく、 revertやインシデント率が増えていないかを安全柵（ガードレール）として監視する。
人間工数（例）
PRあたりの人間承認回数 / コメント数 / 滞留時間
品質の指標
revert頻度 / インシデント率 / ノイズによる手戻り
OLD vs NEW
09 / 16
代理指標の置換

「読了」→「壊れ方」

従来は人が差分を読んでいることが品質保証の“代理指標”になりがちだった。 新設計は、自動が得意な検出は自動に任せ、人が必要な判断にだけ人を使う。
従来型
人が読んだか？（ゲート型）
Claude Code型
何が壊れうるか？（検出＋復旧を前提）
AI REVIEW IMPROVE
10 / 16
AIも学習し続ける

eval化して日次改善

AIレビューの精度改善は“導入して終わり”ではなく、 過去の障害・リバートを eval（評価データ） として日次で再学習・再スコアリングする。
改善の材料
障害 / リバート事例
制御するもの
ノイズ（誤検知） / 収束しない反復レビュー
FAQ THEME
11 / 16
ノイズと責任境界

誤検知は運用で管理

AIレビューが増えると誤検知（ノイズ）が問題になるため、修正したか／意図的か等で分類し、誤報頻度も観測して優先順位をつける。
分類
人の反応で整理（修正/判断）
観測
「きれいなPR」での誤報頻度
収束
レビューラウンドの無限増加を抑制
WHAT IF MISS
12 / 16
見逃しても巻き戻す

最小時間で元に戻す

それでも見逃しがあった場合に備え、 機能フラグ・段階リリース・マージキュー再実行・高速ロールバックで検知から復旧までを短くする。
切り替え
機能フラグで無効化（Feature Flag）
復旧
高速ロールバック（revert）＋再実行
（運用前提：締め付けだけに依存せず“サーキットブレーカー”的自動化も構想）
TAKEAWAY
13 / 16
要点は一文で

壊れる確率を設計で下げる

低リスクは自動で流し、高リスクは人の判断を厚くし、ミスは早期検知して素早く巻き戻す。 さらにrevert/障害率とevalで継続改善する。
このモデルは「人が読む時間」を削るのではなく、復旧を速くすることで実質負担を下げる発想。 （日本語補助：安全柵＝あんぜんさく / 継続改善＝けいぞくかいぜん）
