プラグインが“現場”を変える

DSH プラグイン

DeepSeek Harness（DSH）の周辺では、外部プラグインが増え続け、エージェントの実行環境・UI・メモリ・配布（市場）まで拡張する方向が見えます。

入力はGitHub「dsh-plugin」関連の一覧中心のため、各実装の安全性・品質はこの資料だけでは断定できません。
PROBLEM
03 / 14
何が“増えている”のか

一覧から読む 全体像

dsh-plugin関連のリポジトリ群から、プラグインが単機能ではなく「運用単位（環境・導線・長期記憶・接続）」として広がっていることが示唆されます。

観測
デザイン生成、図解、RAG/ナレッジ、メモリ基盤、デスクトップ/ブラウザ統合、マーケットプレイス的仕組み
観測 = 入力テキスト上の記述ベース（品質は未検証）
結論
DSHの拡張対象が「道具」から「作業環境（現場の入出力）」へシフト
This shift = “ホスト拡張”が“運用設計”へ伸びる
CORE IDEA
04 / 14
ホスト→脳→導線

拡張の 層

プラグインはホスト機能（実行環境やUI）だけでなく、エージェントの“コンテキスト/記憶”や“使い始めやすさ”へも広がっています。

層 i
ホスト拡張：UI、実行環境、登録/接続
Host extension / ホスト拡張
層 ii
知能拡張：メモリOS、コンテキストDB、RAG/ナレッジ
Memory / 記憶
層 iii
導入拡張：マーケット、サイドバー統合、デスクトップ/ブラウザ連携
Marketplace / マーケットプレイス
METAPHOR
05 / 14
Everything is a plugin

万物皆 プラグイン

「部品を差し替えられる」前提が広がるほど、エージェントは“再利用できる作業環境”として組み上がっていきます。

i
作業UI（生成・図解・デスクトップ操作）をモジュール化
ii
知識（RAG/ナレッジ）と長期記憶（メモリOS）を“差し替え可能”に
iii
配布（マーケット）で“導入の摩擦”を下げる

“機能”と“運用”の違い

拡張の 本質

プラグインは「呼べるツール」だけでなく、「いつ・どこで・どの権限で・どう記憶するか」という運用面まで影響します。

ツール中心
API/処理を追加し、短いタスクを拡張
Tool / ツール
環境中心
UI、連携、長期記憶、導入（市場）で“作業体験”を再設計
Environment / 環境

SAFETY
09 / 14
導入判断はセットで

安全性と ガバナンス

ログイン済みブラウザ操作や長期記憶、マーケットプレイスは、権限・データ・依存関係のリスクを増やし得ます。

リスク
悪意あるコード、依存関係の混入、権限過多
Risk / リスク
望ましい運用
署名、権限スコープ、実行前レビュー、サンドボックス、依存監査
Governance / ガバナンス
注意
入力文だけでは安全設計が確認できない（追加調査が必要）
Verify / 確認する
CLOSING
10 / 14
観察ポイント

次に見る べきこと

DSHプラグインは「現場で動くエージェント」を加速させていますが、導入は技術評価だけでなく“リスク管理の設計”とセットで行う段階です。

i
実行権限モデルとデータフロー（どこへ送られるか）を確認
ii
セキュリティ監査、互換性の保証範囲、更新追跡の体制を整える
iii
メモリ/長期記憶は“幻覚対策・評価設計”も別途必要になる前提で設計する
