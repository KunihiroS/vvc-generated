整理の副作用

Memory Tax

高度な「長期メモリ（要約・事実化など）」は、うまくいくこともあるが、設計次第で素のRAGに負ける——その理由を“利益”と“税”に分解して検証する研究の要点。
Bilingual terms / 用語：Memory Tax（メモリ税）・RAG（検索拡張生成）・source-augmented（原文併用）
PROBLEM
03 / 14
問いの芯

本当に賢く？

長期メモリは会話を“メモリ単位”に加工して保存するが、その加工が情報欠落や検索不能を生み得る。では、加工の価値は費用対効果で勝つのか？
長期メモリ / Long-term Memory
会話を要約・事実抽出・好み抽出・グラフ化などで“再構成”して保存
素のRAG / Naive RAG
会話原文をチャンク化し、検索で見つけた文章をLLMに渡して回答
METAPHOR
04 / 14
二つの帳簿

利益 vs 税

メモリには利益（加工で新たに解ける問題が増える）と税（加工で落ちたり、検索で出にくくなり解けない問題が増える）が同時に存在する。多くの条件では、税が利益を上回る。
利益 / Gain
加工が質問に“合う形”に整うと正答が増える
税 / Tax
加工が“手がかりを失う・見つからない”方向に働き正答が減る
EVIDENCE
05 / 14
9割は負け

結果

11種類のメモリ方式を同条件で評価し、全99通り中90通りでメモリが素のRAGを下回ったと報告される。さらに、記憶作成・保守コストが正答率以上に膨らむ。
比較の中心
メモリ方式 vs 素のRAG（原文検索）
頻度
99通り中90通りで敗北
コスト傾向
メモリはLLM呼び出し・トークン・時間が増えやすい
例：RAG（2回検索）は記憶作成でLLMを使わない一方、A-MemやMem-Tは“作成だけで”重い。
DISTINCTION
06 / 14
平均は嘘をつく

問題別に分解

平均正答率だけだと“負けた/勝った”しか見えない。論文は問題ごとに両方正解・メモリだけ正解（利益）・RAGだけ正解（税）・両方不正解に分類し、税が一定割合で存在することを示す。
利益の側
メモリだけ正解（Memory-only correct）
税の側
RAGだけ正解（RAG-only correct）
ENUMERATION
07 / 14
税の3源泉

どこで失う？

メモリ税は少なくとも次の3種類の失敗で説明できる：i忠実性、ii取り出しやすさ、iii頑健性。
i 忠実性 / Fidelity
作成時の加工で必要情報が欠ける
ii 取り出し / Accessibility
検索で埋没・分割・言い換えミスマッチで見つからない
iii 頑健性 / Robustness
作成モデルと読取モデルが違うと崩れて揺れる
PROCESS
08 / 14
費用で詰む

コスト差

メモリは“作る・保つ・壊れたら直す”でトークンとLLM呼び出し回数が増えやすい。性能差が小さい局面では、正当化が難しくなる。
RAG（例）
検索2回など：主に検索と推論（記憶作成でLLMを使わない設計が多い）
メモリ方式
記憶作成・更新・読み取りのためにLLM呼び出しが増えやすい
ここで重要なのは、正答率だけでなくTCO（総保有コスト）視点で比較する必要がある点。
DISTINCTION
09 / 14
評価が支配する

ベンチマーク依存

“原文を厳密に思い出す”系のベンチマークでは、メモリ側の伸びしろが小さくなり得る。つまり、結果はデータセットと設計の組み合わせに影響される。
起きやすいこと
加工メモリが“必要な原文の手がかり”を持てないため、税が増える
注意点
設定次第で結論は変わり得るので、自分の言語・質問分布で再検証が必要
ARCHITECTURE
10 / 14
原文を残す

source-augmented

対策は「メモリだけ」ではなく、原文候補も同時に検索して、リランカーで統合すること。これにより税を大きく減らせる可能性が示されている。
メモリ側
整理された情報（要約・事実化）を候補化
原文側
加工で落ちた証拠を“原文検索”で回収
統合
リランカーで両候補を統合し、最終根拠を強化
CLOSING
11 / 14
意思決定の型

結論

メモリは“一律に悪い”のではなく、利益と税を問題ごとに測り、税が勝つ設計なら原文併用や評価設計でガードするべきだ。
測るべき指標
両方正解／メモリだけ正解（利益）／RAGだけ正解（税）／両方不正解
設計の方向
メモリ＋原文検索（source-augmented）で税を軽減
出典：He ほか, Memory Tax: Dissecting the Net Value of Agent Memory（arXiv:2610.34073 v1）
日本語運用への適用は、言語・質問形式・更新頻度がズレるため必ず自分のデータで確認するのが安全。
