Why
03 / 18
迷いを減らす

“次に何を”を即決

タスク管理で本当に重いのは「分類」だけでなく、入力・更新・検索の摩擦と意思決定の遅れです。

Design（設計）
Eisenhowerマトリクスで、実行方針を4象限に即対応（Do First / Schedule / Delegate / Eliminate）。
Outcome（狙い）
“やるべきこと”を見失わない導線（ショートカット、Quick Capture、検索など）を整備。
Core Data
04 / 18
ローカル保持

IndexedDB保存 デフォルト

コアのタスクデータはブラウザの IndexedDB に保存され、基本的にバックエンド不要・オフライン動作を前提にしています（ローカルファースト）。

Privacy（プライバシー）
タスクがローカルに閉じやすく、第三者サーバへの依存を下げる。
Risk（リスク）
ブラウザデータ消去でローカルのタスクが失われ得るため、バックアップ（エクスポート/復元）が重要。
Sync
05 / 18
責任境界

PocketBase同期は“任意”

PocketBaseによるマルチデバイス同期はオプションで、無効ならローカル中心のままです。

When On（有効時）
タスクデータが、構成されたPocketBaseサーバへ送信される設計。
Check（確認）
トークン保管・暗号化・信頼境界はSECURITY.md等で精査する前提。
Eisenhower
06 / 18
4象限で決める

Do / Schedule / Delegate / Eliminate

“緊急度×重要度”で分類し、各象限に対応した実行方針へ落とし込むことで判断を早めます。

i Do First
緊急かつ重要：今すぐ実行。
ii Schedule
重要だが緊急でない：予定化。
iii Delegate
緊急だが重要でない：委任。
iv Eliminate
緊急でも重要でもない：削除/排除。
Workflow
07 / 18
入力→更新→検索

摩擦を下げる導線

Eisenhowerの価値は、分類のための操作が速いことにあります。READMEではドラッグ＆ドロップやキーボードナビゲーション等が整備されるとされています。

Capture（捕捉）
Quick Captureで思いつきを即タスク化。
Navigate（移動）
ショートカット/キーボードで象限・状態を素早く操作。
Find（発見）
検索とヘルプで探し直しコストを減らす。
MCP
08 / 18
拡張の受け口

MCPサーバでツール提供

アプリ本体とは別にインストールできるMCPサーバがあり、タスクや分析・診断のためのツール群を提供する（README上の説明）。

Tools（ツール）
タスク操作・分析/診断・dry-runawareな書き込みなどを含むとされる。
Trade-off（両刃）
拡張性は上がる一方、権限境界と安全性は別途確認が必要。
Privacy+
09 / 18
安全な“前提”を置く

READMEは参照を要求する

提供情報の中心はREADMEで、同期の脅威モデル・競合解決・整合性モデルなどは本文だけで確証しにくい、と読み手が判断する流れです。

Docs-first
SECURITY.md等で信頼境界と安全設計を確認する前提。
No Magic
“安全”の結論を急がず、設定・運用を精査する姿勢。
Local Risk
ローカルは便利だが、消去で失われ得るためバックアップ運用が要る。
Operations
10 / 18
証拠分離で安心

リリース運用の注意

READMEには、ソース/テスト/ビルド/実稼働の“証拠”を分けて考える注意があるとされています（例：CDNやコンテナ配信の別検証）。

Verify（検証）
アップロード＝証拠ではなく、実際に何が配信されているかを確認。
Quality（品質）
テスト手順の“正しさ”を担保する（後述のbun推奨など）。
Testing
11 / 18
canonical checks

bun test より bun run test

READMEでは、bun test はBun内蔵ランナーでVitestの想定と一致しない可能性があるため、bun run test を推奨しています。

Reason（理由）
Vitest/Playwright前提の“canonical checks”に合わせるため。
Impact（効果）
開発・検証の再現性を高め、運用事故の芽を減らす。
Verdict

思想は明快

“信頼できる作業”志向

総評として、ローカルで閉じるプライバシー設計と、Eisenhowerで判断を支える設計、さらに運用・検証の意識が一貫しています。

Strength（強み）

Caution（注意）

Takeaway
13 / 18
導入判断の要点

最初に確認すべきこと

“ローカル中心か／同期を有効化するか”を起点に、データの置き場所と信頼境界を押さえると判断が速くなります。

① 保存先
ローカルはIndexedDB（消去リスク→バックアップ運用）。
② 同期
PocketBaseは任意。送信先・暗号化/トークン保管はSECURITY.mdで確認。
③ 拡張
MCPは別インストールのため、権限境界と安全性の文書精査が必須。
