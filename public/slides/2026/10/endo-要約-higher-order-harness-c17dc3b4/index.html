COVER
02 / 16
複数AIを統一体験へ

Endo

Endo（旧 Reagent 系譜）は、複数のAIエージェントを「同じ会話体験」として合成する Higher Order Harness（HOH）を目指すプロジェクトです。（高階ハーネス／実行環境の合成）
PROBLEM
03 / 16
切替が面倒

バラバラ問題

多くのAIは「プロバイダ（サービス）ごとに」別々の体験になり、会話履歴・ツール実行・実行計画が統一されにくいです。結果として、使い分けはUI/運用コストになります。
現状の摩擦
履歴・ツール・権限が分断
（例：エージェント切替で前後が繋がらない）
狙い
同一プロトコルで合成する
（モデル差より“ワークフロー設計”へ）
METAPHOR
04 / 16
部品として組む

HOH

Endoの中心は、エージェントを“部品”として組み合わせ、会話の途中でも切替できる合成ハーネスです。（Higher Order Harness）
エージェント
LLM + ツール + 履歴
ハーネス
同一プロトコル統一
体験
切替しても“会話が継続”
ARCHITECTURE
05 / 16
統一プロトコル

同じ挙動にする

Endoは「1つのプロトコルにストリーミング」「回答・ツール呼び出し・許可プロンプト・履歴」の挙動を同一に揃えると説明されています。
統一される対象
ストリーミング / ツール呼び出し
回答・許可プロンプト・履歴も同列
期待効果
ユーザーは“実行設計”へ集中
（プロバイダ差の吸収を狙う）
PROCESS
06 / 16
TypeScriptで組む

ワークフロー

ワークフローはTypeScriptで定義し、並列（`parallel()`）や段階（`phase()`）や会話継続（session ID）を組み合わせられる、とされています。
例：制御
parallel() / phase()
ファンアウトと段階整理
例：継続
session IDで分岐・継続
再開可能な会話設計
EVIDENCE
07 / 16
HOHの核

履歴の引継ぎ

会話途中で別エージェントへ切り替えても、同一セッション内で全履歴を引き継ぐ、と説明されています。HOHの中核機能です。
できること
エージェント切替しても履歴継続
注意
履歴の“意味的互換”は実装依存
DISTINCTION
08 / 16
Dig in

派生スレッド

Dig inは、回答の特定箇所から派生した集中会話を別スレッドで開始し、本筋のスレッドを汚しにくくします。探索・検証を並行しやすい設計です。
メリット
本筋が混ざらない
調査・検証・深掘りの並行
運用感
クリック起点の集中作業
“同じ文脈”を別に掘れる
ENUMERATION
09 / 16
使う形が多い

代表機能

Endoは「会話」「ツール」「実行計画」を束ね、ワークスペース内で永続化しつつ、Workflow cardで追える体験を目指しています。
i
Workflow cardで実行追跡
ii
定型ワークフロー（例）
/best-of-n, /multi-turn-debate, /hypothesis-race
iii
スケジュール実行
cron / 一度きり
SECURITY
10 / 16
APIキー不要

導入の壁を下げる

READMEでは「APIキーを貼り付ける必要がなく、各プロバイダのCLIへサインイン済みのアカウントで動く」と説明されています。参入障壁を下げる方針です。
方針
APIキーの手作業を減らす
（CLI連携＋ログイン前提）
確認点
対応プロバイダ範囲を検証
同様の連携が全て可能とは限らない
EVALUATION
11 / 16
強みと価値

統合体験の合成

Endoの強みは、単なるUI統合ではなく「実行の合成」として複数AIを運用できる点です。切替・並列/段階・Dig in・再開が“調査→計画→反復改善”に向きます。
技術（可能性）
HOHでエージェントを差し替えやすい
workflowをTypeScriptで拡張
実用（効きどころ）
再開可能なスレッド + 見える実行
“チャットしながらワークフロー”
RISK
12 / 16
不確実性が残る

導入前に確認

0.1.x段階でBreaking changesが起こり得るため、ワークフローや内部APIに依存すると移行コストが増える可能性があります。加えて、セキュリティと永続化・権限・ログの具体は本文だけでは不明です。
リスク1
仕様変更（Breaking changes）
特にTSワークフロー等への依存
リスク2
セキュリティ/データ保持の詳細不足
権限粒度・削除/暗号化・監査ログなど
CLOSING
13 / 16
結論

試しながら評価

まずは軽い運用で、セキュリティ（権限・ログ・永続化）と失敗時の挙動を確認しつつ、ワークフロー資産の移植可能性を慎重に見極めるのが現実的です。Endoは“複数AIの統合実行”を本気で狙う設計です。
i
軽く検証
ii
ログ/権限/永続化確認
iii
移行コストを見積もる
