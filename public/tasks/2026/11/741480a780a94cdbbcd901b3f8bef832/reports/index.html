02 / SEARCH STRATEGY

探索の境界と判定法

「同じラベル」ではなく代替されるジョブで探索。公式 README／docs／repo を優先。

01 · DIRECTdesktop / local agent / agent control center / voice agent OS
02 · ADJACENTcoding agent / PR review / multi-agent workflow / human-in-loop
03 · SUBSTITUTECLI + IDE extension + workflow framework の組み合わせ
04 · VERIFY公開一次情報で確認。実機未確認は Unknown に隔離

Similarity judgment: High=中心ジョブと操作面が大きく重なる、Medium=主要ジョブの一部を置換、Low=補完・部分代替、Unclear=一次情報不足。Confidence は証拠の明瞭さであり、製品品質の評価ではない。

05 / UNDERSERVED VALUE & DIFFERENTIATION

強い差／弱い差を分ける

「ある／ない」ではなく、導入・制約・失敗時の負担をどれだけ減らすか。

Strong differentiation 仮説

  • 既存契約を活かす agent switchboard。 Claude Code / Codex 等へのサインインを維持し、タスクごとに配分。新しい provider lock-in やAPIキー移行を避ける。
  • 手が離せない場面の governed delegation。 音声で複数仕事を開始し、実行中の agent・権限・成果物・失敗をデスクトップで再把握できる。
  • 1台内のデータ境界を説明可能にする。 local voice、loopback default、権限の明示、どの agent/provider に何が送られたかの receipt が揃えば強い。
  • OS横断の「使えるまで」。 optional dependency の失敗を可視化し、段階的に機能を有効化する導入体験は framework より価値になる。

False differentiation の罠

  • 「OSS / local-first」だけ。 goose、OpenHands、Cline 等も強く訴求。ライセンスだけで選ばれない。
  • 「multi-agent」だけ。 framework から完成品まで既に広い。agent 数は成果品質や速度を保証しない。
  • 「音声がある」だけ。 静かな職場・正確な複雑指示では不要。修正コストが入力短縮を上回り得る。
  • マスコット／Jarvis感。 discovery には効いても、信頼・ROI・安全性の代わりにはならない。
  • 機能数。 広い surface は保守・権限・OS差のリスクも増やす。深さの証拠なしには差ではない。

07 / RECOMMENDATIONS

ポジションを狭く、証拠を太く

1 · Wedge

“Your local agent switchboard” に集中。「万能Jarvis」ではなく、既存 agent を一つの依頼から並列運用する最短経路として販売する。

2 · Proof

PR triage、issue fan-out、cross-app research の3 benchmark を公開。single agent / OpenHands / manual stack と時間・費用・介入回数で比較。

3 · Trust

task receipt に provider、送信データ、tool call、approval、費用、成果物を残す。local-first を検証可能な data-boundary UX に変える。

4 · Packaging

「chatのみ」「coding agents」「full computer use」を権限 profile として分離。最小権限で始め、必要時だけ昇格。

5 · Interop

agent adapter contract を安定化し、ACP/MCP/skills を活用。特定 harness のUI模倣ではなく、乗換コストを下げる。

6 · Beachhead

常時複数 repo / PR を扱う個人・小規模リードを先に狙う。voice は主語ではなく、hands-busy時の加速装置として検証。

09 / RESEARCH LIMITATIONS

このレポートが言えないこと

Snapshot

2026-11-15 時点の公開情報。急速に変わる repo / SaaS 機能・価格・名称は後日変わり得る。

No hands-on

インストール、同一タスク、性能、障害復旧、アクセシビリティ、セキュリティ監査は未実施。

Claim ≠ quality

ヒートマップは公式記述の存在を整理したもの。完成度、利用率、満足度、市場シェアを示さない。

Selection bias

OSSと直接代替を優先。Cursor、GitHub Copilot、Claude Code、Devin 等のSaaS単体は比較表から除外。

Unknown economics

モデル利用料、subscription再利用、保守工数、multi-agent token 増を正規化していない。

Security

local は offline や private と同義ではない。接続 provider / agent / MCP ごとの外部送信を別途監査すべき。
